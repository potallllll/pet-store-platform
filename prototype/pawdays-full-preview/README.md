# PawDays 客户端＋店员端交互验收原型

本目录是与当前正式需求同步的静态 H5 验收资产，可直接打开 `dist/index.html`，或用任意静态服务器运行 `dist/`。

## 权威边界

- 正式业务规则只以仓库根 `AGENTS.md`、`docs/README.md` 及其指向的当前有效文档为准。
- 本原型用于核对页面、入口、文案、基础状态和交互，不新增业务规则。
- 可点击不代表小程序后端、微信登录／广告、权限、支付、并发或数据持久化已经实现。
- 若原型与正式文档冲突，先修正文档冲突，再同步原型；不得反向用原型覆盖正式规则。

## 本轮重点

- 客户端首页顶部唯一门店栏、正文无品牌 Banner、紧凑消费争议、“本店推荐”。
- 寄养加餐位于寄养详情第二行、时间轴上方，并按普通商品需求处理。
- 店员工作台和洗美页统一使用“临时开单／会员开单”。
- 临时开单填写手机号或微信号；会员开单下拉选择本店已有顾客。
- 洗美详情提供皮肤、耳道、眼睛、口腔、指甲、毛发、全身七组洗护前／后选填照片入口。
- 店员端消费争议展示待回应、补充材料中、待平台裁决、已结束四组，逾期优先，并区分7天正式回应与首个回应后的3天补证。
- 食品问题由平台直接联系厂家并在 Web 后台处理；门店只收到知悉通知，不参与前置核实或厂家沟通。
- 跨店资料只保留“宠物护理注意事项”和统一“顾客风险”；顾客风险内部区分顾客相关／宠物相关，顾客端只管理授权、不查看记录。
- V1 不导入其他门店普通档案、服务报告或护理历史；顾客风险只按认证手机号匹配。
- 上门喂养到结束日期自动显示“已结束”；负责门店停用时转给最近有效门店，新店重新确认后才能查看双方联系方式。
- 积分商城只兑换实物；领取门店停用时自动取消、退回积分并发送重要通知。
- 结算选券并自动校验核销；结算后金额锁定，错误走补收或退款，不提供手动核销、更正收款或直接改余额。
- 当前食用宠物食品由主人在客户端维护；店员端仅只读，未填写时显示“主人暂未填写”。
