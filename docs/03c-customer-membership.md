# 03C 客户端「我的会员」模块

> 状态：已确认子模块
> 所属阶段：03 客户端微信小程序
> 版本：V1.0

## 1. 客户端定位

客户端不提供充值入口，也不允许客户发起充值申请或自行完成余额支付。

“我的会员”仅用于查看当前商户下的会员资产与历史记录，包括：

- 当前可用余额
- 余额明细
- 优惠券
- 积分（具体规则后续确认）
- 相关会员权益（具体规则后续确认）

不同商户之间的会员余额、优惠券、积分及会员权益严格隔离。

## 2. 充值由门店侧发起

会员充值完全由门店侧处理。

基本流程：

店员选择客户
→ 选择老板预先配置的充值套餐
→ 客户在线下付款
→ 店员选择实际支付方式
→ 店员确认已收款
→ 系统生成充值流水
→ 增加会员余额
→ 自动发放套餐中配置的赠送权益

客户无需先在小程序进行任何充值操作。

## 3. 老板配置充值套餐

商户老板可自行维护充值套餐，例如：

- 实收 300 元，到账 330 元
- 实收 500 元，到账 560 元
- 实收 1000 元，到账 1150 元并赠送指定优惠券

每个套餐建议支持：

- 套餐名称
- 实际收款金额
- 赠送余额
- 实际到账总额
- 赠送优惠券
- 可选赠送积分（如后续启用）
- 启用 / 停用
- 生效时间 / 失效时间（可选）
- 备注

不在 V1.0 引入复杂的营销条件引擎。

## 4. 赠送权益

老板可在充值套餐中配置赠送内容。

V1.0 至少考虑：

- 赠送余额
- 赠送优惠券

后续积分规则确认后可支持赠送积分。

充值成功后，系统自动发放套餐中已配置的赠送权益，店员不需要再次手动发券或手动加赠送余额。

## 5. 本金与赠送余额

后台应区分：

- 充值本金余额
- 赠送余额
- 客户端显示的总可用余额

客户端通常只显示总可用余额，不增加客户理解成本。

具体扣款顺序、退款时本金与赠送余额如何处理，在核心业务规则阶段最终确认。

## 6. 余额支付

客户不能在客户端自行发起余额扣款。

门店收银时，由有权限的店员选择会员余额作为支付方式，并由系统完成余额校验和扣减。

余额不足时应支持组合支付，系统自动计算剩余应收金额，避免店员手工计算。

例如：订单应收 200 元，会员余额 80 元，则系统可自动形成：会员余额 80 元 + 微信 / 支付宝 / 现金等 120 元。

## 7. 余额流水与审计

任何余额变化都必须形成不可删除的独立流水，不允许直接覆盖余额数字。

流水类型至少预留：

- 充值
- 赠送
- 消费
- 退款
- 人工增加
- 人工扣减
- 冲正
- 历史初始化

每条关键流水至少记录：

- 客户
- 商户
- 操作时间
- 变动前余额
- 变动金额
- 变动后余额
- 本金 / 赠送部分变化
- 关联订单或充值单
- 支付方式（如适用）
- 操作员工
- 原因 / 备注

错误操作通过冲正处理，不删除或直接修改历史流水。

## 8. 权限原则

商户老板默认拥有全部会员相关权限。

普通店员的权限后续通过细粒度权限开关控制，例如：

- 查看余额
- 使用余额收款
- 执行充值
- 人工调整余额
- 冲正充值

默认建议普通店员不拥有“人工调整余额”和“冲正充值”等高风险权限。

## 9. 减少操作原则

会员模块必须优先减少门店操作：

- 老板只需提前配置充值套餐。
- 店员充值时直接选择套餐，不重复输入赠送金额和赠送券。
- 充值成功后系统自动发放赠送权益。
- 组合支付由系统自动计算剩余应收。
- 客户端只负责查看，不承担充值、付款或复杂会员操作。
