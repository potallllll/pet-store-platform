# 03G 客户端「登录 / 手机号绑定 / 历史客户识别 / 账号安全」模块

> 状态：已确认子模块
> 所属阶段：03 客户端微信小程序
> 版本：V1.0

## 1. 设计原则

- 客户首次进入小程序时尽量不强制完成完整登录 / 手机号绑定流程。
- 浏览当前门店首页、推荐商品、商品列表和商品详情等公开内容时，可先不建立 Customer 关系。
- 当客户首次使用预约、宠物、钱包 / 会员资产、订单、消息、提交购买需求、宠物交友邀请等个人业务时，再要求完成必要身份验证。
- 平台主身份与商户客户身份分离：微信身份形成平台级 User；User 与具体 Merchant 建立商户级 Customer 关系。
- 手机号是已验证联系方式和历史客户匹配依据，不作为平台唯一主身份。
- 历史客户匹配必须以已验证手机号为前提，禁止仅凭手工输入手机号直接展示余额、订单、宠物等隐私数据。
- 多商户 Customer、会员资产、宠物交友和经营数据严格隔离。

## 2. 平台 User 与商户 Customer

系统区分：

- User：平台级微信用户身份。
- Customer：User 与某一 Merchant 之间的客户关系。

同一 User 可以成为多个商户的 Customer，但每个 Merchant 只能访问自己与该 Customer 相关的业务数据。

切换商户时，首页、当前服务、预约、钱包 / 会员资产、优惠券、订单、商品、宠物交友和门店消息均整体切换至目标商户上下文，不允许跨商户串数据。平台个人消息、平台积分和本人上门喂养记录继续归属于 Platform User，不因切店而丢失；消息时间流范围见 `03f`。

## 3. 身份验证触发时机

无需先绑定手机号即可：

- 浏览当前门店首页
- 浏览推荐商品
- 搜索 / 浏览商品
- 查看商品详情
- 浏览不涉及个人业务数据的公开内容

首次进行以下个人业务时要求完成必要身份验证和手机号验证：

- 提交预约
- 新增 / 管理宠物
- 查看当前可用余额、钱包明细或优惠券
- 查看订单
- 查看消息
- 提交商品购买需求
- 开启宠物交友展示或发送宠物好友邀请
- 其他需要访问个人业务数据的操作

验证成功后尽量一次完成后续 User / Customer 识别，不重复要求客户填写已有信息。仅访问平台个人业务时不因此给任意门店建立 Customer 关系；门店业务在明确目标 Merchant 后按第 5 节识别。

身份验证前保留用户原始目标和必要的业务 / 门店标识。验证成功后重新校验目标可见性并继续原操作，不一律跳首页；拒绝 / 中断验证时保留可再次进入的原目标，不伪造成功、不提交个人业务。退出登录或切换 User 后不得向新会话暴露前一 User 的私有草稿或页面内容。

## 4. 手机号定位

手机号不等于平台账号。

手机号用途：

- 已验证联系方式
- 当前商户历史 Customer 匹配依据
- 门店线下客户记录与线上 User 的关联依据之一

不允许仅根据手机号相同就跨商户共享或自动合并数据。

## 5. 历史客户自动识别

客户完成手机号所有权验证后，仅在当前 Merchant 范围内查找历史 Customer。

### 5.1 唯一明确匹配

若仅找到一个可安全绑定、且未发生账号冲突的历史 Customer，则系统自动建立 User ↔ Customer 关联。

关联后客户可直接看到该商户中原有的宠物、当前可用余额、优惠券、订单和服务记录，无需店员再次手工迁移。

### 5.2 无匹配

若当前商户没有匹配的历史 Customer，则自动创建新的 Customer 关系。

### 5.3 多个候选历史客户

若同一已验证手机号在当前商户中对应多个可能的历史 Customer，系统不得自动合并或任意绑定。

客户端提示存在待门店确认的历史资料；由门店侧后续通过人工识别 / 合并 / 绑定能力处理。

在冲突解除前不得暴露候选 Customer 的余额、订单等敏感数据。

### 5.4 已绑定其他 User

若目标 Customer 已绑定其他平台 User，新的 User 即使验证了相同手机号，也不得自动抢绑、覆盖或转移 Customer。

进入账号绑定冲突 / 恢复流程，V1.0 可由商户老板辅助处理；所有换绑必须保留审计记录。

## 6. 线下先建客户、线上后绑定

门店可在客户尚未使用小程序时先由店员建立 Customer、宠物、服务、充值和消费记录。

客户之后首次使用小程序并验证手机号时，如符合唯一安全匹配条件，系统自动关联已有 Customer，使历史资料直接出现在客户端。

不得要求门店为了线上账号预先让所有客户注册。

## 7. 店员辅助绑定兜底

V1.0 支持门店针对复杂历史数据提供“绑定客户小程序”能力。

流程：

店员打开明确的 Customer
→ 生成一次性绑定二维码 / 绑定凭证
→ 客户使用当前微信账号扫码并确认
→ 后端校验后建立 User ↔ Customer 关联

安全要求：

- 一次性使用
- 短有效期
- 使用后立即失效
- 绑定目标 Customer 明确
- 记录生成员工、生成时间、使用时间和绑定结果
- 在绑定成功前不得因为扫描凭证而向错误 User 暴露目标 Customer 的余额、订单等敏感数据

## 8. 更换手机号

已登录 User 更换手机号时，应验证新手机号并更新联系方式，不得因此重新创建新的 Customer。

原有宠物、余额、优惠券、订单、服务报告等业务关系保持不变。

手机号首次绑定和变更都必须记录审计。

## 9. 更换微信账号 / 账号恢复

微信 User 发生变化属于更高风险操作，不允许仅凭相同手机号自动转移已有 Customer。

若新 User 验证手机号后发现目标 Customer 已绑定其他 User，应进入账号恢复 / 换绑流程。

V1.0 可采用商户老板辅助确认作为兜底，不建设复杂独立申诉中心。

## 10. 退出登录与账号注销

退出登录仅结束当前登录会话，不删除 User、Customer、宠物、余额、订单或历史关联。

账号注销与退出登录严格分开。

账号注销时：

- 可删除 / 匿名化应被删除的个人身份数据；
- 财务、订单、退款、审计等依法或业务需要保留的交易事实不得因注销而被无痕删除；
- 具体保留周期和匿名化规则在后续数据 / 隐私规则阶段统一确定。

## 11. 多商户切换

客户直接打开小程序且没有本次明确目标时，使用最近一次仍有效的 Merchant；本次扫码 / 门店业务深链指定的有效门店优先于历史门店。

客户可在已建立关系的商户之间切换。切换后所有商户业务数据必须整体切换，不允许出现 A 店页面与 B 店资产混合展示。

首次扫描新的商户二维码时可先浏览公开内容；首次进行个人业务时再建立该商户 Customer 关系。

### 11.1 启动与目标门店选择

- 本次有效扫码 / 深链目标 → 优先解析目标及其真实所属门店；后台回前台且无新外部目标 → 恢复原页面和同一会话的未提交内容；普通冷启动且无明确目标 → 最近有效门店首页。
- 没有历史门店、历史门店失效或需要门店但当前未选择时，展示扫码 / 选择有效门店入口。选店过程保留原始可恢复目标，不伪造默认门店、Customer、余额或服务。
- 明确指向失效门店或无权业务的链接，先说明该目标不可用；用户可返回或选择其他有效门店，但不得静默替换为历史门店并把链接业务当成该店业务。
- 平台公开上门喂养详情可直接浏览，不强制把用户当前门店切到发布门店；发布时仍须明确有效当前门店并永久绑定。查看个人平台记录按身份校验，进入门店私有资料则另外校验 Customer 权限。
- 门店业务的目标门店、业务所属门店和读取权限均由服务端确认；切店时整体刷新门店数据，旧页面请求结果不得覆盖新门店页面。
- 启动封面广告不改变上述优先级；关闭、失败或等待结束后按 `03p` 恢复目标，登录 / 绑定结束后继续同一目标。

### 11.2 边界验收补充

- 首次打开且无门店，能进入扫码 / 选店；不展示虚构门店资产。
- 历史为 A 店，本次有效 B 店深链进入 B 店对应业务；未建立 B 店关系时先完成必要校验，不能读取 A 店资产作为 B 店数据。
- 登录后恢复消息 / 分享目标；目标无权限、已失效或门店停用时显示可理解的原因与返回路径。
- 后台回前台不丢当前页面和未提交内容；新外部目标优先时不自动提交或丢弃原草稿，草稿只在同一账号及原业务上下文恢复。
- 切店后平台个人消息保留、其他门店私有消息隔离，消息未读按 `03f` 的可见范围更新。

## 12. 宠物基础档案复用

客户进入新的商户时，可主动选择“使用已有宠物档案”。

只有客户明确授权后，才向目标商户提供允许共享的宠物基础资料。

不得跨商户共享：

- 其他商户订单 / 消费金额
- 其他商户会员余额 / 优惠券
- 其他商户服务记录
- 其他商户内部备注
- 其他商户员工评价
- 其他商户经营分析标签

宠物交友展示授权同样属于商户级授权，不随宠物基础档案跨商户自动开启。

## 13. 客户端账号设置

“我的”中提供轻量的“账号与设置”入口，至少可承载：

- 当前已验证手机号
- 更换手机号
- 隐私相关入口
- 减少动态效果（按 10a 的系统偏好与用户设置规则，控制轮播及非必要动画）
- 账号注销
- 退出登录

V1.0 不设计用户名 / 密码 / 忘记密码 / 密码重置体系，主要使用微信身份与必要的手机号验证。

## 14. 家庭共享

V1.0 不实现多人 / 家庭成员共同管理同一宠物或共享同一会员资产的复杂权限体系。

V1.0 采用主要 User 管理宠物和商户关系；架构可在以后版本预留多关系能力。

## 15. 身份安全审计

以下关键动作必须保留审计：

- 手机号首次绑定
- 手机号更换
- 历史 Customer 自动匹配
- Customer 人工绑定
- 重复 Customer 合并
- User / Customer 换绑
- 解绑
- 账号恢复
- 注销申请

至少记录操作时间、操作方式、操作主体、原关系、新关系和原因；人工操作还必须记录操作员工 / 老板。

## 16. 减少操作原则

- 新客户尽量先浏览、后验证，不以登录墙阻断公开浏览。
- 老客户验证手机号后由后端自动识别历史 Customer，不要求客户或店员重复迁移数据。
- 线下先建客户、线上后绑定是正常路径，不强制客户预注册。
- 复杂重复数据通过门店辅助绑定兜底，不让客户处理内部数据问题。
- 高风险换绑必须安全优先；普通低风险登录流程则尽量少步骤。

## 17. 需求变更记录

### 2026-09-08：首开选店、深链优先级与平台个人数据

【需求变更】

- 原规则：直接打开默认最近门店，消息随门店整体切换；无有效门店、明确门店深链和登录后原目标恢复缺少统一规则。
- 新规则：本次有效目标优先于历史门店；无有效门店提供扫码 / 选店；后台与登录后恢复原目标并重新鉴权，平台个人消息和业务保留，门店私有业务仍整体隔离。
- 影响范围：首次进入、登录 / Customer 识别、门店切换、启动广告、消息 / 分享深链、草稿与权限验收。
