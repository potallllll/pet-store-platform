## 1. 文档职责

本文件用于收口客户端首页的具体视觉与布局规格，是 `10a-customer-ui-design-system.md` 的首页专项细化。

业务逻辑仍以 `03-customer-miniapp.md`、`03a`～`03m`、`03o`～`03p` 为准；原 `03n` 已归档。本文件不得自行修改业务状态、广告权益、门店付费权益、隐私、订单、积分或多租户规则。

启动封面广告由 `03p-customer-launch-cover-ad.md` 与 `10c-customer-launch-cover-ad-ui-spec.md` 负责，不计入首页内部模块高度；广告结束 / 降级后按 `03p` 恢复原始业务目标，仅无目标启动进入首页。

---

## 2. 首页最终结构

首页从上到下固定为：

1. 顶部门店栏
2. 顶部品牌 / 生活方式 Banner
3. 当前服务
4. 宠物交友
5. 上门喂养
6. 精选商品
7. 首页底部微信 Banner 广告横幅
8. 底部导航
9. 条件满足时显示养宠顾问悬浮入口

底部一级导航仍只有：预约 / 首页 / 我的。

`launch_cover_ad` 发生在进入本首页之前，不插入上述首页内容流。

## 3. 页面栅格与间距

以 375px 逻辑宽度为设计参考，按 `10a` 第 13.2 节在 320 / 375 / 430px、短屏和字号放大时自适应。375px 基准可按 `1px = 2rpx` 转换布局参考，但实际热区、字号下限、边框与安全区不得随窄屏一同缩小。通用数值只以 `10a` Token 为准，以下是业务布局应用。

- 页面左右边距：`space.4`，实际逻辑尺寸不低于 16px
- 顶部安全区以下首个内容起始：`space.3`
- 主模块之间：`space.6`；紧凑 Banner 与当前服务之间使用 `space.4`
- 模块标题与内容：`space.3`
- 卡片内边距：`space.4`，三列紧凑卡可用 `space.dense.inset`
- 横向卡片间距：`space.dense.card`
- 小标签间距：`space.dense.label`
- 同组按钮间距：`space.2`，放大文字后可换行但热区不重叠
- 4px 栅格及 6 / 10 / 14px 密度例外统一登记在 `10a`，不再临时增加数值

---

## 4. 顶部门店栏

- 高度参考：52px
- 左侧：门店头像（如使用）+ 门店名称 + 可选轻副标题
- 门店头像参考：32×32px
- 门店名称：`type.title`，建议 10 字内；窄屏优先保留可识别名称，省略后在门店详情 / 切换入口可读全名
- 副标题：`type.caption`，最多 1 行，空间不足或大字号时优先省去非必要副标题
- 右侧只保留消息入口
- 消息按钮视觉容器可为 40×40px，实际触控热区不小于 `target.min`，不侵入微信胶囊
- 未读可使用红点 / 数量
- 不在首页顶部同时放搜索、扫码等入口

## 5. 顶部品牌 / 生活方式 Banner

该 Banner 是产品 / 门店氛围视觉，不是微信广告位，也不是启动封面广告。

### 5.1 尺寸

- 宽度：填满页面内容宽度
- 无当前服务的完整变体：参考高度 164px，内容多或字号放大时允许增高
- 有当前服务的紧凑变体：参考高度 72px，短屏可使用最小 48px 的单行品牌条；品牌图片仍可见，但优先缩减图片和装饰留白
- 圆角：`radius.hero`
- 完整变体在 375px 文案区约 42%、图片约 58%；这些比例不锁死，窄屏 / 大字时增大文案宽度或改上下排，不能以缩小字号硬凑两行
- 文字使用 `10a` 已验证的不透明 canvas / surface 或 brand.tint 背景，图片独立裁切；不把必要文字直接压在未知明暗的照片上

### 5.2 文案

- 完整主标题：`type.hero`，正常字号推荐两行、8～12 个中文字符；窄屏 / 放大字号可自然增加行数和高度
- 完整副标题：`type.caption`，正常字号最多 1 行，空间不足先省略
- 完整 CTA 视觉高度可约 34px，但热区至少 `target.min`；文案推荐 4～6 字，完整显示
- 紧凑变体：`type.section` 短品牌标题，省略副标题和非必要 CTA，不出现比当前服务按钮更强的操作

示例：

> 陪伴
> 让生活更温暖

完整品牌 Banner 可以轮播，最多 3 张；单张不自动播放，多张复用 `10a` 的间隔、暂停 / 继续、离屏暂停、手势优先和减少动态效果规则。紧凑变体只展示一张品牌内容，不自动换图。

### 5.3 变体选择与加载稳定性

- 当前服务查询确认存在进行中或尚未真正查看结果的刚完成服务时，使用紧凑变体；确认无当前服务时使用完整变体，预约引导仍保留在当前服务区域。
- 初次查询未完成 / 失败时使用紧凑占位，不把错误当作“无服务”而展开完整 Banner。后台刷新继续保留已验证的变体和服务内容，失败只在服务模块提示。
- 首次展示完整内容前确定变体；若用户已经滚动、正在触控或停留阅读，后到数据不能突然插入 / 压缩 Banner 推动其手下的业务操作，待安全时机更新并保留阅读锚点。

## 6. 当前服务

当前服务是首页最高视觉 / 业务权重模块。

### 6.1 卡片高度

- 洗护 / 美容：参考最小 148px
- 寄养：参考最小 164px
- 长内容 / 大字号自然增高，不限定最大高度；先展示宠物、服务状态和主操作，其余日期与动态摘要紧随，不因媒体加载移动按钮

### 6.2 内容

- 宠物头像参考 76×76px
- 标题：宠物名 + 服务类型，`type.section`，建议 14 字内，超长可换行 / 在详情读取全名
- 日期 / 状态 / 最新动态正文使用 `type.body.small`，非关键更新时间可用 `type.caption`
- 最新动态摘要最多约 16 个中文字符
- 主按钮视觉高度可参考 38px，热区至少 `target.min`；文案 4～6 字为建议，完整业务动词不可截断

寄养卡至少显示：日期范围、当前第几天、最新动态、今日动态数量、新媒体提示和“查看寄养动态”。

## 7. 宠物交友

### 7.1 单卡尺寸

375px 基准下参考：

- 三列单卡宽度为 `(实际内容宽度 - 2 × space.dense.card) / 3`；375px、左右 16px 时约 107.7px，320px 时约 89.3px，不同时硬编码 104px
- 单卡高度参考最小 166px，长昵称 / 标签 / 大字号可增高
- 圆角使用 `radius.card`
- 图片区为与卡宽一致的正方形，加载前保留比例

### 7.2 卡片结构

固定核心信息：

1. 宠物主图
2. 宠物昵称
3. 热度
4. 卡片底部浅色“可发送邀请”能力标签（仅符合条件时）

昵称推荐最多 4 字，但此为展示建议而非数据长度限制；卡片可省略，在详情提供全名。无法容纳完整“可发送邀请”时允许标签自然增高，不缩小文字或误作按钮。

热度不使用爱心 / 点赞图标语义；展示例如：

> 热度 286

热度基于最近 7 天有效点击及当前门店 7 日排名，前端只展示服务端结果。

### 7.3 轮播

- 每屏最多 3 只，一轮最多 12 只真实且不同的宠物；不足一屏时左对齐实际数量，不复制或放空白宠物卡凑数
- 真实数量至少 4 只且包含本人主宠物时，该宠物固定第 4 位；0～3 只及无本人宠物按 `03h` 第 2.1 节，不强造第二屏
- 一屏不自动播放；多屏默认自动轮播 + 手动滑动，提供页码及可点按的上一屏 / 下一屏、暂停 / 继续
- 间隔、手势后的最短恢复等待、动画统一引用 `10a` 第 2.5 节；手势 / 焦点阅读 / 弹层 / 离屏 / 后台时暂停
- 显式暂停不因短暂空闲、刷新或返回恢复；开启减少动态效果后仅手动切换。详细状态优先级以 `03h` 第 2.2 节为准

## 8. 上门喂养

### 8.1 顶部操作

- 发布需求：主操作
- 我的需求：次操作
- 右侧“更多需求”进入公开列表
- 操作按钮视觉高度可参考 36px，触控热区至少 `target.min`；窄屏可分行排列，保留所有入口

### 8.2 单卡

- 高度参考最小 132px；长地点 / 状态和字号放大时自然增高，不以 138px 作为上限
- 标题最多约 12 个中文字符
- 地点摘要建议 12 字内，必须优先完整保留真实城市 / 区县，必要时分行；完整模糊地点在详情可读
- 要求摘要最多约 18 个中文字符
- 预算使用明显但克制的暖橙 / 杏棕强调

客户端主状态：

1. 待接单
2. 已接单待门店对接
3. 进行中
4. 已完成

取消只用于历史 / 终止状态展示。

### 8.3 本地为空

当前城市无真实可公开需求时：

- 随机补充其他城市真实公开需求；
- 必须显示真实城市 / 区县；
- 不得伪造本地需求；
- 推荐 2～3 条；
- 如果全平台都无可公开需求，再展示真正 Empty State 和“发布需求”。

## 9. 精选商品

- 正常字号每屏建议 3 张；窄屏 / 大字号可使用较宽卡片横向浏览，不强行缩小内容
- 横向滑动
- 三列时宽度复用第 7.1 节可用宽度公式，高度参考最小 156px，可随内容增高
- 圆角使用 `radius.card`
- 图片区约 86px 高
- 商品名最多约 8 个中文字符 / 2 行内
- 副描述最多约 10 个中文字符 / 1 行
- 首页只突出图片、商品名、参考售价和必要库存状态
- 不展示复杂 SKU / 物流 / 收货地址

## 10. 首页底部微信 Banner 广告横幅

这是用于微信广告曝光变现的正式广告位，与顶部品牌 Banner、启动封面广告完全不同。

### 10.1 位置

固定在：

> 精选商品之后 → 微信 Banner 广告横幅 → 底部导航

使用 placement：

`home_bottom_banner`

### 10.2 布局

- 广告位属于正常内容流，不覆盖正文
- 水平宽度适配页面内容宽度
- 广告实际高度根据微信广告组件 / SDK 返回适配，不硬编码单一创意比例
- 与精选商品上方保持约 24px 模块间距
- 与底部导航 / 安全区之间建议至少保留 12～16px 可用间距（最终结合真实广告组件尺寸校准）
- 养宠顾问在符合付费门店资格显示时，也不得覆盖广告主要点击区域
- 页面底部内容占位按实际底部导航高度 + 底部安全区 + `space.4` 计算；系统已占据的空间不重复累加，广告完整区域可滚动至导航之上

### 10.3 加载状态

至少覆盖：

- disabled
- loading
- loaded
- no_fill
- failed

`disabled / no_fill / failed` 时自动收起，不留大块永久空白。

`loading` 只使用广告组件支持的预估占位，不伪造广告素材；返回实际尺寸后更新，保留当前阅读锚点。加载、变化与收起不能把用户按下位置变成不同业务按钮；同一轮加载收起后不反复展开重试，用户重新进入 / 合法刷新再按广告策略处理。

广告失败不得影响首页任何业务模块。

### 10.4 调试

开发 / H5 原型应提供清晰的“广告调试占位”状态，用于模拟：

- 加载成功
- 无填充
- 加载失败
- 已关闭
- 收起后页面布局

正式生产必须切换为真实微信广告组件，不允许 Mock 冒充真实广告。

广告单元 ID / 开关必须配置化，不散落硬编码在 UI 组件中。

## 11. 养宠顾问悬浮入口

产品方确认采用方案 A：圆形悬浮按钮，但**仅在当前门店具备有效付费权益且已向本店客户开放时显示**。

展示前提：

- 当前 Store 有有效 `pet_advisor` Feature Entitlement；唯一归属字段为 `owner_type=store`、`owner_id=store_id`，Merchant 仅作为购买、管理和审计主体；
- 门店已开启该功能；
- 当前 Platform User 已与本店建立有效 Customer 关系；
- 服务端资格校验通过。

未满足时首页不显示可用顾问悬浮按钮；不能仅靠前端本地开关强行展示后继续调用 AI。

满足条件时：

- 尺寸参考 52×52px
- 默认左侧中下安全区域
- 距边参考 8～12px
- 不遮挡底部导航、微信系统区域、首页底部 Banner 广告
- 可拖动
- 松手吸附最近左 / 右侧
- 吸附使用 `motion.snap`；减少动态效果时立即定位
- 采用柔和杏橙 / 奶油暖色，不使用绿色为基底或紫蓝科技发光

同一用户切换到未付费 / 已过期 / 已关闭门店后，悬浮入口应随当前门店上下文刷新并消失；切回符合资格门店后恢复。

遵循 `10a` 第 13.3 节提供可点选的“调整位置”，不能只能拖动。记忆位置须在当前视口、字号、底部栏及广告尺寸确定后重新限制在安全范围；键盘 / 弹层使入口无法避让时暂时隐藏，结束后恢复合法位置，不靠覆盖主按钮保持可见。

## 12. 底部导航

固定：

> 预约 | 首页 | 我的

- 当前项：暖橙 / 杏棕强调
- 未选中：暖灰中性色
- 线性圆角图标
- 热区至少 `target.min`，图标 + 文字标明选中项，不只靠颜色
- 使用平台实际底部安全区；H5 适配 `safe-area-inset-bottom`，系统 TabBar 已保留安全区时不重复补偿

## 13. 文案长度基线

| 区域 | 建议长度 |
|---|---|
| 门店名称 | 10 字内 |
| 顶部副标题 | 16 字内 |
| Banner 主标题 | 8～12 字 |
| 当前服务标题 | 14 字内 |
| 最新动态摘要 | 16 字内 |
| 宠物昵称 | 4 字内 |
| 上门喂养标题 | 12 字内 |
| 上门喂养要求摘要 | 18 字内 |
| 商品名 | 8 字内 |
| 商品副描述 | 10 字内 |
| 普通按钮文案 | 4～6 字 |

首页负责快速浏览和进入详情，不在首页展示长篇正文。

上述字数均为内容编排建议，不是表单数据校验上限。长文本按 `10a` 自然换行或提供详情全文，不因固定卡高吞掉主操作、状态、实际城市或金额。

## 14. 状态标签

统一参考：

- 正常字号最小高度 24px，随字号 / 内容增加
- 水平内边距约 10px
- 圆角约 12px
- 字号 / 行高用 `type.label`；关键状态需要更多说明时用 `type.body.small`
- 正常字号优先单行；空间不足时状态可独占一行或改为自然换行的浅底文字条，不能截断“已接单待门店对接”等完整状态

低饱和状态色只引用 `10a` 已验证的配对：

- 待接单 / 等待：brand.tint / brand.strong
- 已接单待门店对接：status.accepted.fill / .ink
- 进行中：status.info.fill / .ink
- 已完成：status.success.fill / .ink
- 已取消：status.neutral.fill / .ink

页面整体仍不是绿色基底。

## 15. 首页视觉权重

优先级：

1. 当前服务
2. 宠物交友
3. 上门喂养
4. 顶部品牌 Banner
5. 精选商品
6. 底部微信 Banner 广告（商业曝光位，但不压过核心业务）

Banner 广告需要真实曝光机会，但不得通过遮挡核心业务或破坏交互来获得曝光。

启动封面广告属于启动阶段的独立曝光层，按 `03p` 衔接原始业务目标，不纳入本首页视觉权重排序。

### 首屏任务验收

- 数据加载完成、100% 字号、320×568 / 375×812 / 430×932 逻辑视口、有至少一条当前服务时，从页首不滚动即可看到第一条服务的宠物身份、简化状态和完整主操作热区。测试使用真实系统顶部区域与底部导航，而不是裁掉这些区域的画板；不要求一屏展示全部 3 条服务。
- 若短屏不满足，按顺序使用 48px 紧凑品牌条、去除非必要顶部副标题、收紧顶部组内留白；不得改变模块顺序、压缩热区 / 文字下限或移除服务主操作。图片和装饰不先于服务信息占据空间。
- 150% / 200% 字号时允许自然纵向滚动，不以“仍要整卡塞进首屏”裁字或缩小按钮；第一条服务中身份、状态、主操作先于媒体和扩展摘要，完整信息与操作均可达。各字号下不发生正文横向滚动或系统区 / 键盘遮挡。
- 无当前服务时采用完整 Banner，并在随后区域给“去预约”；服务加载失败展示局部错误与重试，不错误切换成无服务营销态。
- 上述为待原型 / 真机验证的明确验收条件，不以参考高度相加或仅完成文档认定达标。

## 16. 故障隔离

任何一个首页模块失败只局部降级。

尤其：

- 微信 Banner 广告失败 → 广告收起，其他业务继续；
- 养宠顾问权益不可用 / 服务失败 → 不展示或局部提示，不影响首页；
- 宠物交友失败 → 仅交友区域错误；
- 上门喂养失败 → 不影响商品和当前服务；
- 当前服务失败 → 不得导致整页白屏。

首页所有模块使用 `10a` 第 13.1 节的 Loading / 刷新 / Empty / No Results / Error / Disabled / Busy 行为；首次服务加载、旧数据刷新和已确认空数据不可混为一态。

启动封面广告失败由 `03p / 10c` 处理，按 `03p` 恢复原始业务目标，无目标才回首页，不阻塞目标页。
