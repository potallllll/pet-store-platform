## 1. 产品定位

V1.0 新增平台级会员积分体系。

积分属于 Platform User，不属于某一家 Merchant / Customer 的会员余额。

必须与以下资产严格分离：

- 本金余额
- 赠送余额
- 商户优惠券
- 商户充值记录
- 商户钱包流水

平台积分不可提现、不可直接视为现金余额，不进入“我的钱包”资金账本。

本文件明确替代阶段 03 早期“客户端不设计积分机制”的旧总结规则；自本变更确认后，V1.0 正式包含平台积分体系。

## 2. 客户端入口

“我的”页面新增独立积分入口 / 积分摘要，不把积分塞入会员资产摘要卡。

建议结构：

- 当前积分
- 今日签到
- 积分商城
- 我的兑换
- 积分明细

会员资产摘要卡仍只展示当前可用余额、优惠券数量、本金余额和赠送余额。

## 3. 每日签到

每日签到必须完成一次有效激励视频广告观看后才算签到成功。

规则：

- 每个自然日最多成功签到一次。
- 广告未完整观看、加载失败或验证失败：签到不成功，不增加积分。
- 完整观看成功后由服务端生成当日签到奖励。
- 签到奖励每天为随机 1～10 积分。
- 随机值必须由服务端产生，前端不得决定最终积分。

## 4. 每周总奖励规则

自然周按服务端权威时间和全局业务时区 `Asia/Shanghai` 计算，范围为周一 00:00:00（含）至下一周周一 00:00:00（不含）。自然日和跨周归属不得由客户端本地时钟决定。

若用户一周 7 天均完成有效签到，则该自然周 7 次签到奖励累计必须正好为 50 积分。

因此每日“随机 1～10 分”不是完全无约束随机，而应由服务端采用受约束随机：

- 每日结果仍落在 1～10 分。
- 在用户持续完成整周签到的前提下，系统需保证剩余天数仍有可行分配空间。
- 第 7 次签到时补足该周精确总额 50 分，但当日结果仍必须在 1～10 分范围内。

> random_algorithm_owner: backend
> random_algorithm_status: pending_technical_design

产品需求只冻结“单日 1～10 分、全勤周严格 50 分、漏签不补足”的结果约束，不指定概率分布或随机算法。技术架构阶段必须冻结服务端算法版本与分布策略；客户端不得自行生成、预测或重算奖励。

每次成功签到以 `platform_user_id + Asia/Shanghai 自然日` 作为业务幂等范围，并保存最终 `awarded_points`、`algorithm_version`、服务端生成时间和关联广告权益记录。重复请求必须返回首次成功结果，算法升级不得改写历史奖励。

如果用户漏签：

- 只获得实际完成签到日期的积分。
- 不自动补足到 50 分。
- V1.0 不提供补签。
- 不因漏签而补发未获得积分。

示例：完整签到 7 天可出现 8 + 7 + 6 + 9 + 5 + 8 + 7 = 50，但具体每日结果每周可不同。

## 5. 积分账户与流水

积分必须使用独立积分账本，不允许只保存一个可被直接覆盖的余额字段。

至少记录：

- 变动类型
- 积分变动值（正 / 负）
- 变动前余额
- 变动后余额
- 来源业务 ID
- 时间
- 幂等键
- 备注 / 原因（如适用）

典型记录：

- 每日签到 +N
- 兑换实物 -N
- 兑换实物 -N
- 门店停用自动取消返还 +N
- 平台人工调整（如后续允许）

积分消费记录在积分中心 / 积分商城体系内独立展示，不混入商户钱包流水。

## 6. 积分商城管理权

积分商城由 Platform Super Admin 统一管理；实物奖励的总仓发货操作要求当前 Platform Super Admin 同时持有 `reward_fulfillment.manage` 权限。

V1.0 不允许普通 Merchant Owner 自行决定平台积分商品的积分价格。

超级管理员至少可配置：

- 奖励名称
- 奖励图片
- 实物奖励内容
- 所需积分
- 平台奖励库存
- 上下架状态
- 每人兑换上限（可选）
- 有效期（如适用）
- 可兑换 / 可领取门店范围
- 可领取门店范围和实物履约信息

## 7. 奖励类型：V1仅实物

V1积分商城只允许兑换平台实物奖励，例如狗粮、猫粮、冻干、零食和其他平台实物。不得配置或兑换商户优惠券、服务券、活动券、钱包余额或现金；对应券类字段和入口仅保留历史读取，禁止新写。V1不提供快递到家，统一采用总仓发往顾客选择门店后线下领取。
## 8. 总仓到门店自提流程

> status: confirmed
> status_scope: physical_rewards_only_with_disabled_store_points_return
> development_readiness: ready
> blocked_by: []
> reward_store_receipt_confirmation: excluded
> reward_pickup_credential: excluded
> reward_fulfillment_states: [待总仓发货, 已发往门店, 已领取, 已取消]
> reward_pickup_validity_hours_after_shipment: 720
> disabled_pickup_store_action: cancel_and_return_points
> replacement_store_selection: excluded

1. 兑换成功时服务端原子扣积分、占用平台奖励库存并生成原兑换单；失败或结果未知按同一请求恢复，不重复扣分或占库存。只有持有`reward_fulfillment.manage`的Platform Super Admin可以登记真实总仓发货。
2. 不设置门店到货确认、领取凭证或扫码。顾客实际领取后，原领取门店老板／有效员工在原兑换单登记“已领取”；不需要审批。
3. 真实发货起连续720小时仍未登记领取时，系统默认已领取且不退积分；必须标记系统默认来源，不伪造实际领取时间或店员。
4. 原领取门店账号停用时，原兑换单自动取消并原路退回本次积分，向顾客发送重要通知；顾客不能重新选择门店。未发货的占用库存释放；已发货实物由平台在原兑换单记录后续处理，门店无操作。
5. 门店停用取消与人工领取、720小时默认完成并发时，以服务端先成功的状态转换为准，同一兑换只产生一个终态；积分最多退回一次。
6. 实物错发、损坏、少件、无法领取等异常全部由平台在原兑换单处理；门店端不提供异常登记、换货、补发、退积分或改店操作。
7. 成功兑换在领取门店有效时，顾客和门店均不能主动取消；只有门店账号停用触发第4条自动取消退积分。兑换失败的原子回滚不受此限制。
8. 系统自动记录每次状态修改的操作主体、服务端时间及改前改后；顾客查看真实状态与平台处理结果，普通门店不能读取平台内部处理备注。

### 8.1 状态与动作

| 状态／条件 | 处理主体 | 结果 |
|---|---|---|
| 待总仓发货 | Platform Super Admin | 登记真实发货后进入已发往门店 |
| 已发往门店且实际领取 | 原门店老板／有效员工 | 登记已领取，保存真实人和时间 |
| 已发往门店满720小时未登记 | 系统 | 默认已领取，不退积分，不伪造实际交付 |
| 原领取门店账号停用 | 系统＋平台 | 自动取消、退回积分、重要通知顾客；不允许换店 |
| 实物异常 | 平台 | 在原兑换单处理，门店无动作 |
| 已领取／已取消 | 各端只读 | 不重复扣分、退分、出库或完成 |

### 8.2 奖励自提内部备注

奖励自提内部备注由平台在原兑换单维护；门店不提供新增或修改入口。平台修改同样自动记录实际操作人、时间和前后值，备注不向其他门店公开。
## 9. 积分商城库存边界

积分实物奖励使用平台 / 总仓独立奖励库存，不直接占用某家门店普通商品销售库存。

至少概念上区分：

- `reward_inventory`：平台总仓积分奖励库存
- `store_product_inventory`：门店商品正常销售库存

总仓将积分奖励发到门店用于履约时，应记录真实总仓发货和顾客领取结果，不设置门店到货确认阶段，但不应无理由把积分奖励自动并入门店普通可售库存。

## 10. 我的兑换

客户端“我的兑换”至少展示：

- 奖励名称
- 消耗积分
- 领取 / 使用门店
- 当前状态
- 兑换时间

历史上已经合法产生的券类兑换记录仅按原权限只读展示；V1不得再创建或兑换券类奖励。当前实物奖励显示真实发货和领取状态，不推断已到货，不展示领取凭证。

兑换记录属于 Platform User，切换当前门店后仍可查看；关联领取 / 使用门店须如实展示。查看具体商户优惠券时，按 `03g` / `03f` 校验对应门店 Customer 权限后进入，不把平台兑换记录作为越权凭证。

## 11. 故障隔离

积分系统故障不得导致：

- 商户钱包不可用
- 洗护 / 美容不可用
- 寄养不可用
- 商品正常销售不可用
- 订单收银不可用

积分签到 / 商城不可用时，只降级积分相关能力。

## 12. V1.0 关键验收场景

### C-POINTS-01：每日签到

- 点击签到后进入激励广告。
- 完整观看后签到成功。
- 当日增加 1～10 随机积分。
- 同一天不得重复获得签到积分。
- 同日重复请求返回首次成功的相同积分值；记录可追溯到算法版本、服务端生成时间和广告权益记录，客户端不重新随机。

### C-POINTS-02：完整自然周

- 用户周一至周日每天完成签到。
- 每天奖励均在 1～10 分。
- 7 天合计严格为 50 分。

### C-POINTS-03：漏签

- 未签到日期无积分。
- 该周不自动补足 50。
- 无补签。

### C-POINTS-04：V1不兑换券

- 积分商城不展示优惠券／服务券／活动券奖励。
- 历史已合法发出的积分券只读保留，不允许新兑换。

### C-POINTS-05：兑换实物

- 选择领取门店。
- 仅持有 `reward_fulfillment.manage` 的 Platform Super Admin 可确认总仓发货到门店；Merchant Owner 与 Staff 不可执行。
- 无门店到货确认／奖励收货待办，无领取凭证／扫码验码；发货不自动表示到货或已领取。
- 门店线下联系，顾客实际领取后店员在原兑换单点已领取，记录门店／员工／时间，不需老板审批。

### 兑换边界验收补充

- 重复提交、网络重试及迟到回调不重复扣积分 / 占库存；最后一份库存并发兑换结果符合真实库存。
- 结果未知时可从我的兑换恢复查询；补偿未入账时显示返还处理中，不提前展示积分已返还。
- 未发货／历史已取消／其他门店不能人工登记领取；实际未交付不能人工假记。发货起720小时到期与人工登记并发只完成一次，分别保留manual_actual或timeout_default来源，默认完成不伪造实际领取时间／员工；成功重试不重复。
- 成功兑换后发货前后均不能取消、不退积分；发货起720小时未登记按§8.5默认已领取，非取消。门店停用自动取消原兑换、退回积分并发送重要通知，不允许换店，失败补偿及原历史保留。
