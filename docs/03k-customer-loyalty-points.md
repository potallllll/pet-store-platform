## 1. 产品定位

V1.0 新增平台级会员积分体系。

积分属于 Platform User，不属于某一家 Merchant / Customer 的会员余额。

必须与以下资产严格分离：

- 本金余额
- 赠送余额
- 商户优惠券
- 商户充值记录
- 商户钱包流水

平台积分不可提现、不可直接视为现金余额，不进入“我的钱包”资金账本。

本文件明确替代阶段 03 早期“客户端不设计积分机制”的旧总结规则；自本变更确认后，V1.0 正式包含平台积分体系。

## 2. 客户端入口

“我的”页面新增独立积分入口 / 积分摘要，不把积分塞入会员资产摘要卡。

建议结构：

- 当前积分
- 今日签到
- 积分商城
- 我的兑换
- 积分明细

会员资产摘要卡仍只展示当前可用余额、优惠券数量、本金余额和赠送余额。

## 3. 每日签到

每日签到必须完成一次有效激励视频广告观看后才算签到成功。

规则：

- 每个自然日最多成功签到一次。
- 广告未完整观看、加载失败或验证失败：签到不成功，不增加积分。
- 完整观看成功后由服务端生成当日签到奖励。
- 签到奖励每天为随机 1～10 积分。
- 随机值必须由服务端产生，前端不得决定最终积分。

## 4. 每周总奖励规则

自然周按服务端权威时间和全局业务时区 `Asia/Shanghai` 计算，范围为周一 00:00:00（含）至下一周周一 00:00:00（不含）。自然日和跨周归属不得由客户端本地时钟决定。

若用户一周 7 天均完成有效签到，则该自然周 7 次签到奖励累计必须正好为 50 积分。

因此每日“随机 1～10 分”不是完全无约束随机，而应由服务端采用受约束随机：

- 每日结果仍落在 1～10 分。
- 在用户持续完成整周签到的前提下，系统需保证剩余天数仍有可行分配空间。
- 第 7 次签到时补足该周精确总额 50 分，但当日结果仍必须在 1～10 分范围内。

> random_algorithm_owner: backend
> random_algorithm_status: pending_technical_design

产品需求只冻结“单日 1～10 分、全勤周严格 50 分、漏签不补足”的结果约束，不指定概率分布或随机算法。技术架构阶段必须冻结服务端算法版本与分布策略；客户端不得自行生成、预测或重算奖励。

每次成功签到以 `platform_user_id + Asia/Shanghai 自然日` 作为业务幂等范围，并保存最终 `awarded_points`、`algorithm_version`、服务端生成时间和关联广告权益记录。重复请求必须返回首次成功结果，算法升级不得改写历史奖励。

如果用户漏签：

- 只获得实际完成签到日期的积分。
- 不自动补足到 50 分。
- V1.0 不提供补签。
- 不因漏签而补发未获得积分。

示例：完整签到 7 天可出现 8 + 7 + 6 + 9 + 5 + 8 + 7 = 50，但具体每日结果每周可不同。

## 5. 积分账户与流水

积分必须使用独立积分账本，不允许只保存一个可被直接覆盖的余额字段。

至少记录：

- 变动类型
- 积分变动值（正 / 负）
- 变动前余额
- 变动后余额
- 来源业务 ID
- 时间
- 幂等键
- 备注 / 原因（如适用）

典型记录：

- 每日签到 +N
- 兑换优惠券 -N
- 兑换实物 -N
- 兑换取消返还 +N
- 平台人工调整（如后续允许）

积分消费记录在积分中心 / 积分商城体系内独立展示，不混入商户钱包流水。

## 6. 积分商城管理权

积分商城由 Platform Super Admin 统一管理；实物奖励的总仓发货操作要求当前 Platform Super Admin 同时持有 `reward_fulfillment.manage` 权限。

V1.0 不允许普通 Merchant Owner 自行决定平台积分商品的积分价格。

超级管理员至少可配置：

- 奖励名称
- 奖励图片
- 奖励类型
- 所需积分
- 平台奖励库存
- 上下架状态
- 每人兑换上限（可选）
- 有效期（如适用）
- 可兑换 / 可领取门店范围
- 优惠券面额与适用范围（券类）

## 7. 奖励类型

### 7.1 线下消费优惠券

积分可兑换门店线下消费优惠券，例如：

- 固定金额优惠券
- 洗护优惠券
- 美容优惠券
- 寄养优惠券
- 其他平台允许的商户消费券

兑换前用户应选择适用 / 领取门店（若该奖励要求绑定门店）。

兑换成功后：

积分系统负责扣减积分并保存兑换记录；
钱包 / 优惠券域负责向所选 Merchant Customer 发放正式优惠券。

两者不得共用同一账本；跨模块失败必须支持幂等和补偿，避免积分已扣但优惠券未发或重复发券。

兑换门店需处于奖励允许范围内并有效；若尚未建立所选 Merchant Customer 关系，先按 `03g` 完成必要身份与关系校验，再确认扣积分。选择领取 / 使用门店本身不得读取其他门店的资产或自动共享宠物档案。

跨模块结果未确定时，客户端显示“兑换处理中”并可回到同一兑换记录查询；补偿已启动但尚未到账时显示“返还处理中”。只在优惠券已成功发放或积分补偿流水已成功入账后展示对应成功结果。

### 7.2 实物奖励

支持兑换：

- 狗粮
- 猫粮
- 冻干
- 零食
- 其他平台积分实物奖励

V1.0 不提供用户快递到家。

统一采用：

> 总仓发货到指定门店 → 实物线下到店 → 用户实际领取后店员登记已领取（无到货确认／领取凭证）。

用户兑换实物时：

选择奖励 → 选择领取门店 → 确认兑换并扣积分／生成原兑换单 → 生成总仓发货任务 → 持有reward_fulfillment.manage的Platform Super Admin确认发往指定门店 → 实物线下到店并由门店联系顾客 → 顾客实际领取后，本店老板／有效员工在原兑换单点击“已领取”。

系统履约状态为待总仓发货、已发往门店、已领取、已取消，不再设置“门店已收货／待自提”状态转换、门店到货确认按钮或奖励收货待办。物流实际到店及线下联系不增加系统确认步骤；已发往门店不表示已经到货或现在即可领取，不用发货、预计日期、页面访问或定时任务自动推断到店／已领取。

### 8.1 提交与展示

- 确认兑换时，服务端校验积分可用余额、奖励上架／限额、总仓奖励库存和领取门店资格。同一次请求只生成一个兑换结果，不因重复点击、重试或回调重复扣积分／占库存。
- 宣布兑换成功前，扣积分、占奖励库存和唯一兑换单须结果一致；结果未知展示兑换处理中，先查询原请求，失败按可审计补偿恢复。积分处理与实物履约分别展示，不把兑换处理中／返还处理中冒充已领取或已返还。
- 详情展示奖励、积分数、所选领取门店、真实履约／积分状态、最近更新时间和下一步。发货后显示“已发往门店，请联系门店确认领取时间”，不显示未经确认的已到货／可立即领取，不生成领取码、二维码、领取凭证或凭证核验指引。
- 顾客到店无需出示系统领取凭证。店员在本店原兑换记录找到对应顾客及奖励，实际交付后点“已领取”，保留真实领取时间、办理门店、经办员工及审计；不另设顾客确认、短信核验、照片／签字或老板审批。
- 系统保留真实发货及领取结果通知，不再依赖门店收货动作自动发送到货通知；实际到店后的联系由门店线下完成，不新增物流回调、自动签收或到货时间估算机制。

### 8.2 状态、主体与动作

| 状态 / 条件 | 主体 | 动作与校验 | 结果 / 客户端反馈 |
|---|---|---|---|
| 兑换处理中 / 请求结果未知 | 兑换用户 | 查询同一请求，不另起扣积分 | 原兑换结果或仍在处理，不因超时显示成功 |
| 待总仓发货 | 持有reward_fulfillment.manage的Platform Super Admin | 确认发货；取消权限／截止／退回路径仍受DEC-POINTS-01阻塞 | 已发往门店并审计，不自动标已到货／已领取 |
| 已发往门店且未取消 | 所选领取门店老板／有效员工 | 实物确已交给该顾客后，在原兑换单点击已领取；不要求收货确认记录或领取凭证 | 一次记已领取，记录本店／员工／实际领取时间，未实际交付不可提前点 |

| 已领取 | 兑换用户、原领取门店 | 查看历史；重复点击返回原结果 | 不重复扣积分／出库／生成领取记录，不通过原兑换取消返积分 |
| 非终止状态且门店停用／履约异常 | 兑换用户及原业务有权限人员 | 查真实状态；按DEC-POINTS-02待决边界处理 | 不自动作废、改店或标已领取，不无痕改积分 |

### 8.3 并发与领取记录

- 奖励库存与门店普通商品库存分离，最后一份并发兑换不得超兑；取消／失败补偿仍保留记录。
- 只允许所选领取门店的有效老板／员工对已发往门店且未取消的兑换单登记真实领取，不限定原经办人，不新增逐员工权限。未发货／已取消／其他门店对象不能登记领取；不能因为熟客免凭证而跨店读取或替其他用户领取。
- 无领取凭证不等于无状态／权限校验；服务端校验原兑换单、所选门店、实际操作者、最新状态及请求幂等。已领取的重试只返回原结果，不重复发放、扣积分、出库或记领取时间。
- 有效取消与领取互斥，服务端只允许一个合法转换成功；取消成立后不能领取，领取成立后不能再按原兑换取消返积分。本条不提前开放DEC-POINTS-01阻塞的取消权限／入口。
- 已取消与积分已返还分开，补偿失败保留处理中并按原业务键重试，不能重复加积分；发货后连续30天未领取自动取消且不退积分按§8.5已定；停店／改店及剩余异常仍按DEC-POINTS-02，本次到货与凭证简化不取消这些规则。

- 原发货／兑换／门店及取消原因时间保留，截止不因打开、联系、切店或重试重置。超期取消不表示实物已退仓、不自动增加总仓或门店可售库存；未领实物、停店改店及事后误登记等异常细则仍待DEC-POINTS-02。本条不增加到货确认、领取凭证、短信或额外逾期提醒。

## 9. 积分商城库存边界

积分实物奖励使用平台 / 总仓独立奖励库存，不直接占用某家门店普通商品销售库存。

至少概念上区分：

- `reward_inventory`：平台总仓积分奖励库存
- `store_product_inventory`：门店商品正常销售库存

总仓将积分奖励发到门店用于履约时，应记录真实总仓发货和顾客领取结果，不设置门店到货确认阶段，但不应无理由把积分奖励自动并入门店普通可售库存。

## 10. 我的兑换

客户端“我的兑换”至少展示：

- 奖励名称
- 消耗积分
- 领取 / 使用门店
- 当前状态
- 兑换时间

券类奖励可深链到对应优惠券；实物奖励显示真实发货和领取状态，不推断已到货，不展示领取凭证。

兑换记录属于 Platform User，切换当前门店后仍可查看；关联领取 / 使用门店须如实展示。查看具体商户优惠券时，按 `03g` / `03f` 校验对应门店 Customer 权限后进入，不把平台兑换记录作为越权凭证。

## 11. 故障隔离

积分系统故障不得导致：

- 商户钱包不可用
- 洗护 / 美容不可用
- 寄养不可用
- 商品正常销售不可用
- 订单收银不可用

积分签到 / 商城不可用时，只降级积分相关能力。

## 12. V1.0 关键验收场景

### C-POINTS-01：每日签到

- 点击签到后进入激励广告。
- 完整观看后签到成功。
- 当日增加 1～10 随机积分。
- 同一天不得重复获得签到积分。
- 同日重复请求返回首次成功的相同积分值；记录可追溯到算法版本、服务端生成时间和广告权益记录，客户端不重新随机。

### C-POINTS-02：完整自然周

- 用户周一至周日每天完成签到。
- 每天奖励均在 1～10 分。
- 7 天合计严格为 50 分。

### C-POINTS-03：漏签

- 未签到日期无积分。
- 该周不自动补足 50。
- 无补签。

### C-POINTS-04：兑换优惠券

- 扣积分后获得指定门店优惠券。
- 积分记录与商户优惠券记录分别可查。

### C-POINTS-05：兑换实物

- 选择领取门店。
- 仅持有 `reward_fulfillment.manage` 的 Platform Super Admin 可确认总仓发货到门店；Merchant Owner 与 Staff 不可执行。
- 无门店到货确认／奖励收货待办，无领取凭证／扫码验码；发货不自动表示到货或已领取。
- 门店线下联系，顾客实际领取后店员在原兑换单点已领取，记录门店／员工／时间，不需老板审批。

### 兑换边界验收补充

- 重复提交、网络重试及迟到回调不重复扣积分 / 占库存；最后一份库存并发兑换结果符合真实库存。
- 结果未知时可从我的兑换恢复查询；补偿未入账时显示返还处理中，不提前展示积分已返还。
- 未发货／已取消／其他门店不能登记领取；已发货未实际交付不提前记领取，无收货记录及领取凭证不阻断真实领取。重复点击只返回原结果，取消与领取竞态仅一个合法转换成功；不扩大待决取消权限。
- 切店不隐藏本人兑换；发货起720小时未领按§8.5自动取消且不退积分；其他停店／改店异常保留真实状态，不执行未确认的自动改店。
