# 03K 客户端「平台积分 + 每日签到 + 积分商城」模块

> 状态：已确认子模块
> 所属阶段：03 客户端微信小程序
> 版本：V1.0

## 1. 产品定位

V1.0 新增平台级会员积分体系。

积分属于 Platform User，不属于某一家 Merchant / Customer 的会员余额。

必须与以下资产严格分离：

- 本金余额
- 赠送余额
- 商户优惠券
- 商户充值记录
- 商户钱包流水

平台积分不可提现、不可直接视为现金余额，不进入“我的钱包”资金账本。

本文件明确替代阶段 03 早期“客户端不设计积分机制”的旧总结规则；自本变更确认后，V1.0 正式包含平台积分体系。

## 2. 客户端入口

“我的”页面新增独立积分入口 / 积分摘要，不把积分塞入会员资产摘要卡。

建议结构：

- 当前积分
- 今日签到
- 积分商城
- 我的兑换
- 积分明细

会员资产摘要卡仍只展示当前可用余额、优惠券数量、本金余额和赠送余额。

## 3. 每日签到

每日签到必须完成一次有效激励视频广告观看后才算签到成功。

规则：

- 每个自然日最多成功签到一次。
- 广告未完整观看、加载失败或验证失败：签到不成功，不增加积分。
- 完整观看成功后由服务端生成当日签到奖励。
- 签到奖励每天为随机 1～10 积分。
- 随机值必须由服务端产生，前端不得决定最终积分。

## 4. 每周总奖励规则

自然周定义为周一 00:00 至周日 23:59（按平台统一业务时区执行）。

若用户一周 7 天均完成有效签到，则该自然周 7 次签到奖励累计必须正好为 50 积分。

因此每日“随机 1～10 分”不是完全无约束随机，而应由服务端采用受约束随机：

- 每日结果仍落在 1～10 分。
- 在用户持续完成整周签到的前提下，系统需保证剩余天数仍有可行分配空间。
- 第 7 次签到时补足该周精确总额 50 分，但当日结果仍必须在 1～10 分范围内。

如果用户漏签：

- 只获得实际完成签到日期的积分。
- 不自动补足到 50 分。
- V1.0 不提供补签。
- 不因漏签而补发未获得积分。

示例：完整签到 7 天可出现 8 + 7 + 6 + 9 + 5 + 8 + 7 = 50，但具体每日结果每周可不同。

## 5. 积分账户与流水

积分必须使用独立积分账本，不允许只保存一个可被直接覆盖的余额字段。

至少记录：

- 变动类型
- 积分变动值（正 / 负）
- 变动前余额
- 变动后余额
- 来源业务 ID
- 时间
- 幂等键
- 备注 / 原因（如适用）

典型记录：

- 每日签到 +N
- 兑换优惠券 -N
- 兑换实物 -N
- 兑换取消返还 +N
- 平台人工调整（如后续允许）

积分消费记录在积分中心 / 积分商城体系内独立展示，不混入商户钱包流水。

## 6. 积分商城管理权

积分商城由 Platform Super Admin 统一管理。

V1.0 不允许普通 Merchant Owner 自行决定平台积分商品的积分价格。

超级管理员至少可配置：

- 奖励名称
- 奖励图片
- 奖励类型
- 所需积分
- 平台奖励库存
- 上下架状态
- 每人兑换上限（可选）
- 有效期（如适用）
- 可兑换 / 可领取门店范围
- 优惠券面额与适用范围（券类）

## 7. 奖励类型

### 7.1 线下消费优惠券

积分可兑换门店线下消费优惠券，例如：

- 固定金额优惠券
- 洗护优惠券
- 美容优惠券
- 寄养优惠券
- 其他平台允许的商户消费券

兑换前用户应选择适用 / 领取门店（若该奖励要求绑定门店）。

兑换成功后：

积分系统负责扣减积分并保存兑换记录；
钱包 / 优惠券域负责向所选 Merchant Customer 发放正式优惠券。

两者不得共用同一账本；跨模块失败必须支持幂等和补偿，避免积分已扣但优惠券未发或重复发券。

兑换门店需处于奖励允许范围内并有效；若尚未建立所选 Merchant Customer 关系，先按 `03g` 完成必要身份与关系校验，再确认扣积分。选择领取 / 使用门店本身不得读取其他门店的资产或自动共享宠物档案。

跨模块结果未确定时，客户端显示“兑换处理中”并可回到同一兑换记录查询；补偿已启动但尚未到账时显示“返还处理中”。只在优惠券已成功发放或积分补偿流水已成功入账后展示对应成功结果。

### 7.2 实物奖励

支持兑换：

- 狗粮
- 猫粮
- 冻干
- 零食
- 其他平台积分实物奖励

V1.0 不提供用户快递到家。

统一采用：

> 总仓发货到指定门店 → 门店收货 → 用户到门店自提。

## 8. 总仓到门店自提流程

用户兑换实物时：

选择奖励
→ 选择可领取门店
→ 确认兑换
→ 扣减积分并生成积分兑换单
→ 总仓生成发货任务
→ 总仓发货到指定门店
→ 门店确认收货
→ 状态变为“待用户自提”
→ 通知用户到店领取
→ 店员核销 / 确认领取
→ 状态“已领取”

至少支持状态：

- 待总仓发货
- 已发往门店
- 门店已收货 / 待自提
- 已领取
- 已取消

如因平台缺货等原因取消兑换，必须通过积分补偿流水返还积分，不允许直接无痕改余额。

### 8.1 提交与处理状态

- 确认兑换时，服务端统一校验积分可用余额、奖励上架状态 / 限额、总仓可用奖励库存和领取门店资格。同一次请求只生成一个兑换结果，不因重复点击、网络重试或回调而重复扣积分或重复占库存。
- 对用户宣布“兑换成功”前，扣积分、占用奖励库存、唯一兑换单之间必须得到一致结果；任一步结果未知时展示“兑换处理中”，先查询原请求，不发起另一笔兑换。失败按可审计补偿恢复，不能留下无人处理的扣分结果。
- 积分处理状态与实物履约状态分开表达。`兑换处理中`、`返还处理中`是结果尚未确定的处理提示，不伪装成“待总仓发货”“已返还”或“已领取”。
- 详情页至少展示奖励、积分数、领取门店、当前履约状态、积分处理结果、最近更新时间及下一步。待自提时展示领取门店信息和本人可用的领取凭证 / 核验指引；凭证不得让其他门店或其他用户取得核销权限。

### 8.2 状态、主体与动作

| 状态 / 条件 | 主体 | 动作与校验 | 结果 / 客户端反馈 |
|---|---|---|---|
| 兑换处理中 / 请求结果未知 | 兑换用户 | 查询同一请求；重试不得另起一笔扣分 | 恢复原兑换结果或明确仍在处理，不能因超时显示成功 |
| 待总仓发货 | 平台 / 总仓有权限人员 | 按已有履约权限发货；取消由已确认规则校验 | 进入已发往门店；取消成立时阻止继续发货并进入积分补偿流程 |
| 已发往门店 | 所选领取门店有权限人员 | 实际收货后确认收货 | 进入待自提并通知用户；不得直接核销为已领取 |
| 门店已收货 / 待自提 | 兑换用户、所选领取门店有权限人员 | 用户到店，门店核验本人兑换凭证及订单状态后确认领取 | 仅成功核销后成为已领取，记录核销门店、人员和时间 |
| 已取消且积分未返还完成 | 兑换用户、补偿处理服务 | 用户查询结果；按原兑换单幂等返还积分 | 显示“已取消 · 返还处理中”，补偿流水成功后显示已返还 |
| 已领取 | 兑换用户、原领取门店 | 查看历史；重复核销返回原结果 | 不重复出库，不再通过原兑换取消流程返还积分 |
| 任一非终止状态且领取门店停用 / 发生履约异常 | 兑换用户及原业务有权限人员 | 查看具体原因、当前积分与履约结果；接续策略见待决清单 | 保留记录与已占库存去向，不静默改店、标记已领取或无痕加减积分 |

用户能否主动取消、发货后如何退回等尚未确认的动作，按 `DEC-POINTS-01` 处理，不据表格自行新增客户端取消权限。

### 8.3 并发、取消与核销

- 最后一份奖励库存并发兑换时，只能形成符合库存约束的成功兑换；失败用户的积分不得被永久扣留。取消或失败释放奖励占用时要保留库存处理记录，不与门店普通销售库存混用。
- 核销只允许所选领取门店的有权限人员对“待自提”且未取消的兑换单执行；未收货、已取消、已领取或其他门店的兑换单不能新核销。
- 有效取消和核销互斥：只有一个符合最新状态的操作可成功。取消已成立即不得领取；核销已成立不得再通过取消返积分，重复请求只返回原结果。
- “已取消”与“积分已返还”不得等同。补偿失败保留返还处理中 / 异常提示和可查询记录，后续重试使用原补偿业务键，只返还一次；结果明确后按 `03f` 通知用户。
- 自提逾期、领取门店停用、用户希望改领取门店时，不自动作废权益、自动变更门店或转入商户钱包；具体处理见 `DEC-POINTS-02`。

### 8.4 待决清单（不属于已确认可执行规则）

| 决策 ID | 待确认内容 | 收口阶段 / 影响 |
|---|---|---|
| DEC-POINTS-01 | 用户主动取消权限、取消截止、已发货后的退回 / 取消路径及人员权限 | 阶段 06；决定取消入口和履约 / 补偿状态迁移 |
| DEC-POINTS-02 | 自提期限、逾期提醒与权益处理、领取门店停用后的接续、是否允许改领取门店 | 阶段 05 / 06；决定异常履约页与后台流程，不自动扩大商户资金权限 |

## 9. 积分商城库存边界

积分实物奖励使用平台 / 总仓独立奖励库存，不直接占用某家门店普通商品销售库存。

至少概念上区分：

- `reward_inventory`：平台总仓积分奖励库存
- `store_product_inventory`：门店商品正常销售库存

总仓将积分奖励发到门店用于履约时，应记录运输 / 到店 / 核销状态，但不应无理由把积分奖励自动并入门店普通可售库存。

## 10. 我的兑换

客户端“我的兑换”至少展示：

- 奖励名称
- 消耗积分
- 领取 / 使用门店
- 当前状态
- 兑换时间

券类奖励可深链到对应优惠券；实物奖励显示物流到门店状态和自提状态。

兑换记录属于 Platform User，切换当前门店后仍可查看；关联领取 / 使用门店须如实展示。查看具体商户优惠券时，按 `03g` / `03f` 校验对应门店 Customer 权限后进入，不把平台兑换记录作为越权凭证。

## 11. 故障隔离

积分系统故障不得导致：

- 商户钱包不可用
- 洗护 / 美容不可用
- 寄养不可用
- 商品正常销售不可用
- 订单收银不可用

积分签到 / 商城不可用时，只降级积分相关能力。

## 12. V1.0 关键验收场景

### C-POINTS-01：每日签到

- 点击签到后进入激励广告。
- 完整观看后签到成功。
- 当日增加 1～10 随机积分。
- 同一天不得重复获得签到积分。

### C-POINTS-02：完整自然周

- 用户周一至周日每天完成签到。
- 每天奖励均在 1～10 分。
- 7 天合计严格为 50 分。

### C-POINTS-03：漏签

- 未签到日期无积分。
- 该周不自动补足 50。
- 无补签。

### C-POINTS-04：兑换优惠券

- 扣积分后获得指定门店优惠券。
- 积分记录与商户优惠券记录分别可查。

### C-POINTS-05：兑换实物

- 选择领取门店。
- 总仓发货到门店。
- 门店收货后通知用户。
- 用户到店自提并由店员核销。

### 兑换边界验收补充

- 重复提交、网络重试及迟到回调不重复扣积分 / 占库存；最后一份库存并发兑换结果符合真实库存。
- 结果未知时可从我的兑换恢复查询；补偿未入账时显示返还处理中，不提前展示积分已返还。
- 未收货不能核销、其他门店不能核销、重复核销只返回原结果；取消与核销同时发生仅一方成功。
- 切店不隐藏本人兑换；领取门店停用、逾期待处理时保留真实履约与积分状态，不执行未确认的自动作废 / 改店规则。

## 13. 需求变更记录

### 2026-09-08：兑换处理中、实物履约与返还边界

【需求变更】

- 原规则：已有独立积分账本、券类幂等补偿、总仓库存与取消补偿流水，但实物请求结果未知、取消 / 核销并发、未到账提示和停店接续缺少可验收口径。
- 新规则：补充一致兑换结果、处理中 / 返还处理中展示、主体状态动作表、指定门店核销与取消互斥，以及跨店个人兑换查询；未确认的取消 / 发货后处理、自提期限 / 停店改店列为 `DEC-POINTS-01`～`02`。
- 影响范围：积分商城、我的兑换、消息、总仓履约、门店收货 / 核销、积分补偿、阶段 06 与验收。

### 2026-09-06：新增平台积分体系

【需求变更】

- 原规则：阶段 03 早期明确“客户端不设计积分机制”。
- 新规则：V1.0 新增 Platform User 级积分、广告签到、积分商城、优惠券兑换与总仓到门店自提的实物兑换流程。
- 签到新规则：每日完整观看广告后随机获得 1～10 分；完整自然周 7 天签到累计严格为 50 分；漏签则只获得实际签到积分，不补足 50。
- 实物履约：平台总仓发货至用户选择的门店，门店收货后用户到店自提。
- 影响范围：客户端“我的”、广告权益、平台超级管理员后台、总仓履约、门店收货 / 核销、优惠券、数据库、API、统计与技术架构。
