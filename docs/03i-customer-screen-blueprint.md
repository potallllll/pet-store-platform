> 版本：V1.0

## 1. 文档职责

本文件是客户端当前**主产品页面蓝图**，用于冻结：

- 客户端页面地图
- 一级 / 二级入口关系
- 首页与“我的”等核心页面的信息顺序
- 关键页面默认状态
- 关键交互路径
- H5 / UI 原型最小验收范围

本文件已于 2026-09-06 合并此前 `03n-customer-screen-blueprint-extension.md` 的新增功能入口关系与关键场景，因此不再保留“旧首页顺序 / 无积分”等过期假设。

`03n` 继续作为上门喂养、积分、养宠顾问、广告权益等新增功能的详细页面补充，但不得与本文件当前总蓝图冲突。

本文件**不冻结最终视觉参数**，包括：品牌色、背景色、字体、字号、圆角、阴影、图标、渐变、精确动效曲线、精确轮播秒数、栅格 / 间距 Token。最终视觉在阶段 10 UI / Design System 中统一确认。

## 3. 首页蓝图

首页信息顺序固定为：

1. 当前门店
2. 当前服务
3. 宠物交友
4. 上门喂养
5. 推荐商品

2026-09-06 已正式将“宠物交友”和“上门喂养”的顺序调整为以上版本。旧原型 / 旧文档中的“当前服务 → 上门喂养 → 宠物交友”不得继续使用。

### 3.1 当前门店

顶部只突出：

- 当前门店名称
- 必要时的切换门店入口

不额外显示“当前门店”“已绑定客户”等重复辅助标签。

### 3.2 当前服务

当前服务为首页最高优先级区域。

- 首页最多直接显示 3 条进行中 / 刚完成服务。
- 更多服务进入完整列表。
- 洗护 / 美容只显示客户简化状态。
- 寄养卡展示日期范围、当前第几天、今日动态数量、最近动态、新图片 / 视频提示。
- 寄养卡必须提供“查看寄养动态”入口。
- 无当前服务时使用轻量预约引导。

### 3.3 洗护 / 美容刚完成

- 客户打开小程序仍进入首页。
- 显示服务完成提示。
- 提供“查看本次服务结果”和“稍后查看”。
- “稍后查看”后完成卡继续保留。
- 真正查看过结果后，该完成服务退出首页当前服务区域。

### 3.4 寄养动态时间轴

点击“查看寄养动态”后进入当前宠物寄养详情。

页面顶部先展示：

- 宠物
- 寄养日期范围
- 当前第几天
- 当前状态
- 今日更新数量

之后展示**按真实发生时间倒序排列的时间轴**：

> 最新动态在上 → 更早动态向下

要求：

- 按日期分组，如今天 / 昨天 / 具体日期。
- 最新一条可使用“最新”等轻量状态提示。
- 每条至少表达时间、动作类型和说明。
- 图片 / 视频动态允许在对应时间点直接展示媒体缩略图 / 预览入口。
- 动态类型至少覆盖喂食、饮水、排泄、遛宠、玩耍、休息、清洁、用药 / 特殊照护、照片 / 视频、寄养加餐、异常和自定义事件。
- 客户端排序使用业务记录的 `occurred_at` / 实际发生时间，不使用录入时间替代。
- 店员补录历史事件时，应插回真实发生时间位置，而不是简单显示为最新录入。

寄养详情下方在符合条件时提供“投喂零食”。

### 3.5 宠物交友

首页宠物交友区域：

- 自动横向轮播，同时支持手动滑动。
- 用户操作时自动轮播让位，短暂空闲后恢复。
- 每屏 3 只，一轮最多 12 只不同宠物。
- 自己的主展示宠物固定第 4 位，即第二屏第 1 位。
- 自己未开启交友时可仅本人可见。
- 对真正可邀请的其他宠物显示“可发送邀请”。
- 自己、私有、未开启或其他不可邀请状态不得错误显示该角标。
- “更多”进入当前门店完整交友列表。

自动轮播精确秒数留到阶段 10。

### 3.6 上门喂养

首页上门喂养区域位于宠物交友之后。

至少展示：

- 公开需求摘要
- 日期 / 时间
- 模糊地点
- 每日预算
- 状态
- “查看更多”
- “发布需求”

公开地址只展示区县 + 小区名称 / 附近区域，不公开门牌号、精确住宅地址、手机号或微信。

需求详情可在符合条件时点击“我要接单”。第一个成功接单者由后端原子锁定，其他人显示“已有人接单 / 等待门店对接”。

发布成功后支持分享到微信聊天 / 群，分享深链进入对应需求详情。

### 3.7 推荐商品

展示 3～6 个当前门店推荐商品，并提供“查看更多”。

商品卡至少展示：

- 图片
- 商品名称
- 售价 / 参考售价
- 有货 / 库存紧张 / 暂时无货

不得出现“立即付款”等线上成交误导。

## 4. 预约页面蓝图

预约页优先采用低步骤连续式交互。

洗护 / 美容：

选择宠物 → 选择服务 → 选择日期 → 选择开放时间段 → 确认预约。

要求：

- 一只宠物时自动预选。
- 已有客户 / 宠物资料自动带出。
- 无宠物时允许轻量添加，保存后返回当前流程。
- 价格只作参考，不出现在线支付。
- 同页提供“我的预约”入口或预约记录区域。
- 提交后明确显示“待门店确认”，不得表现成已经正式预约成功。

寄养预约增加入住 / 离店时间、已有寄养资料确认和本次特殊要求。

## 5. 洗护 / 美容服务结果页蓝图

信息顺序固定为：

1. 服务状态 / 基本信息
2. N 组洗护 / 美容前后对比
3. 本次服务摘要 / 服务记录
4. 结算信息
5. AI 洗护分析
6. 关联订单入口（如需要）

AI 不得放在普通结果 / 前后对比之前。

### 5.1 N 组拖动对比

- 后端返回 N 组完整 before / after，客户端动态生成 N 组。
- 不写死数量。
- 各组独立拖动。
- 可用组标签 / 角度标签切换。
- 缺一侧素材不得伪造成完整对比。

H5 原型可以使用 1 / 2 / 4 / 6 组模拟控制验证动态能力，但该模拟控制不是正式产品按钮。

### 5.2 AI 洗护分析

普通入口按钮：`查看报告`

卡片说明可使用：

> 结合本次洗护前、洗护后照片，生成专业护理观察报告。

同时保留：

> 报告生成期间可停留在本页等待。本报告不作为医疗诊断。

### 5.3 AI 广告弹窗

标题：`查看 AI 洗护报告`

说明：

> 本功能采用国际领先AI助手分析，相关费用已由赞助商赞助，观看完整广告后即可免费查看本次 AI 洗护报告。

只有完整观看 / 获得有效资格后，后端才启动 AI。

### 5.4 AI 生成状态

依次与真实后台任务状态对应：

1. 宠物影像质量检测中
2. 洗护前后特征比对中
3. 毛发与清洁状态分析中
4. 专业护理知识检索中
5. 结果复核与报告生成中

正常目标约 30～60 秒；真实完成立即展示。

约 60 秒仍未完成：

> 报告仍在生成中
>
> 分析已提交，可稍后返回本页面查看结果。

离开页面后后台继续执行，再次进入读取服务端真实状态。

## 6. 寄养加餐蓝图

寄养详情仅在满足条件时显示“投喂零食”：

- 宠物处于有效寄养中；
- 主人允许额外零食；
- 门店存在可投喂商品。

路径：

投喂零食 → 展示可投喂商品 → 选择商品 / 规格 / 数量 → 确认 → 提示“已通知店员”。

提交后：

- 生成统一商品购买需求，不另建投喂订单。
- 未处理完成时显示“投喂请求处理中”。
- 店员完成实际投喂后，寄养时间轴自动新增对应动态。

顺序基线：

1. 头像 / 昵称
2. 脱敏手机号（存在时）
3. 会员资产摘要卡
4. 积分入口 / 积分摘要
5. 我的宠物
6. 我的钱包
7. 我的订单
8. 消息
9. 账号与设置

### 7.1 会员资产摘要卡

固定展示：

- 当前可用余额（主金额）
- 当前可使用优惠券数量
- 本金余额
- 赠送余额

整卡可进入余额明细。

积分不进入这张资金资产卡。

视觉只冻结信息层级，不冻结背景色、渐变、字体、圆角、阴影等。

### 7.2 积分入口

至少展示：

- 当前积分
- 今日签到状态
- 积分商城入口

积分不混入“我的钱包”。

## 8. 积分中心与积分商城蓝图

### 8.1 每日签到

点击签到 → 激励广告 → 完整观看并验证成功 → 签到成功 → 显示今日获得 N 积分（1～10） → 更新本周累计。

若自然周 7 天全部签到，周累计必须严格等于 50。

中途退出 / 广告失败：不签到、不加积分。

### 8.2 积分商城

至少区分：

- 优惠券 / 虚拟权益
- 实物奖励

实物兑换路径：

选择奖励 → 选择领取门店 → 确认扣积分 → 待总仓发货 → 已发往门店 → 门店已收货 / 待自提 → 已领取。

不建设用户收货地址、快递到家、用户运费与用户物流配送页。

### 8.3 积分明细 / 我的兑换

积分明细独立展示积分增减记录。

我的兑换展示：奖励名称、消耗积分、领取 / 使用门店、兑换时间、当前状态。

## 10. 我的宠物 / 钱包 / 订单 / 商品 / 消息

### 10.1 我的宠物

宠物列表至少展示头像、名称、类型 / 品种、性别、年龄、当前体重，并可进入档案 / 添加宠物。

宠物档案承载基本资料、护理档案、寄养资料、服务记录、服务相册和宠物交友设置。

### 10.2 我的钱包

不重复大号余额卡，主要承载：余额明细、我的优惠券、邀请码兑换。无充值入口。

### 10.3 我的订单

顶部只保留：全部 / 服务 / 商品。

服务订单进入同一服务结果页，不创建第二套报告页面。

### 10.4 商品

必须能走通：

首页推荐 → 商品列表 / 搜索 / 分类 → 商品详情 / SKU → 购物车或直接提交 → 提交购买需求 → 商品订单状态。

无在线支付、地址、运费、物流。

### 10.5 消息

单一时间流，代表性消息至少包括：服务完成、预约变化、寄养异常 / 新动态、商品确认 / 取消、钱包 / 优惠券、宠物好友邀请、上门喂养状态、积分实物到店自提等。

## 11. 养宠顾问全局入口蓝图

### 11.1 悬浮按钮

- 初始在左侧安全区域。
- 可自由拖动。
- 松手后自动吸附最近的左 / 右边缘。
- 不遮挡微信系统胶囊、底部导航和固定主要按钮。
- 可记录上次纵向位置。
- 全屏广告 / 沉浸媒体等特殊场景可临时隐藏。

### 11.2 首次进入

悬浮按钮 → “养宠顾问介绍”弹窗 → 关闭 / 开始咨询 → 聊天页。

之后默认直接进入聊天，可从“关于养宠顾问”重新查看介绍。

### 11.3 次数状态

客户端需正确表达：

- 前三次有效提问免费
- 剩余免费 / 已解锁次数
- 用完后需看广告
- 广告成功后增加 3 次额度
- AI 失败不扣次数

前三次免费按 Platform User 账号累计、终身一次，不按日重置。

## 13. 必须覆盖的关键场景

### C-HOME-01：首页普通状态

- 默认首页。
- 当前门店 → 当前服务 → 宠物交友 → 上门喂养 → 推荐商品。

### C-HOME-02：洗护刚完成

- 仍进入首页。
- 显示完成提示。
- 查看 / 稍后。
- 查看结果后完成卡退出当前服务。

### C-BOARDING-01：寄养动态时间轴

- 点击“查看寄养动态”。
- 进入当前宠物时间轴。
- 最新动态在上。
- 按日期分组。
- 支持文本和图片 / 视频动态。
- 至少演示喂食、饮水、玩耍、排泄等多个动作。

### C-BOARDING-02：寄养加餐

- 从寄养详情进入投喂零食。
- 选择可投喂商品。
- 提交后显示已通知店员 / 请求处理中。
- 实际完成后时间轴出现投喂动态。

### C-SOCIAL-01：首页宠物交友

- 每屏 3 只，最多 12 只。
- 自动轮播 + 手动滑动。
- 可邀请卡显示“可发送邀请”。

### C-SOCIAL-02：自己的宠物第 4 位

- 第二屏第 1 位为自己的主宠物。
- 私有状态不显示“可发送邀请”。

### C-FEED-01：上门喂养发布 / 分享

- 填写时间、模糊地点、每日预算、要求。
- 发布。
- 分享深链。

### C-FEED-02：公开隐私 / 接单

- 不展示精确住宅地址和联系方式。
- 第一位接单者成功锁定。
- 之后显示等待门店对接。

### C-RESULT-01：N 组前后对比

- 多组切换。
- 每组独立拖动。
- 组数动态变化。

### C-AI-01：AI 未解锁

- 普通结果可看。
- 点击查看报告才出现广告说明。

### C-AI-02：广告完成后生成

- 完整广告后进入真实生成阶段。
- 5 阶段进度。
- 完成后展示报告。

### C-AI-03：约 60 秒未完成

- 显示仍在生成。
- 可以离开。
- 返回读取真实状态。

### C-WALLET-01：资产摘要

- 总余额、优惠券数量、本金、赠送。
- 整卡进入余额明细。
- 无充值。

### C-POINTS-01：每日签到

- 完整广告后随机 1～10 分。
- 同日不可重复签到。

### C-POINTS-02：完整周 50 分

- 周一至周日 7 次都在 1～10。
- 总计严格 50。

### C-POINTS-03：积分实物自提

- 选择领取门店。
- 待总仓发货 → 已发往门店 → 待自提 → 已领取。

### C-ADVISOR-01：悬浮入口

- 拖动。
- 自动吸附最近左右边缘。

### C-ADVISOR-02：前三次免费 / 广告解锁

- 前 3 次有效回答免费。
- 第 4 次前看广告。
- 成功后增加 3 次额度。

### C-ADVISOR-03：AI 失败不扣额度

- 模拟失败后剩余额度不变。

### C-PRODUCT-01：商品购买需求

- 商品列表 / 详情 / SKU / 购物车。
- 提交后“门店确认中”。
- 无在线付款。

### C-IDENTITY-01：按需身份验证

- 公开内容可先浏览。
- 首次进入个人业务时才触发必要身份验证。

### 2026-09-06：首页宠物交友 / 上门喂养顺序调整

【需求变更】

- 原规则：新增上门喂养后曾确定为“当前服务 → 上门喂养 → 宠物交友 → 推荐商品”。
- 新规则：首页最终调整为“当前服务 → 宠物交友 → 上门喂养 → 推荐商品”。
- 影响范围：首页、H5 / UI、客户端总纲、上门喂养文档和产品蓝图。

### 2026-09-06：寄养动态时间轴

【需求变更】

- 原规则：寄养详情已有动态与媒体概念，但时间轴浏览方式未完整冻结。
- 新规则：点击“查看寄养动态”进入当前宠物寄养详情，以真实发生时间倒序展示最新动作，按日期分组；图片 / 视频与对应动作挂在同一时间点；实际发生时间与系统录入时间分离。
- 影响范围：首页寄养卡、寄养详情、店员端寄养动态录入、API、数据库、H5 / UI 与验收。
