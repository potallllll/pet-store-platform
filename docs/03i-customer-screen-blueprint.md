# 03I 客户端「页面蓝图与关键交互验收场景」

> 状态：已确认子模块
> 所属阶段：03 客户端微信小程序
> 版本：V1.0

## 1. 文档职责

本文件用于解决“业务规则已经明确，但新人 / AI 仍可能自行决定页面结构”的问题。

本文件正式冻结：

- 客户端页面地图
- 一级 / 二级页面入口关系
- 核心页面的信息排列顺序
- 关键页面默认状态
- 必须覆盖的关键交互场景
- 原型 / H5 预览最小验收范围

本文件**不负责**最终视觉设计，不提前冻结：

- 品牌色
- 字体
- 字号体系
- 圆角
- 阴影
- 图标风格
- 动效曲线
- 精确轮播秒数
- 栅格 / 间距 Token

以上视觉参数在阶段 10 UI / Design System 中确定。

如果本文件与 `03a`～`03h` 的具体业务规则发生冲突，以对应业务子模块为准；本文件负责把已经确认的业务规则映射到页面和交互，不得绕过隐私、多商户、财务、权限和审计规则。

## 2. 客户端总页面地图

V1.0 客户端页面层级至少覆盖以下结构：

```text
底部导航
├─ 预约
│  ├─ 预约填写 / 快速预约
│  └─ 我的预约 / 预约详情
│
├─ 首页
│  ├─ 当前服务
│  │  ├─ 洗护 / 美容服务结果
│  │  └─ 寄养详情 / 寄养时间轴
│  ├─ 宠物交友
│  │  ├─ 宠物交友更多列表
│  │  └─ 宠物交友详情 / 邀请
│  └─ 推荐商品
│     ├─ 商品列表
│     ├─ 商品详情 / SKU
│     └─ 购物车 / 提交购买需求
│
└─ 我的
   ├─ 我的宠物
   │  └─ 宠物档案
   │     ├─ 基本资料
   │     ├─ 护理档案
   │     ├─ 寄养资料
   │     ├─ 服务记录
   │     ├─ 服务相册
   │     └─ 宠物交友设置
   ├─ 我的钱包
   │  ├─ 余额明细
   │  ├─ 我的优惠券
   │  └─ 邀请码兑换
   ├─ 我的订单
   │  ├─ 服务订单详情
   │  └─ 商品订单详情
   ├─ 消息
   │  └─ 关联业务详情
   └─ 账号与设置
      ├─ 已验证手机号 / 更换手机号
      ├─ 隐私相关入口
      ├─ 账号注销
      └─ 退出登录
```

预约与正式订单仍严格分离；商品购买需求不等同于线上付款；客户端不新增充值、积分、在线支付页面。

## 3. 底部导航与默认入口

底部一级导航顺序固定：

1. 预约
2. 首页
3. 我的

正常直接打开小程序时默认进入“首页”。

任何原型 / H5 / UI 骨架不得把服务、商品、宠物、消息等新增为底部一级 Tab。

## 4. 首页蓝图

首页信息顺序固定为：

1. 当前门店
2. 当前服务
3. 宠物交友
4. 推荐商品

### 4.1 当前门店

顶部只突出：

- 当前门店名称
- 必要时的切换门店入口

不额外展示“当前门店”“已绑定客户”等重复辅助标签。

### 4.2 当前服务

当前服务为首页最高业务优先级区域。

- 进行中 / 刚完成的服务优先展示。
- 首页最多直接显示 3 条当前服务，更多进入完整列表。
- 洗护 / 美容只显示客户简化状态，不暴露店员内部细分步骤。
- 寄养卡展示日期范围、当前第几天、今日动态数量、最近动态以及新媒体提示。
- 无当前服务时使用轻量预约引导。

### 4.3 服务刚完成的首页状态

洗护 / 美容服务首次完成时：

- 客户直接打开小程序仍默认进入首页，而不是直接跳到孤立结果页。
- 首页出现完成提示，明确本次服务结果已经可查看。
- 提供“查看本次服务结果”和“稍后查看”。
- 客户选择稍后查看时，首页保留该完成服务卡。
- 客户真正打开并查看过本次服务结果后，该完成服务退出首页“当前服务”区域，之后通过订单 / 宠物服务记录等历史入口查看。

### 4.4 宠物交友

首页宠物交友区域：

- 默认自动横向轮播。
- 同时允许客户手动横向滑动。
- 用户主动滑动时优先响应手势，自动轮播暂时让位；交互结束后再恢复自动轮播。
- 每屏同时显示 3 只宠物。
- 一轮最多 12 只不同宠物，不重复凑数。
- 当前客户自己的主展示宠物固定为本轮第 4 个位置，即第二屏第 1 个位置。
- 自己的宠物未开启交友时可仅本人可见，并明确标识；不得因此对其他客户公开。
- 提供“更多”进入完整交友列表。

具体自动轮播间隔和动画参数阶段 10 确定；原型可使用约 4～5 秒 / 屏作为演示值，但该秒数不是当前正式业务常量。

### 4.5 推荐商品

首页展示当前门店 3～6 个推荐商品，并提供“查看更多”。

推荐商品卡片至少能表达：

- 图片
- 商品名称
- 售价 / 参考售价
- 有货 / 库存紧张 / 暂时无货

不得使用“立即付款”等会让客户误认为支持线上成交的文案。

## 5. 预约页面蓝图

预约页优先采用低步骤的一屏式 / 连续式交互，不因为模块结构而机械拆成多层页面。

洗护 / 美容正常路径：

选择宠物
→ 选择服务
→ 选择日期
→ 选择门店开放时间段
→ 确认预约

设计要求：

- 只有一只宠物时自动预选。
- 已有客户 / 宠物资料自动带出。
- 无宠物时允许在当前流程中轻量添加，保存后自动返回。
- 价格只作为参考价，不出现在线支付动作。
- 页面应同时提供“我的预约”入口或下方预约记录区域，避免客户无法回看已提交预约。
- 客户提交后明确显示“待门店确认”，不得表现成已经预约成功。

寄养预约沿用同样的连续式原则，加入入住 / 离店时间、已有寄养资料确认和本次特殊要求。

## 6. 洗护 / 美容服务结果页蓝图

服务结果页的信息顺序原则上固定为：

1. 本次服务状态 / 基本信息
2. N 组洗护 / 美容前后对比
3. 本次服务摘要 / 服务记录
4. 结算信息
5. AI 洗护分析
6. 关联订单入口（如页面需要）

不得把 AI 报告置于普通前后对比之前，导致客户必须先经过广告才能查看普通服务结果。

### 6.1 N 组拖动对比

- 店员上传 N 组完整“服务前 + 服务后”，客户端动态生成 N 组独立拖动对比。
- 不允许写死 1 组、4 组或其他固定数量。
- 页面允许通过组标签 / 角度标签切换，例如正面、背面、左侧、右侧、头部、四肢。
- 每组对比独立保持 before / after 对应关系。
- 缺一侧素材的组不得伪造可拖动完整对比。

H5 原型至少需要演示多组切换；可以使用 1 / 2 / 4 / 6 组模拟控制帮助验收动态能力，但模拟控制仅属于原型辅助，不是正式客户端业务按钮。

### 6.2 AI 洗护分析

普通页面按钮统一显示：

> 查看报告

AI 卡片可显示：

> 结合本次洗护前、洗护后照片，生成专业护理观察报告。

并保留：

> 报告生成期间可停留在本页等待。本报告不作为医疗诊断。

不得在顾客页面展示“服务完成后不会提前调用 AI”“完整观看后才开始 AI 分析”等内部技术说明。

### 6.3 AI 广告弹窗

标题：

> 查看 AI 洗护报告

说明：

> 本功能采用国际领先AI助手分析，相关费用已由赞助商赞助，观看完整广告后即可免费查看本次 AI 洗护报告。

只有完成有效广告观看 / 获得有效免广告查看资格后，后端才提交图片并启动 AI。

### 6.4 AI 生成中

依次使用与真实任务状态对应的顾客文案：

1. 宠物影像质量检测中
2. 洗护前后特征比对中
3. 毛发与清洁状态分析中
4. 专业护理知识检索中
5. 结果复核与报告生成中

正常体验目标约 30～60 秒；真实结果提前完成立即展示，不故意拖延。

约 60 秒仍未完成时改为：

> 报告仍在生成中
>
> 分析已提交，可稍后返回本页面查看结果。

客户退出后任务继续；再次进入读取服务端真实状态。

## 7. 我的页面蓝图

“我的”页面用于汇总客户身份入口和高频个人业务。

推荐并作为 V1.0 页面基线的顺序：

1. 客户头像 / 昵称或可识别展示名
2. 已验证手机号的脱敏展示（存在时）
3. 当前门店当前可用余额
4. 余额明细轻量快捷入口
5. 我的宠物
6. 我的钱包
7. 我的订单
8. 消息
9. 账号与设置

要求：

- 当前可用余额必须在“我的”页直接可见。
- “我的钱包”不再重复放一个大号余额卡。
- 客户端不得出现“充值”入口。
- 不显示积分入口。
- 消息可显示未读数量。

头像、昵称、脱敏手机号属于页面身份信息；真实数据仍受登录、手机号验证和隐私规则控制。

---

## 8. 我的钱包页面蓝图

钱包页不重复展示大号余额卡，主要承载：

- 余额明细
- 我的优惠券
- 邀请码兑换

客户端只查看资产，不允许发起充值或直接决定余额扣款。

---

## 9. 我的宠物页面蓝图

宠物列表至少展示：

- 头像
- 名称
- 类型 / 品种
- 性别
- 年龄
- 当前体重
- 查看档案
- 添加宠物

宠物档案按已确认结构承载：基本资料、护理档案、寄养资料、服务记录、服务相册、宠物交友设置。

服务相册与服务结果共享同一底层服务照片，不复制独立业务数据。

---

## 10. 我的订单页面蓝图

入口：我的 → 我的订单。

顶部只保留：

- 全部
- 服务
- 商品

服务订单卡至少显示时间、宠物、服务、客户状态、实付金额（已结算时）及详情 / 服务结果入口。

商品订单卡至少显示时间、商品摘要、件数、客户状态、实付金额（已结算时）和详情入口。

洗护 / 美容订单的“查看服务结果”必须复用首页当前服务进入的同一服务结果页。

---

## 11. 商品页面蓝图

必须能形成完整轻商城链路，而不能只画商品列表：

首页推荐商品
→ 商品列表 / 搜索 / 分类
→ 商品详情
→ SKU / 数量选择
→ 加入购物车或直接提交购买需求
→ 提交购买需求
→ 我的订单显示门店确认中

正式 H5 预览应至少能走通：商品列表 → 商品详情 → 购物车 / 提交需求 → 商品订单状态。

客户端不存在在线支付、地址、物流、运费页面。

---

## 12. 消息页面蓝图

入口：我的 → 消息。

使用单一时间流，不做复杂多 Tab。

H5 / 原型至少应演示下列代表性消息：

- 服务完成
- 预约状态变化
- 寄养业务 / 异常或新动态
- 商品确认 / 取消
- 钱包 / 优惠券资产变化
- 宠物好友邀请

消息点击尽量直接进入关联业务详情。

宠物好友邀请应演示“同意 / 不同意”；同意后进入“已告知店员，请等待店员回复”的状态链路。

---

## 13. 账号与身份相关页面

“我的 → 账号与设置”至少覆盖：

- 当前已验证手机号
- 更换手机号
- 隐私相关入口
- 账号注销
- 退出登录

公开浏览不强制登录；首次进入预约、宠物、钱包、订单、消息、购买需求、宠物交友等个人业务时再触发身份 / 手机号验证。

原型如果模拟登录拦截，应展示“按需触发”，不能做成打开小程序即登录墙。

## 14. 必须覆盖的关键场景

### C-HOME-01：普通直接打开

- 默认首页。
- 显示当前门店。
- 首页信息顺序为当前服务 → 宠物交友 → 推荐商品。

### C-HOME-02：洗护刚完成

前置：某洗护服务刚进入完成状态，客户尚未查看本次服务结果。

必须表现：

1. 客户打开小程序仍进入首页。
2. 出现服务完成提示。
3. 提供“查看本次服务结果”和“稍后查看”。
4. 选择稍后查看后仍能在首页当前服务看到完成卡。
5. 查看本次服务结果后，回到首页，该服务不再占据“当前服务”区域。

### C-SOCIAL-01：首页宠物交友

- 每屏 3 只。
- 最多 12 只不同宠物。
- 自动轮播。
- 支持手动横向滑动。
- 用户手动操作后再恢复自动轮播。

### C-SOCIAL-02：自己的宠物第 4 位

- 第二屏第 1 位为自己的主展示宠物。
- 未开启交友时显示“未开启交友 / 仅自己可见”。
- 不得因此对其他客户公开。

### C-RESULT-01：N 组前后对比

- 模拟至少 4 组完整对比。
- 可在不同对比组之间切换。
- 每组可独立拖动 before / after。
- 组数变化时 UI 按 N 动态变化。

### C-AI-01：未获得查看资格

- 普通服务结果和 N 组对比可正常查看。
- 点击“查看报告”才出现广告说明。

### C-AI-02：广告完成后生成

- 完整观看成功后才进入 AI 分析状态。
- 显示 5 段专业分析进度。
- 真实完成后直接展示报告。

### C-AI-03：超过约 60 秒

- 不无限强制客户停留。
- 显示“报告仍在生成中”。
- 客户可离开。
- 再次进入读取真实状态。

### C-WALLET-01：我的与钱包

- 我的页面直接显示余额。
- 钱包页面不重复大余额卡。
- 钱包包含余额明细、优惠券、邀请码兑换。
- 无充值、无积分。

### C-PRODUCT-01：商品购买需求

- 商品列表 / 搜索。
- 商品详情 / SKU。
- 购物车或直接提交。
- 提交后状态“门店确认中”。
- 无在线付款。

### C-ORDER-01：服务订单复用

- 洗护 / 美容订单能进入同一服务结果页。
- 不建立独立报告列表或第二套服务结果数据。

### C-IDENTITY-01：按需身份验证

- 未绑定客户可浏览公开首页 / 商品。
- 第一次访问个人业务时才触发必要微信身份 / 手机号验证。

## 15. H5 / UI 原型验收矩阵

生成“客户端完整 H5 预览”时，至少覆盖：

| ID | 页面 / 场景 | 必须展示 | 必须可交互 |
|---|---|---|---|
| C-HOME-01 | 首页普通状态 | 门店、当前服务、交友、推荐商品 | 首页主要入口 |
| C-HOME-02 | 洗护刚完成 | 完成提示、完成服务卡 | 查看 / 稍后、查看后移出当前服务 |
| C-SOCIAL-01 | 宠物交友 | 3 只 / 屏、最多 12 只 | 自动轮播 + 手动滑动 |
| C-SOCIAL-02 | 自己宠物 | 第 4 位、仅本人可见状态 | 开启交友引导 |
| C-APPT-01 | 预约 | 宠物、服务、日期、时段 | 完成一次预约提交 |
| C-RESULT-01 | 服务结果 | N 组前后对比 | 切组 + 拖动 |
| C-AI-01 | AI 未解锁 | 查看报告、广告说明 | 完整观看 / 中途退出模拟 |
| C-AI-02 | AI 生成中 | 5 阶段状态 | 等待 / 离开 |
| C-AI-03 | AI 超时 | 仍在生成提示 | 返回后继续查询状态 |
| C-PET-01 | 我的宠物 | 宠物列表、档案结构 | 进入档案 / 添加宠物 |
| C-WALLET-01 | 我的 / 钱包 | 首页余额、余额明细、券、邀请码 | 查看明细 / 兑换入口 |
| C-ORDER-01 | 我的订单 | 全部 / 服务 / 商品 | 服务订单进入同一结果页 |
| C-PRODUCT-01 | 商品 | 列表、详情、SKU、购物车 | 提交购买需求 |
| C-MSG-01 | 消息 | 关键业务消息 | 深链 / 好友邀请同意不同意 |
| C-SETTING-01 | 账号设置 | 手机号、隐私、注销、退出 | 对应入口 |

原型中的假数据、模拟按钮和模拟 AI 仅用于展示交互；正式开发阶段不得用 Mock / 假状态冒充真实业务实现。

## 16. 新人 / AI 生成客户端预览的强制读取规则

当任务为以下任一内容时：

- 客户端 H5 预览
- 客户端页面 Demo
- 客户端 UI 骨架
- 客户端交互原型
- 从需求文档生成页面

执行者必须至少读取：

1. `AGENTS.md`
2. `docs/README.md`
