## 1. 文档职责

本文件是客户端当前**主产品页面蓝图**，用于冻结：

- 客户端启动与页面地图
- 一级 / 二级入口关系
- 首页与“我的”等核心页面的信息顺序
- 关键页面默认状态
- 关键交互路径
- H5 / UI 原型最小验收范围

原 `03n` 已归档；其现行内容由本文件与 `03e`、`03j`、`03k`、`03l`、`03m` 承接。`03o` / `03p` 分别负责首页底部 Banner 广告与启动封面广告。归档文件不得作为实现依据，详细业务子模块不得与本文件当前总蓝图冲突。

本文件**不冻结最终视觉参数**，包括：品牌色、背景色、字体、字号、圆角、阴影、图标、渐变、精确动效曲线、精确轮播秒数、栅格 / 间距 Token。已确认视觉与首页规格见阶段 10 的 `10a` / `10b` / `10c`。

## 3. 首页蓝图

首页业务信息顺序固定为：

1. 当前门店
2. 当前服务
3. 消费争议 / 风险反馈
4. 上门喂养
5. 推荐商品

UI 层可在顶部门店栏下使用品牌 / 生活方式 Banner；精选商品后、底部导航前存在 `home_bottom_banner` 微信广告位。它们不改变上述业务优先级。

### 3.1 当前门店

顶部只突出：

- 当前门店名称
- 必要时的切换门店入口
- 右侧消息入口

不额外显示“当前门店”“已绑定客户”等重复辅助标签；首页顶部不同时堆叠搜索、扫码等入口。

门店资料发生修改时，客户端现行展示位置按字段可见范围读取04§3.0.6规定的当前有效资料版本；待审修改不替换门店名称等已展示内容，平台批准并生效后再更新。门头照片不自动映射为品牌Banner／门店头像。营业执照不向顾客公开：顾客页面及接口不展示或返回原件、脱敏副本、缩略图或可访问材料的引用／链接，审核通过也不例外。本规则不增加新的门店详情页或公开证照入口。

### 3.2 当前服务

当前服务为首页最高优先级区域。有进行中服务时，按 10b 紧凑品牌 Banner 变体，在 10b 约定的最小支持屏幕、100% 系统字号下首屏露出第一条服务状态及主操作；150% / 200% 字号允许自然纵向滚动且内容与操作完整可达，不为凑首屏截断。不得仅以参考卡片高度判定通过。

- 首页最多直接显示 3 条进行中 / 刚完成服务。
- 更多服务进入完整列表。
- 洗护 / 美容只显示客户简化状态。
- 寄养卡展示日期范围、当前第几天、今日动态数量、最近动态、新图片 / 视频提示。
- 寄养卡必须提供“查看寄养动态”入口。
- 无当前服务时使用轻量预约引导。

### 3.3 洗护 / 美容刚完成

- 普通启动且无分享、通知、扫码或后台恢复目标时，客户完成启动广告流程后进入最近有效门店首页；存在明确目标时按 `03p` 恢复该目标，不因本场景改写为首页。
- 显示服务完成提示。
- 提供“查看本次服务结果”和“稍后查看”。
- “稍后查看”后完成卡继续保留。
- 真正查看过结果后，该完成服务退出首页当前服务区域。

### 3.4 寄养动态时间轴

点击“查看寄养动态”后进入当前宠物寄养详情。

页面顶部先展示：

- 宠物
- 寄养日期范围
- 当前第几天
- 当前状态
- 今日更新数量

之后展示**按真实发生时间倒序排列的时间轴**：

> 最新动态在上 → 更早动态向下

要求：

- 按日期分组，如今天 / 昨天 / 具体日期。
- 最新一条可使用“最新”等轻量状态提示。
- 每条至少表达时间、动作类型和说明。
- 图片 / 视频动态允许在对应时间点直接展示媒体缩略图 / 预览入口。
- 动态类型至少覆盖喂食、饮水、排泄、遛宠、玩耍、休息、清洁、特殊照护（含代喂药）、照片 / 视频、寄养加餐、异常和自定义事件。
- 客户端排序使用业务记录的 `occurred_at` / 实际发生时间，不使用录入时间替代。
- 店员补录历史事件时，应插回真实发生时间位置，而不是简单显示为最新录入。

寄养详情下方在符合条件时提供“投喂零食”。

04§5.4健康／特殊照护范围：疫苗资料／照片选填，缺材料不自动拒绝或默认已完成疫苗，原必需入住检查保留；代喂药只在特殊照护中记录主人要求、门店是否接收及真实执行，实际内容／时间／执行人与录入事实分离，系统／AI不生成修改方案。异常记录观察与已采取处理、主人联系状态／结果，不因未联系上默认同意或因消息关闭。顾客仅查看本人有权查看的真实记录，内部沟通不公开；异常提前接走沿实际离店停计，不自动免单／退款，不新增医疗处置规则。

入住与日常照护按04§5.1已确认16项：实际到店、检查与资料核对后门店明确确认才进入有效寄养，预约到点不自动入住；同宠在住防重，多宠独立boarding_id／位置／入住与预计离店。预计离店到点只提醒、不自动结束／续住／加费，计费按04§5.2北京时间03:00截点，实际入住<截点≤实际离店每个计一天；0晚不收寄养费、实际离店结算，延期／提前离店按实际重算。不按24小时／预计天数，不把“当前第几天”当计费天数或把账本补录时间当离店，0晚不自动免单／结束；本店员工入住时逐宠设置本次日价，同店同客多宠可一起结算；每宠明细展示自己的日价／实际晚数／基础金额，再汇总，不混用价格、时间或状态。日价更正／免费按04§5.2第14～18项：离店确认前可留痕更正整次日价，不分段，门店涨价不自动改本次；日价大于0，免费须最终调0并明确免单。已离店未付只调最终应收、保留原基础费用及时间；已收款／免单不直接改账。挂单查询／人工联系及撤销按04§4.6，撤销仍待结算、不恢复在住；特殊交接等剩余范围仍待DEC-STAFF-05／06。

分批接走按04§5.2各批分别结算，同批离店多宠仍可一起结算；客户端保留逐宠真实时间／费用及本批结算结果，余下宠物仍显示在住、未结算和本人可见动态，不用顾客级统一已付／完成覆盖。

寄养结算页的“确认本次应收”承载离店动作，不再另加确认离店／接走／顾客签字。本人顾客可看到已离店但尚未结算的真实状态／金额，不能因未付款继续展示寄养中或累加天数；挂单原因／催款备注内部可见。实际离店默认当前服务端时间，可填不早于入住、不晚于当前的真实过去时间；随带物品只展示交还提醒，不强制上传／逐件勾选。后续补收款或明确免单更新原本批财务，不改每宠实际离店或影响其余在住宠物。

统一照护表单固定逐宠单选喂食／遛狗／清扫笼子 → 选择实际发生时间 → 上传照片（选填）→ 确认保存；不是三个独立表单，不做批量完成、不设每日媒体配额。一个确认只产生一笔真实记录，实际时间和录入时间分开，重试不重复；普通喂食不能推进商品加餐状态或重复其已生成动态。

顾客仅查看本人有权读取的customer_visible动态，store_internal不进入时间轴、今日数量、最近动态、缩略图或消息；关闭notify_customer不会把原本可见动态隐藏。异常由员工实际处理、填写结果并明确关闭，已读／发送成功不代表已处理。临时寄养资料只影响本次，当前加餐读取当期有效授权及限制，未核实或矛盾不能凭长期旧值默认允许。

### 3.5 消费争议 / 风险反馈

原“宠物交友”首页模块已退役，不再作为当前实现范围。

首页该位置改为消费争议入口，至少可进入：

- 附近门店；
- 宠物食品。

首页只承担风险摘要与入口，不在卡片层直接把未经平台裁决的投诉写成成立事实。

门店 / 食品详情至少区分：

- 用户反馈；
- 商家回应状态；
- 平台核验状态；
- 是否已解决。

投诉基础内容审核通过后立即公开为“用户反馈 · 待商家回应 / 尚未核验”。

商家回应期限 7 天；逾期显示“商家逾期未回应”，但不自动成立。商家正式回应后双方进入 3 天补证期，随后由 1 名有 `complaint_review.decide` 权限的平台审核员裁决。

所有公开投诉长期保留；未解决整体靠前，已解决整体靠后，各组内部按时间倒序。

同一食品同一批次在最近 2 天内达到至少 3 条独立投诉时显示“出现集中反馈”。3 条为硬门槛；跨不同门店来源只提高风险优先级 / 排序，不得把 2 条折算为 3 条。提示保留 2 个月。

宠物档案可记录当前食用品牌；匹配该标准品牌的新食品投诉通过基础审核并公开后生成站内风险提醒。同一用户同一投诉只提醒一次。食品投诉列表 / 详情必须展示服务端返回的“问题热度”；具体算法受 `DEC-FOOD-HEAT-01` 阻塞。

最终卡片布局、附近距离表达、筛选与详情视觉仍受 `DEC-RISK-UI-01` 阻塞。

### 3.6 上门喂养

首页区域在消费争议之后。只推荐有效待接单、未到首次上门截止的真实需求，展示宠物摘要、时间、模糊地点、预算、待接单状态及发布／查看更多；本地无结果可补其他城市同样有效需求，城市如实显示，全平台无结果显示空态。

保留用户自主接单；需求方只有发布／撤销，当前门店只有确认／撤销。状态为待接单、待门店确认、已确认、已撤销／已过期。门店确认后仅当前店可以看双方必要联系方式，需求方／接单用户不互看，公开列表、详情、消息／分享均不放出双方私密资料。线下协商修改不在APP操作，服务进度与完成不跟踪，详见03j。

### 3.7 推荐商品

展示 3～6 个当前门店推荐商品，并提供“查看更多”。

商品卡至少展示：

- 图片
- 商品名称
- 售价 / 参考售价
- 有货 / 库存紧张 / 暂时无货

不得出现“立即付款”等线上成交误导。

### 3.8 首页底部微信 Banner 广告

精选商品后、底部导航前提供 `home_bottom_banner`。

- 仅用于微信广告曝光 / 点击变现。
- 不属于激励广告，不发积分、不授予 AI 权益。
- 广告失败、无填充或关闭时自动收起。
- 广告故障不得影响首页其他模块。
- 养宠顾问在有资格显示时不得覆盖广告主要点击区域。

详细规则见 `03o-customer-home-banner-ad.md`。

## 4. 预约页面蓝图

预约页优先采用低步骤连续式交互。

洗护 / 美容：

选择宠物 → 选择服务 → 选择日期及期望到店时间 → 提交申请 → 等待门店人工确认。

要求：

- 一只宠物时自动预选。
- 已有客户 / 宠物资料自动带出。
- 无宠物时允许轻量添加，保存后返回当前流程。

生成客户端 H5 / Demo / UI 骨架 / 原型 / 正式页面前，必须使用 `docs/README.md` 第 3 节的唯一读取矩阵：完整客户端或跨模块任务读取全量清单；明确的单模块任务读取基础文件、`03i`、相关子模块及适用 UI 规格。存在跨模块依赖或无法判断范围时使用全量清单；原 `03n` 已归档，不读取。

本文件负责当前统一页面 / 启动蓝图；详细子模块负责对应业务细节。若出现无法同时满足的明确冲突，必须停止并提出冲突，不得自行选择。

## 17. 与阶段 10 UI / Design System 的边界

阶段 10 可以调整：

- 页面 / 卡片背景色
- 品牌色
- 卡片样式
- 间距
- 字体层级
- 图标
- 渐变 / 高光
- 动画速度
- 空状态插画

但不得无需求变更地修改：

- 底部导航
- 首页核心业务顺序
- 启动封面广告存在及其三种来源模式
- 首页底部 Banner 广告存在与曝光属性
- 寄养动态时间轴能力
- 消费争议 / 风险反馈入口、投诉状态及食品问题热度语义；具体布局受DEC-RISK-UI-01阻塞，热度算法受DEC-FOOD-HEAT-01阻塞
- 上门喂养入口、状态与隐私边界
- “我的”资产卡信息组成
- 平台积分独立入口
- N 组对比能力
- AI 报告授权 / 生成链路
- 养宠顾问付费门店资格、悬浮 / 吸附和用户次数规则
- 关键验收场景
