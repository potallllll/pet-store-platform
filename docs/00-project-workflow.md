# 项目需求与 Codex 开发总流程

## 总原则

项目采用“需求先冻结、开发后执行”的方式：

需求讨论 → 角色与业务设计 → 多端功能设计 → 业务规则 → 权限 → 数据库 → UI → 技术架构 → 测试验收 → V1.0 冻结 → Codex Master Prompt → Codex 开发 → 审查整改 → 最终验收。

## 正式需求管理

聊天中的内容属于讨论草稿；只有经过确认的内容才进入正式规格。

每项需求使用以下状态：

- 讨论中
- 待确认
- 已确认
- 以后版本

已确认需求若发生修改，必须记录原规则、修改后规则和受影响模块。

## 需求设计阶段

1. 项目定位
2. 用户角色与账号体系
3. 客户端小程序
4. 店长 / 员工端小程序
5. Web 管理后台
6. 核心业务规则
7. 完整业务流程
8. 权限体系
9. 数据库设计
10. UI / Design System
11. 技术架构
12. 测试与验收

## V1.0 冻结

所有需求最终分为：

- V1.0 必须实现
- V1.1 预留
- V2.0 未来功能

V1.0 冻结后原则上不继续新增功能。

## Codex 阶段

冻结后生成完整 `Codex Master Prompt`，要求 Codex 自主按合理工程顺序执行项目初始化、数据库、后端、权限、业务模块、客户端、店长端、Web 后台、第三方能力、测试、Build、修复、README 和部署文档。

Codex 不得自行删减需求、用 Mock/TODO 冒充正式实现、绕过权限或数据校验、因报错而注释功能。

## 验收

Codex 第一轮完成后，对架构、业务、数据库、权限、安全、遗漏功能和测试结果进行审查，形成整改清单并再次修复，直到符合 V1.0 验收标准。
