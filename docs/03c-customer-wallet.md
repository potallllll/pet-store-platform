# 03C 客户端「我的钱包」模块

> 状态：已确认子模块
> 所属阶段：03 客户端微信小程序
> 版本：V1.0

## 1. 客户端定位

客户端不提供充值入口，也不允许客户发起充值申请或自行完成余额支付。

“我的”页面直接展示当前商户下的当前可用余额，客户无需先进入钱包页面即可看到余额。

“我的钱包”用于查看和使用当前商户下的其他会员资产与明细，包括：

- 余额明细
- 优惠券
- 邀请码兑换

“我的钱包”页面不重复展示大号当前可用余额卡片，避免与“我的”页面重复占用空间。

V1.0 不设计积分机制，不展示积分入口，不建立积分获取、抵现、过期或积分流水体系。

不同商户之间的会员余额、优惠券及相关会员权益严格隔离。

## 2. 充值由门店侧发起

会员充值完全由门店侧处理。

基本流程：

店员选择客户
→ 选择老板预先配置的充值套餐
→ 客户线下付款
→ 店员选择实际支付方式
→ 店员确认已收款
→ 系统生成充值流水
→ 增加会员余额
→ 自动发放套餐中配置的赠送余额 / 优惠券

客户无需先在小程序进行任何充值操作。

## 3. 老板配置充值套餐

商户老板可自行维护充值套餐，例如：

- 实收 300 元，赠送 30 元，到账 330 元
- 实收 500 元，赠送 60 元，并赠送洗护优惠券 1 张
- 实收 1000 元，赠送 150 元，并赠送指定优惠券

每个套餐支持：

- 套餐名称
- 实际收款金额
- 赠送余额
- 实际到账总额
- 赠送优惠券及数量
- 启用 / 停用
- 生效时间 / 失效时间（可选）
- 备注

V1.0 不引入复杂营销条件引擎。

## 4. 充值赠送权益

充值套餐可配置：

- 赠送余额
- 赠送优惠券

充值成功后系统自动发放套餐中已配置的赠送权益，店员不需要再次手动增加赠送余额或逐张发券。

## 5. 本金与赠送余额

后台必须区分：

- 充值本金余额
- 赠送余额
- 客户端显示的总可用余额

客户端通常只显示总可用余额，不增加客户理解成本；该总可用余额直接展示在“我的”页面。

具体扣款顺序、退款时本金与赠送余额如何处理，在核心业务规则阶段最终确认。

## 6. 余额支付

客户不能在客户端自行发起余额扣款。

门店收银时，由有权限的店员选择会员余额作为支付方式，并由系统完成余额校验和扣减。

余额不足时支持组合支付，由系统自动计算剩余应收金额，避免店员手工计算。

例如：订单应收 200 元，会员余额 80 元，可自动形成：会员余额 80 元 + 微信 / 支付宝 / 现金等 120 元。

## 7. 余额流水与审计

任何余额变化都必须形成不可删除的独立流水，不允许直接覆盖余额数字。

流水类型至少包括 / 预留：

- 充值
- 赠送
- 消费
- 退款
- 人工增加
- 人工扣减
- 冲正
- 历史初始化

每条关键流水至少记录：

- 客户
- 商户
- 操作时间
- 变动前余额
- 变动金额
- 变动后余额
- 本金 / 赠送部分变化
- 关联订单或充值单
- 支付方式（如适用）
- 操作员工
- 原因 / 备注

错误操作通过冲正处理，不删除或直接修改历史流水。

## 8. 优惠券类型

V1.0 只保留三类优惠券：

1. 满减券：例如满 100 减 20。
2. 无门槛 / 指定范围金额券：例如洗护抵扣 20 元。
3. 折扣券：例如美容 9 折，可配置最高优惠金额。

老板创建优惠券时至少配置：

- 优惠券名称
- 优惠券类型
- 优惠金额 / 折扣比例
- 使用门槛（如适用）
- 最高优惠金额（折扣券适用）
- 适用范围
- 有效期
- 启用 / 停用
- 备注（可选）

适用范围 V1.0 支持：

- 全部消费
- 洗护
- 美容
- 寄养
- 商品

V1.0 不要求老板维护复杂多层营销条件。

## 9. 优惠券发放方式

V1.0 只支持以下三种来源：

### 9.1 充值套餐自动赠送

老板在充值套餐中预先绑定优惠券。充值完成后系统自动发放，不增加店员操作。

### 9.2 老板 / 有权限员工手动赠送

老板可选择客户并直接赠送已配置的优惠券。

普通店员是否允许赠券由权限体系控制；默认不开放随意赠券权限。

### 9.3 邀请码兑换

V1.0 不做“系统活动自动赠送优惠券”，改为邀请码兑换。

老板可创建邀请码并绑定一张或多张已配置优惠券。邀请码至少支持：

- 邀请码内容（系统生成或老板指定）
- 绑定优惠券及数量
- 启用 / 停用
- 生效时间 / 失效时间
- 总兑换次数上限（可选）
- 单个客户兑换次数上限；默认同一邀请码同一客户仅可兑换一次
- 已兑换次数
- 创建人
- 创建时间
- 备注（可选）

客户端在“我的钱包”中提供轻量入口：

邀请码兑换
→ 输入邀请码
→ 后端校验当前商户、邀请码状态、有效期、次数限制和客户领取资格
→ 校验成功后自动发放绑定优惠券
→ 显示兑换结果

邀请码 V1.0 仅用于兑换优惠券，不直接增加会员余额，避免绕过充值和余额审计流程。

邀请码必须属于当前商户，不允许跨商户兑换。

## 10. 收银时优惠券使用

收银时系统自动识别该客户当前订单可使用的优惠券。

如果存在多张可用券，系统自动计算并默认推荐对客户最优惠的一张，店员无需人工逐张寻找。

店员可按需要更换其他可用优惠券。

V1.0 每个订单最多使用一张优惠券，不做多张优惠券叠加。

优惠券与人工调价可同时存在，但后台必须分别保存：

- 原始金额
- 优惠券优惠金额
- 人工调价金额
- 最终应收金额

不得只保存最终成交金额。

## 11. 优惠券核销与退款

优惠券在店员选择时仅锁定，不立即核销。

流程：

选择优惠券
→ 临时锁定
→ 确认订单收款
→ 正式核销

订单取消或未完成收款时，锁定券恢复可用。

V1.0 退款规则采用简单方案：

- 整单取消 / 全额退款：若优惠券仍在有效期，则恢复优惠券。
- 部分退款：不恢复优惠券。

更复杂退款边界在核心业务规则阶段统一复核。

## 12. 客户端优惠券展示

“我的优惠券”仅需区分：

- 可使用
- 已使用 / 已过期

每张券至少显示：

- 券名称
- 优惠内容
- 适用范围
- 有效期
- 使用门槛（如有）

客户端不提供复杂领券中心。

## 13. 权限原则

商户老板默认拥有全部会员相关权限。

普通店员的权限后续通过细粒度权限开关控制，例如：

- 查看余额
- 使用余额收款
- 执行充值
- 人工调整余额
- 冲正充值
- 查看优惠券
- 手动赠送优惠券

默认普通店员不拥有“人工调整余额”“冲正充值”“随意赠券”等高风险权限。

## 14. 减少操作原则

钱包 / 会员资产模块必须优先减少门店和客户操作：

- 当前可用余额直接显示在“我的”页面，客户不必额外进入钱包才能查看。
- “我的钱包”不重复展示当前余额大卡，主要承载余额明细、优惠券和邀请码兑换。
- 老板提前配置充值套餐和优惠券模板。
- 店员充值时直接选择套餐，不重复输入赠送金额和赠送券。
- 充值成功后自动发放赠送权益。
- 收银时系统自动匹配并推荐最优惠的可用券。
- 组合支付由系统自动计算剩余应收。
- 邀请码兑换由客户自行输入，兑换成功后系统自动发券，不增加店员操作。
- 客户端不承担充值和余额支付。
