# 10A 客户端 UI Design System（提前进行的客户端子阶段）

> 状态：已确认基线，持续补充
> 所属阶段：10 UI / Design System（经产品方确认允许提前与阶段 04 并行推进）
> 当前范围：客户端通用视觉方向 + 首页 UI 已确认规则

## 1. 文档职责

本文件用于冻结客户端已经由产品方确认的视觉语言、首页 UI 结构与组件表现。

- 业务规则仍以 `03-customer-miniapp.md`、`03a`～`03n` 为准。
- 页面地图与业务入口以 `03i-customer-screen-blueprint.md` 为主产品蓝图。
- 本文件不得修改财务、权限、多租户、订单、库存、广告权益等业务规则。
- 后续预约、“我的”、服务结果、积分商城、养宠顾问等页面继续在本文件补充。
- 临时 H5 / AI 预览图只用于沟通；若与本文件及正式业务文档冲突，以正式文档为准。

## 2. 客户端整体视觉方向

### 2.1 已确认设计气质

客户端采用：

> 高级、亲和、温暖、生活方式感、轻盈、精致。

明确不采用大面积绿色作为页面基底，不做医疗化、企业后台化或紫蓝霓虹 AI 科技风。

当前确认方向来自产品方认可的暖色高保真参考：

- 页面主基底：浅米白 / 奶油白 / 暖灰白。
- 卡片：白色或非常浅的暖色表面。
- 主要强调：柔和杏色、暖橙、浅金棕。
- 文字：深棕灰 / 深中性色，避免全页面纯黑。
- 允许少量低饱和蓝、绿、灰用于业务状态语义，但不得重新形成“绿色为品牌基底”的视觉。
- 宠物图片、生活方式图片承担主要情绪价值。
- 不使用 Emoji 作为正式生产图标；正式图标采用统一圆角线性 / 轻量图标体系。

### 2.2 通用风格原则

- 页面背景与白卡片形成柔和层级。
- 大部分卡片使用轻边框或极轻阴影，不做大面积厚重悬浮卡。
- 强调色只用于主操作、价格、积分、重点状态和少量视觉引导。
- 页面不通过高饱和红色、绿色堆叠制造“促销感”。
- UI 优先展示业务信息和宠物图片，不通过复杂装饰制造高级感。

## 3. 首页最终信息结构

首页顺序严格沿用当前主产品蓝图：

1. 顶部门店栏
2. 可选品牌 / 生活方式 Banner
3. 当前服务
4. 宠物交友
5. 上门喂养
6. 推荐商品
7. 底部导航
8. 全局养宠顾问悬浮入口

业务区顺序仍为：

> 当前门店 → 当前服务 → 宠物交友 → 上门喂养 → 推荐商品

Banner 属于视觉承载，不改变上述业务优先级。

---

## 4. 首页顶部栏

### 4.1 左侧

至少展示当前门店名称；必要时提供门店切换。

可以在视觉允许时使用一行极轻的生活方式副标题，但不得重新出现“当前门店 / 已绑定客户”等重复说明。

### 4.2 右侧

产品方已确认：

> 首页顶部右侧只保留“消息”入口。

不在首页顶部同时放搜索、扫码等第二 / 第三入口，减少顶部噪音。

消息图标可显示未读红点 / 数量，但不得因消息模块加载失败导致首页整体失败。

---

## 5. 首页 Banner

当前视觉方向允许首页顶部使用一张生活方式型宠物 Banner，用于提升门店品牌与宠物生活氛围。

原则：

- 使用宠物 / 人宠生活场景为主视觉。
- 文案短，不承担复杂业务操作。
- 不做强促销广告墙。
- 圆角、渐变、图片滤镜保持暖色、克制。
- Banner 不得抢过“当前服务”的业务优先级。

具体尺寸、轮播与运营配置在后续首页高保真 / Web 配置规则中继续确认。

---

## 6. 当前服务卡

当前服务是首页最高业务优先级卡片。

### 6.1 洗护 / 美容

卡片至少表达：

- 宠物
- 服务名称
- 客户侧简化状态
- 开始 / 完成等必要时间
- 主操作

完成状态主操作统一进入“查看本次服务结果”。

### 6.2 寄养

寄养卡至少表达：

- 宠物
- 寄养状态
- 日期范围
- 当前第几天
- 最新一条动态
- 今日动态数量
- 新照片 / 视频提示（如有）
- `查看寄养动态`

点击后进入按实际发生时间倒序的寄养时间轴。

---

## 7. 宠物交友首页卡片

### 7.1 本节“单张卡片”定义

本 Design System 中所称“单张卡片结构”明确指：

> 首页「宠物交友」中的单只宠物展示卡片。

### 7.2 卡片信息

建议并确认的核心信息为：

- 宠物主图（视觉主体）
- 宠物社交昵称
- 热度
- 邀请能力标签（符合条件时）

不在首页交友卡片上堆叠主人信息、联系方式或商户内部资料。

### 7.3 热度替代爱心 / 点赞

产品方已确认：

> 原预览中的爱心 / 点赞表达取消，改为“热度”。

热度不是客户点赞数，也不建立点赞业务。

热度依据：

- 该宠物最近 7 天有效点击数；
- 该宠物最近 7 天在当前门店可公开交友宠物中的点击排名。

建议数据语义：

- `clicks_7d`：最近 7 天有效点击量；
- `store_click_rank_7d`：当前门店最近 7 天点击排名。

首页可以轻量展示：

> 热度 286

排名靠前时，可在不拥挤的前提下补充类似“本店热度 TOP 3”的轻量表达。

具体“有效点击”的去重窗口、防刷、机器人过滤、热度分数换算方式在后续统计 / 核心业务规则阶段冻结；前端不得自行累加或决定热度最终值。

### 7.4 “可发送邀请”视觉

产品方已选择方案 A：

> 使用卡片底部浅色状态 / 能力标签显示 `可发送邀请`。

不使用过强悬浮按钮抢占宠物图片。

只有真正允许发起邀请的其他宠物显示该标签；自己的宠物、仅自己可见、未开启交友或当前不可邀请的宠物不得显示。

### 7.5 轮播

沿用已确认业务规则：

- 自动横向轮播；
- 支持手动滑动；
- 每屏 3 只；
- 一轮最多 12 只；
- 自己的主展示宠物固定第 4 位；
- 用户手势期间自动轮播让位。

精确秒数仍未冻结。

## 8. 上门喂养首页卡片

上门喂养卡片视觉定位：

> 需求市场卡片，不做商品卡，不做传统复杂订单卡。

至少展示：

- 宠物摘要
- 日期 / 时间
- 模糊地点
- 每日预算
- 喂养要求摘要
- 客户侧状态
- 查看详情

预算需要明显，但不得通过高饱和促销红制造电商感。

### 8.1 客户端状态简化

产品方已确认首页 / 客户端正常主流程采用以下 4 个展示状态：

1. `待接单`
2. `已接单待门店对接`
3. `进行中`
4. `已完成`

底层业务可以保留更细状态用于门店处理、审计和流程控制，但客户端正常展示进行聚合：

- 门店对接中 / 已确认 / 服务中等进行阶段，可统一映射为 `进行中`；
- 最终完成映射为 `已完成`。

取消属于终止 / 历史异常状态，不作为首页正常活跃流程四状态之一；若用户在“我的发布 / 我的接单”等历史页面查看已取消需求，应如实显示已取消，不得伪装为已完成。

### 8.2 首页操作

首页上门喂养区域可提供：

- 发布需求：主操作；
- 我的需求：次操作；
- 更多需求：进入公开列表。

---

## 9. 推荐商品

首页推荐商品定位为“精选商品 / 好物展示”，不是完整电商首页。

卡片尽量轻：

- 商品图
- 商品名
- 参考售价
- 必要库存状态

不在首页商品卡堆叠 SKU、物流、收货地址等不存在或低频信息。

---

## 10. 养宠顾问悬浮入口

沿用已确认业务规则：

- 默认左侧安全区域；
- 可拖动；
- 松手自动吸附最近左 / 右侧；
- 不遮挡微信系统胶囊、底部导航和固定主操作；
- 视觉采用与暖色 Design System 一致的圆形 / 轻胶囊组件；
- 不采用大面积绿色或紫色科技发光风。

---

## 11. 底部导航

固定：

> 预约 | 首页 | 我的

- 当前项使用暖橙 / 杏棕体系强调。
- 未选中使用暖灰中性色。
- 图标采用统一圆角线性图标。
- 不做高耸悬浮中央首页按钮。

---

## 12. 状态、错误与故障隔离

首页任何模块加载失败必须局部降级：

- 当前服务失败不应导致商品、交友、上门喂养全部白屏；
- 宠物交友失败只显示该区域错误与重试；
- 上门喂养失败只影响该模块；
- 消息入口异常不阻塞首页；
- 养宠顾问异常仅提示顾问暂不可用。

通用状态需覆盖：

- Loading / Skeleton
- Empty
- Local Error + Retry
- Disabled
- Submitting

## 13. 本轮已确认事项

2026-09-06 首页 UI 设计确认：

1. 客户端主视觉不再使用绿色为基底，采用高级亲和的浅米白 / 奶油暖色 + 杏橙 / 浅金棕体系。
2. 首页顶部右侧只放消息入口。
3. 宠物交友单卡取消爱心 / 点赞表达，改为“热度”。
4. 宠物热度以最近 7 天有效点击数及当前门店 7 日点击排名为依据。
5. 宠物交友的“可发送邀请”使用方案 A：卡片底部浅色能力标签。
6. 上门喂养客户端正常主流程状态简化为：待接单 → 已接单待门店对接 → 进行中 → 已完成。
7. 首页业务顺序继续保持：当前服务 → 宠物交友 → 上门喂养 → 推荐商品。

后续继续完成：首页具体尺寸 / 间距 / Banner、预约页、“我的”、服务结果页及其组件规范。
