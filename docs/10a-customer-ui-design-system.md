## 2. 客户端整体视觉方向

### 2.1 已确认设计气质

客户端采用：

> 高级、亲和、温暖、生活方式感、轻盈、精致。

明确不采用大面积绿色作为页面基底，不做医疗化、企业后台化或紫蓝霓虹 AI 科技风。

当前确认方向：

- 页面主基底：浅米白 / 奶油白 / 暖灰白。
- 卡片：白色或非常浅的暖色表面。
- 主要强调：柔和杏色、暖橙、浅金棕。
- 文字：深棕灰 / 深中性色。
- 允许少量低饱和蓝、绿、灰用于业务状态语义，但不得重新形成绿色品牌基底。
- 宠物图片、生活方式图片承担主要情绪价值。
- 正式生产图标采用统一圆角线性 / 轻量图标体系，不直接使用 Emoji。

### 2.2 通用风格原则

- 页面背景与白卡片形成柔和层级。
- 大部分卡片使用轻边框或极轻阴影，不做大面积厚重悬浮卡。
- 强调色只用于主操作、价格、积分、重点状态和少量视觉引导。
- 页面不通过高饱和红色、绿色堆叠制造促销感。
- UI 优先展示业务信息和宠物图片，不通过复杂装饰制造高级感。

### 2.3 唯一通用 Token 来源：颜色与用途

本节是客户端通用视觉 Token 的唯一规范来源；`10b` / `10c` 只引用本节并定义有业务名称的布局变体，不另建一套色值、字体或状态体系。正式开发时建立一个共享 Token 源，按本表映射到小程序 WXSS 与 H5 预览适配层；页面和组件只引用语义名称。新增或修改通用 Token 必须同时更新本节、适配层与共享组件，并重新验证实际组合。当前阶段只确认规格，不生成产品代码或另一份 `DESIGN.md`。

| Token | 色值 | 允许用途 / 配对 |

### 2.4 字体与行高

`font.family.ui` 使用系统中文无衬线字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。标题、正文与数字使用同一可用系统字族，通过字重和层级区分；不为装饰下载字体导致首屏字体替换和控件位移。下表为 375px 设计基准下的字号 / 行高，支持用户字号放大，不设固定文本容器高度。

| Token | 字号 / 行高 / 字重 | 用途 |
|---|---|---|
| `type.hero` | 28px / 36px / 700 | 无当前服务时的完整品牌 Banner 标题 |
| `type.title` | 20px / 28px / 600 | 门店名称、页面标题 |
| `type.section` | 16px / 24px / 700 | 模块、服务卡标题 |
| `type.body` | 16px / 24px / 400 | 详情正文、长说明、输入内容 |
| `type.body.small` | 14px / 20px / 400 | 卡片日期、状态说明等简短正文 |
| `type.caption` | 13px / 20px / 400 | 次级时间、副标题 |
| `type.label` | 12px / 18px / 500 | 简短非交互状态标签 |
| `type.button` | 14px / 20px / 600 | 按钮、链接和轮播控制 |

正文、报错、金额和关键业务状态不得为挤进固定卡高而缩小字号。字号放大时行高同步增长，中文自然换行，长数字 / 英文允许安全断行；重要完整内容必须能从详情或明确的展开入口读取。

### 2.5 间距、圆角、触控与动效

| Token | 375px 基准值 | 用途 |
|---|---|---|
| `space.1 / .2 / .3 / .4 / .5 / .6 / .8` | 4 / 8 / 12 / 16 / 20 / 24 / 32px | 4px 栅格；页面边距 space.4，模块间距 space.6 |
| `space.dense.label / .card / .inset` | 6 / 10 / 14px | 仅限小标签间距、三列卡片间距、紧凑卡片内边距的例外 |
| `radius.control / .card / .hero / .pill` | 12 / 16 / 20 / 999px | 按钮与输入框 / 普通卡 / 品牌 Banner / 胶囊与圆形 |
| `stroke.control` | 1px | 必要控件边界，使用 border.control 或对应语义边界色 |
| `focus.width / .offset` | 2 / 2px | 焦点描边宽度 / 外偏移，使用 brand.strong；有色表面外增加 surface 隔离边 |
| `target.min` | 44×44px | 项目最小触控热区，以实际逻辑 px 验收；不是声称 WCAG AA 一律要求 44px |
| `motion.press / .snap / .carousel` | 100 / 200 / 300ms | 按下反馈 / 顾问吸附 / 横向切屏，默认 ease-out |
| `motion.carousel.interval / .resume` | 6000 / 8000ms | 自动切屏间隔 / 手动操作结束后最短恢复等待 |
| `motion.reduced` | 0ms | 减少动态效果时取消非必要位移动画，并关闭自动轮播 |

小按钮可采用低于 44px 的视觉高度，但外层热区至少达到 `target.min`，不得相互重叠、覆盖邻接卡片或广告点击区。可点击图标必须有中文可访问名称；H5 与支持键盘的客户端还需可见焦点和标准键盘操作。

### 2.6 按钮与反馈统一规则

| 呈现 / 意图 | 默认 | 按下 / 聚焦 | 不可用 / 提交中 |
|---|---|---|---|
| 主操作 solid / brand | brand.fill 背景 + brand.ink 文字 + brand.strong 边界 | brand.pressed 背景；统一焦点描边 | disabled.fill + text.secondary；提交中保留原尺寸并显示进行中 |
| 次操作 outline / neutral | surface 背景 + text.primary 文字 + border.control | neutral.pressed 背景 + brand.strong 边界；统一焦点描边 | 同上，不触发重复处理 |
| 文本操作 link / brand | brand.strong 文字；正文内链接有下划线 | brand.tint 背景，文字保持 brand.strong | 以文字说明原因，不仅降低整体透明度 |
| 最终危险确认 solid / danger | status.danger.ink 背景 + surface 文字 | 可见按下边界与焦点，不靠整体变淡 | 保留对象与后果说明；与安全主操作分开 |

成功、提示、警告、错误使用对应语义图标与文字；警告复用 brand.tint / brand.strong。浅杏色主按钮不配白色小字；brand.strong 在 brand.fill 上只可作边界，不能替代 brand.ink 做小字。同种操作在所有页面使用相同文案、状态和反馈；忙碌期间不扩宽按钮、不跳转两次。具体可否重试、取消及幂等仍由相应业务文档决定。

### 2.7 对比度验收与已计算基线

普通文字（含按钮、占位与报错）至少 4.5:1；大字至少 3:1；识别必要的非文本图标、控件边界和焦点与相邻背景至少 3:1。纯装饰边框不承担控件识别。依据：[W3C 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C 非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

2026-09-08 按不透明 sRGB 色值实算，使用线性亮度 `L = 0.2126R + 0.7152G + 0.0722B`、对比度 `(较亮 L + 0.05) / (较暗 L + 0.05)`；8 位通道除以 255 后，值不大于 0.04045 时除以 12.92，否则按 `((值 + 0.055) / 1.055)^2.4` 转换。下表仅为展示四舍五入，达标判断使用未舍入值。

| 实际前景 / 背景组合 | 对比度 | 结论 |
|---|---|---|
| text.primary / canvas；surface | 13.102；14.482 | 文字通过 |
| text.secondary / canvas；surface | 5.839；6.454 | 文字通过 |
| text.muted / canvas；surface | 4.878；5.392 | 文字通过 |
| brand.ink / brand.fill；brand.pressed | 6.387；5.315 | 主按钮文字通过 |
| brand.strong / canvas；surface；brand.tint | 6.553；7.243；5.879 | 链接 / 等待标签文字通过 |
| text.primary / surface.subtle；neutral.pressed | 12.034；10.436 | 次按钮文字通过 |
| text.secondary / disabled.fill | 5.262 | 本项目仍保持不可用文字可读 |
| accepted.ink / accepted.fill | 6.370 | 状态文字通过 |
| info.ink / info.fill | 6.730 | 状态文字通过 |
| success.ink / success.fill | 6.269 | 状态文字通过 |
| neutral.ink / neutral.fill | 5.527 | 状态文字通过 |
| danger.ink / danger.fill；surface / danger.ink | 5.996；7.122 | 错误文字 / 危险确认文字通过 |
| border.control / canvas；surface | 3.703；4.094 | 必要控件边界通过 |
| brand.strong / brand.fill；brand.pressed | 4.320；3.595 | 品牌控件边界通过；小字不使用此组合 |
| brand.strong / neutral.pressed | 5.220 | 次按钮按下边界通过 |

以上只证明这些静态配色组合达标，不代表整套小程序已通过无障碍验收。透明度、图片、渐变、叠层改变实际背景时须重新测量；品牌 Banner 业务文字放在已验证的不透明底色上，不直接叠在未知明暗照片上。

## 3. 首页最终信息结构

首页顺序固定为：

1. 顶部门店栏
2. 顶部品牌 / 生活方式 Banner
3. 当前服务
4. 宠物交友
5. 上门喂养
6. 精选商品
7. 首页底部微信 Banner 广告横幅
8. 底部导航
9. 满足门店付费权益条件时显示养宠顾问悬浮入口

业务区顺序仍为：

> 当前门店 → 当前服务 → 宠物交友 → 上门喂养 → 推荐商品

顶部品牌 Banner 属于产品视觉承载；底部微信 Banner 广告属于广告曝光变现位，两者不得混淆。

小程序启动 / 符合频控的重新进入时还存在独立的 `launch_cover_ad` 启动封面广告层；它发生在恢复本次业务目标之前，没有明确目标时才衔接最近有效门店首页。它不属于首页内容流，也不改变上述首页模块顺序。

## 4. 首页顶部栏

### 4.1 左侧

至少展示当前门店名称；必要时提供门店切换。

可以在视觉允许时使用一行极轻的生活方式副标题，但不得重新出现“当前门店 / 已绑定客户”等重复说明。

### 4.2 右侧

产品方已确认：

> 首页顶部右侧只保留“消息”入口。

不同时放搜索、扫码等第二 / 第三入口。

消息图标可显示未读红点 / 数量，但消息模块加载失败不得导致首页整体失败。

## 5. 顶部品牌 / 生活方式 Banner

顶部允许使用生活方式型宠物 Banner，用于提升门店品牌与宠物生活氛围。

原则：

- 宠物 / 人宠生活场景为主视觉。
- 文案短，不承担复杂业务操作。
- 不做强促销广告墙。
- 圆角、渐变、图片滤镜保持暖色、克制。
- 不得抢过“当前服务”的业务优先级。
- 有当前服务（包括仍需查看的刚完成服务）时使用紧凑 Banner，无当前服务时使用完整品牌 Banner；模块顺序不变，首屏任务与降级标准见 `10b` 第 5、15 节。
- 参考高度与具体排版见 `10b-customer-homepage-ui-spec.md`。

该 Banner 不是微信广告位，也不是启动封面广告。

## 6. 当前服务卡

当前服务是首页最高业务优先级卡片。

### 6.1 洗护 / 美容

至少表达：宠物、服务名称、客户侧简化状态、必要时间和主操作。

完成状态主操作统一进入“查看本次服务结果”。

### 6.2 寄养

至少表达：宠物、寄养状态、日期范围、当前第几天、最新一条动态、今日动态数量、新照片 / 视频提示和 `查看寄养动态`。

点击后进入按实际发生时间倒序的寄养时间轴。

## 7. 宠物交友首页卡片

### 7.1 单张卡片定义

“单张卡片结构”明确指首页「宠物交友」中的单只宠物展示卡片。

### 7.2 卡片核心信息

- 宠物主图
- 宠物社交昵称
- 热度
- 邀请能力标签（符合条件时）

不堆叠主人信息、联系方式或商户内部资料。

### 7.3 热度

原预览中的爱心 / 点赞表达取消，改为“热度”。热度不是点赞数，不建立点赞业务。

热度依据：

- 最近 7 天有效点击数；
- 当前门店最近 7 天点击排名。

建议数据语义：

- `clicks_7d`
- `store_click_rank_7d`

首页可轻量展示 `热度 286`；排名靠前时可补充“本店热度 TOP 3”等轻量表达。

有效点击去重、防刷和热度算法后续冻结；前端不得自行决定最终热度值。

### 7.4 “可发送邀请”视觉

产品方确认采用方案 A：

> 卡片底部浅色状态 / 能力标签显示 `可发送邀请`。

只有真正允许邀请的其他宠物显示；自己的宠物、仅自己可见、未开启或当前不可邀请的宠物不得显示。

### 7.5 轮播

- 多于一屏时默认自动横向轮播，保留暂停 / 继续及减少动态效果选择；
- 支持手动滑动；
- 每屏最多 3 只，不足时按实际数量；
- 一轮最多 12 只；
- 本轮真实宠物至少 4 只且包含本人主宠物时，该宠物固定第 4 位；不足时按 `03h` 第 2.1 节紧凑展示，不补位、不重复；
- 单屏不自动播放；手势、阅读焦点、弹层和后台状态均暂停自动切换；显式暂停不自动恢复。

数量、本人私有卡与手势恢复以 `03h` 为准；间隔与动效统一使用本文件第 2.5 节 Token。

## 8. 上门喂养首页卡片

视觉定位：需求市场卡片，不做商品卡或复杂订单卡。

至少展示：宠物摘要、日期 / 时间、模糊地点、每日预算、喂养要求摘要、客户侧状态和查看详情。

### 8.1 客户端主状态

正常主流程只展示：

1. `待接单`
2. `已接单待门店对接`
3. `进行中`
4. `已完成`

底层更细状态可用于门店和审计；客户端聚合显示。取消属于终止 / 历史状态，不属于正常四状态。

### 8.2 首页操作

- 发布需求：主操作
- 我的需求：次操作
- 更多需求：进入公开列表

### 8.3 本地无需求

当前城市没有可展示需求时，随机补充其他城市仍可公开的真实平台需求。

要求：

- 如实显示对应城市 / 区县；
- 不把异地需求伪装成本地需求；
- 随机只改变推荐顺序，不生成虚假需求；
- 全平台均无可公开需求时才显示真正 Empty State。

## 9. 精选商品

定位为精选好物展示，不是完整电商首页。

## 10. 首页底部微信 Banner 广告

产品方已确认首页最底部增加用于微信广告曝光变现的 Banner 广告位。

正式 placement：

`home_bottom_banner`

位置：

> 精选商品之后 → 微信 Banner 广告横幅 → 底部导航

规则：

- 与顶部品牌 / 生活方式 Banner 完全区分；
- 与启动封面广告完全区分；
- 不属于激励广告，不发放积分、AI 报告资格或养宠顾问次数；
- 使用正式微信广告组件 / SDK；
- 广告单元 ID 与开关配置化，不散落硬编码于页面；
- 广告加载失败、无填充或关闭时自动收起，不长期留下空白；
- 广告故障不得影响首页其他业务；
- 养宠顾问在有资格显示时不得覆盖广告主要点击区域；
- 开发 / H5 可使用明确标注的广告调试占位模拟 loaded / no_fill / failed / disabled，正式生产不得用 Mock 冒充真实广告。

详细规则见 `03o-customer-home-banner-ad.md` 与 `10b-customer-homepage-ui-spec.md`。

## 11. 养宠顾问悬浮入口

养宠顾问默认视觉仍采用方案 A：圆形悬浮按钮，但它已经改为**条件显示的付费门店权益组件**。

展示前提：

- 当前 Store 有有效 `pet_advisor` Feature Entitlement；唯一归属字段为 `owner_type=store`、`owner_id=store_id`，Merchant 仅作为购买、管理和审计主体；
- 门店已向本店客户开启；
- 当前 Platform User 已与当前门店建立有效 Customer 关系；
- 服务端资格校验通过。

满足条件时：

- 默认左侧安全区域；
- 可拖动；
- 松手自动吸附最近左 / 右侧，同时提供不依赖拖动的左 / 右移位操作；
- 不遮挡微信系统胶囊、底部导航、固定主操作和底部 Banner 广告；
- 采用柔和杏橙 / 奶油暖色体系；
- 正式图标不得直接使用 Emoji；
- 不采用大面积绿色或紫色科技发光风。

不满足条件时不展示可用悬浮入口；不能因为前端缓存了“曾经开通过”就在未付费门店继续显示。

同一用户切换门店时必须刷新条件：付费 / 已开启门店显示，未付费 / 已过期 / 已关闭门店隐藏。

拖动时用边界或阴影反馈，不整体减淡导致文字 / 图标对比度下降；吸附采用 `motion.snap`，减少动态效果时立即定位。热区和避让见 `10b`，替代操作见本文件第 13.3 节。

## 13. 状态、错误与故障隔离

首页任何模块加载失败必须局部降级：

- 当前服务失败不应导致其他模块白屏；
- 宠物交友失败只影响交友区域；
- 上门喂养失败只影响该模块；
- 消息入口异常不阻塞首页；
- 养宠顾问权益无效 / 服务异常只影响顾问入口；
- 底部 Banner 广告失败仅收起广告自身。

启动封面广告的成功、跳过、失败 / 无填充均按 `03p` 恢复已校验的原始业务目标，仅普通无目标启动回首页；`10c` 负责展示衔接，不得让广告故障阻塞业务页。

### 13.1 统一异步与页面状态

| 状态 | 统一展示 | 恢复 / 操作规则 |
|---|---|---|
| 首次 Loading | 模块内加载提示；结构已确定的卡片可用与最终几何一致的 Skeleton | 导航可用；媒体预留比例、按钮位置稳定；超时进入本模块 Error，不无限旋转 |
| 刷新 / 加载下一页 | 保留当前已验证数据，局部显示更新中 / 加载更多 | 不整页替换为 Skeleton，不重置滚动位置；旧响应不得覆盖新查询 / 新门店 |
| Empty | 查询成功且确实无数据，说明“暂无”与下一步 | 无当前服务显示“去预约”，无宠物显示“添加宠物”；上门喂养按 `03j` 区分本地空与全平台空 |
| No Results | 保留搜索词 / 筛选，说明没有匹配结果 | 提供“清空搜索 / 重置筛选”，立即清空并查询；不等同业务 Empty |
| Local Error | 模块内说明“加载失败”与“重试”；已有数据时标记更新失败 | 只重试失败模块，保留安全输入 / 列表位置；错误不得伪装成零余额、零积分、无服务或无库存 |
| Disabled | 明确不可操作及原因，采用第 2.6 节表现 | 不响应提交，Toast 不能是唯一原因说明；资格要求隐藏的入口仍按业务规则隐藏 |
| Submitting / Busy | 原控件内显示进行中，保留原宽度、输入和可见状态 | 阻止重复触发；成功读权威结果并按业务约定导航，失败可修正 / 重试；结果未知先查询原请求，不直接新建请求 |

业务提交的超时 / 恢复以对应业务文档为准；没有单独策略的普通读取请求客户端等待上限为 10 秒，到时给局部重试，迟到响应按请求版本处理。切换门店须撤销或忽略旧上下文请求，清除旧店敏感展示后加载新店；旧缓存不能充当新店结果。广告关闭 / 无填充的正常收起不展示成业务错误。

字段错误用中文说明并保留输入，提交时滚动到首个错误字段；搜索非空时有清空按钮，中文组字期间不发远程查询。成功 Toast 只作补充，余额、订单、积分等关键结果留在可重新访问的页面。列表详情返回保留原门店内的查询、筛选和滚动位置；权限、范围或门店改变时先校验，不恢复旧店敏感快照。

### 13.2 小程序适配、长内容与安全区

- 375px 是设计逻辑宽度，不是物理像素。小程序采用 750rpx 网格；基准上 `1px = 2rpx`，实际宽度 W 逻辑 px 时 `1rpx = W / 750px`。布局宽度可用 rpx，字体、细边框、最小热区和安全区不能全部等比缩小。
- 字号以本文件为 100% 基线，窄屏不低于各角色基线，并适配平台字体放大。热区按实际逻辑 px 不小于 44×44 验收，不能用窄屏下不足 44px 的 88rpx 代替。
- 覆盖 320 / 375 / 430px 宽度，至少含 320×568 短屏、375×812 与 430×932 长屏，分别验证 100%、150%、200% 文本缩放。小程序字号档位与 H5 缩放分开验证，不当作同一运行时能力。
- 卡片尺寸为参考或最小高度；长名称、状态、日期范围自然增高，不设固定最大高度裁掉操作。摘要可省略，金额、日期含义、状态、必要错误和按钮文字必须完整；详情可读完整名称与原文。
- 底部内容占位包含实际导航 / 固定栏高度、底部安全区及间隔；安全区只补偿一次，不重复叠加系统 TabBar 已预留空间。顶部按实际状态区和微信胶囊避让，不硬编码统一刘海高度。
- 键盘出现时按可视区域重排，当前输入、错误和提交 / 关闭可达；允许自然纵向滚动，不锁死整页高度。弹层长正文独立滚动，操作仍可达；全屏媒体、广告、弹层或键盘使顾问无安全位置时暂时隐藏悬浮入口，退出后重新校准。
- 媒体加载前保留比例，失败给真实替代说明和重试 / 详情入口。异步插入、广告收起保留阅读锚点，不能把手指下的业务按钮换成其他操作；广告留位与收起见 `10b`。

### 13.3 非拖动操作与动态效果

- N 组护理前后对比保留独立拖动，并为每组提供可点击的“护理前 / 护理后”或“并排查看”替代，显示当前组、素材时间及前后标签；缺一侧时只展示实际素材。可访问名称、焦点与键盘操作与同页控件一致。
- 顾问主体点击进入顾问，不依赖长按 / 拖动；在可见且名为“调整位置”的操作中提供“移到左侧 / 移到右侧 / 重置位置”。选项可独立触控，移位后继续避让系统区、主操作与广告；菜单不能只在悬停时可见。
- “我的 → 账号与设置”提供“减少动态效果”选项，关闭自动轮播及非必要位移动画；能读取系统偏好时默认跟随，不能读取时仍保留用户选项。明确暂停后刷新模块或返回同页不得自行继续；只有选择“继续”才恢复，减少动态效果开启时仍以手动切换为准。继续按钮本身保留焦点不应立即触发再次暂停，后续焦点移入其他卡片 / 控制时重新暂停，细则见 `03h`。

### 13.4 设计验收

覆盖本节视口和字号缩放、超长门店 / 宠物名、长状态与报错、键盘打开、单模块失败、搜索无结果、刷新旧响应、重复提交、广告收起、顾问移位、轮播暂停及非拖动对比。检查信息和操作完整、焦点 / 阅读顺序、实际热区、媒体占位和颜色组合。`10b` 首屏目标必须通过真实渲染验证，本轮文档和色值计算不代替真机 / H5 验证。

## 14. 本轮已确认事项

以下是当前仍然有效的客户端 UI 设计确认事项：

1. 客户端主视觉不使用绿色为基底，采用浅米白 / 奶油暖色 + 杏橙 / 浅金棕体系。
2. 首页顶部右侧只放消息入口。
3. 宠物交友单卡取消爱心 / 点赞，改为热度。
4. 热度以最近 7 天有效点击数及当前门店 7 日点击排名为依据。
5. “可发送邀请”使用方案 A：卡片底部浅色能力标签。
6. 上门喂养客户端正常主流程状态：待接单 → 已接单待门店对接 → 进行中 → 已完成。
7. 首页业务顺序：当前服务 → 宠物交友 → 上门喂养 → 推荐商品。
8. 养宠顾问默认视觉采用方案 A 圆形悬浮按钮，但仅在当前门店付费权益有效、门店已开启且当前用户属于本店 Customer 时显示。
9. 当前城市无上门喂养需求时，随机补充其他城市真实公开需求，不伪造本地需求。
10. 精选商品之后、底部导航之前存在 `home_bottom_banner` 微信 Banner 广告横幅，用于曝光变现；支持配置化与调试状态，失败 / 无填充时自动收起。
11. 新增 `launch_cover_ad` 启动封面广告；支持自定义图片、自定义视频或微信官方广告，成功 / 跳过 / 降级后的业务目标恢复统一按 `03p` 当前规则执行。

首页精确尺寸 / 间距 / 文案长度 / 卡片高度 / Banner 与广告位专项规格见 `10b-customer-homepage-ui-spec.md`；启动封面广告 UI 见 `10c-customer-launch-cover-ad-ui-spec.md`。
