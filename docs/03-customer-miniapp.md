## 1. 客户端定位

客户端核心定位：

> 服务过程透明 + 客户资料与资产查询 + 门店业务意向提交 + 平台级社区 / 权益 / 广告能力 + 条件式 AI 辅助能力。

V1.0 客户端已确认支持：

- 查看洗护 / 美容 / 寄养服务状态；
- 查看洗护 / 美容 N 组前后对比与按需 AI 洗护报告；
- 查看寄养动态时间轴、图片 / 视频，并在寄养中发起“投喂零食 / 寄养加餐”；
- 在线预约洗护 / 美容 / 寄养；
- 查看和维护宠物档案；
- 浏览商品、购物车并提交购买需求；
- 查看会员资产摘要、钱包、优惠券、订单与消息；
- 当前门店宠物交友；
- 平台级公开上门喂养需求市场；
- 平台积分、广告签到、积分商城与总仓到店自提；
- 首页底部微信 Banner 广告曝光；
- 小程序启动封面广告；
- **仅对符合付费门店权益条件的客户开放养宠顾问**。

客户端不承担真实线上支付，不提供会员充值入口。

详细规则以 `03a`～`03m`、`03o`～`03p` 为准；页面蓝图以 `03i` 为准。原 `03n` 已归档，不属于现行需求。

---

## 2. 门店、多商户与身份

- 一套平台小程序 + 商户专属二维码。
- V1 当前约束 `1 Merchant = 1 Store`。
- 平台 User 与商户 Customer 分离。
- 同一 User 可成为多个 Merchant 的 Customer，但商户余额、优惠券、订单、服务记录、内部备注等严格隔离。
- 已验证手机号用于当前商户历史 Customer 匹配，不作为平台唯一主身份。
- 切换门店时，所有门店业务上下文必须整体切换。
- 平台积分属于 Platform User；商户钱包属于 Merchant Customer，两者严格分离。
- 养宠顾问的**用户额度**属于 Platform User，但**使用资格**由当前门店 `pet_advisor` Feature Entitlement + 门店开关 + Customer 关系共同决定。
- 公开浏览不强制立即登录；进入个人业务时按需触发微信身份 / 手机号验证。

完整身份规则见 `03g-customer-identity-security.md`。

## 3. 启动流程与封面广告

小程序启动 / 符合频控的重新进入时，可在恢复正式业务目标前展示独立 `launch_cover_ad`。

支持：

- `custom_image`：平台自定义图片；
- `custom_video`：平台自定义视频；
- `wechat_ad`：微信官方广告。

Platform Super Admin 可单独配置：

- 开关；
- 广告来源模式；
- 图片 / 视频素材；
- 微信广告单元；
- 生效时间；
- 频控；
- 跳过策略；
- 测试 / 正式环境。

广告关闭、过期、无填充、素材加载失败或 SDK 失败时恢复原入口目标（无明确目标时进入首页），不得阻塞小程序正常使用。

预约 / 首页 / 我的及内部详情页之间跳转，不重复弹启动广告。

先保存分享 / 通知目标及关联门店；广告关闭、失败、超时后继续目标，无明确目标才进入首页。后台恢复保留原页面与安全草稿；无有效门店时按 03g 进入选店 / 扫码引导。详细规则见 `03p-customer-launch-cover-ad.md`。

## 4. 底部导航与首页

底部一级导航固定：

1. 预约
2. 首页
3. 我的

首页业务顺序固定：

> 当前门店 → 当前服务 → 宠物交友 → 上门喂养 → 推荐商品

UI 层当前完整顺序：

> 顶部门店栏 → 顶部品牌 / 生活方式 Banner → 当前服务 → 宠物交友 → 上门喂养 → 精选商品 → 首页底部微信 Banner 广告 → 底部导航

首页顶部右侧只保留消息入口。

顶部品牌 / 生活方式 Banner 是产品视觉内容，不是微信广告。有进行中服务时采用 10b 的紧凑变体，在约定最小支持屏幕、100% 系统字号下首屏应露出第一条服务状态与主操作；放大字号时自然滚动可完整访问。

## 5. 当前服务与寄养动态

### 5.1 洗护 / 美容

客户侧状态简化为：

- 等待中
- 洗护中 / 美容中
- 洗护完毕 / 美容完毕

首页最多直接展示 3 条当前服务，更多进入完整列表。

服务首次完成时首页提示查看结果；用户真正查看过结果后，该完成卡退出首页当前服务区域，但历史记录继续保留。

### 5.2 寄养

寄养卡至少展示：

- 日期范围；
- 当前第几天；
- 今日动态数量；
- 最近动态；
- 新图片 / 视频提示；
- `查看寄养动态`。

寄养详情按**真实发生时间倒序**展示时间轴：最新在上，历史向下，并按今天 / 昨天 / 具体日期分组。

动态可包含喂食、饮水、排泄、遛宠、玩耍、休息、清洁、用药 / 特殊照护、图片 / 视频、寄养加餐、异常和自定义事件。

实际发生时间与系统录入时间分离；补录事件按真实发生时间插回正确位置。

## 6. 寄养加餐

仅当：

- 当前宠物处于有效寄养中；
- 主人允许额外零食；
- 门店存在允许寄养投喂且可售的商品；

才显示 `投喂零食`。

路径：

投喂零食 → 选择可投喂商品 / SKU → 确认 → 已通知店员 → 请求处理中 → 店员处理 / 收银 / 实际投喂 → 寄养时间轴自动新增投喂动态。

不建立第二套投喂订单，复用统一商品购买需求：

- `source_channel = mini_program`
- `business_scenario = boarding_feed`
- 关联 `boarding_id / pet_id`

正式成交只计商品销售收入一次。付款状态与投喂执行状态分别记录：已收款不等于已投喂；待投喂仍显示请求处理中，实际执行确认成功后才写入一次动态并恢复新请求入口。取消、提前离店或无法执行的收口见 03e。

## 7. 宠物交友

- 首页多屏数据默认自动横向轮播，同时支持手动滑动与暂停 / 继续；减少动态效果、离开可视区域、单屏数据时暂停自动播放，详见 03h。
- 每屏 3 只，一轮最多 12 只不同宠物。
- 本轮真实宠物至少 4 只且包含本人主宠物时，自己的主展示宠物固定第 4 位；不足 4 只按实际数量展示，不复制宠物、不填空位；一屏容纳全部时不自动轮播。
- 自己未开启交友时可仅本人看到，不代表向其他客户公开。
- 只有主人主动授权后，宠物才进入其他客户可见的交友池。
- 真正可邀请的其他宠物使用卡片底部浅色 `可发送邀请` 能力标签。
- 自己 / 私有 / 未开启 / 不可邀请宠物不得显示该标签。
- 卡片互动指标使用**热度**，不建立点赞业务。
- 热度依据最近 7 天有效点击与当前门店 7 日点击排名，由服务端计算。
- 不公开主人联系方式，不提供客户之间直接聊天。
- 对方同意邀请后自动向本店店员生成待办。

详细规则见 `03h-customer-pet-social.md`。

## 8. 上门喂养

上门喂养是平台级公开需求市场。

用户可发布：

- 宠物 / 数量；
- 日期范围；
- 每日时间 / 次数；
- 地点；
- 每日预算；
- 喂养要求；
- 特殊注意事项。

公开页只显示模糊地点，不公开精确住宅地址、门牌号、手机号、微信、真实姓名。

第一个有效接单者由服务端原子锁定；接单后只向发布时绑定门店生成待办。

客户端正常主状态：

1. 待接单
2. 已接单待门店对接
3. 进行中
4. 已完成

取消属于历史 / 终止状态。

当前城市无可展示需求时，随机补充其他城市仍可公开的**真实平台需求**，必须如实显示异地城市 / 区县；全平台都无需求时才显示真正 Empty State。

发布后支持分享到微信聊天 / 群并深链到需求详情。

V1 不做线上资金托管、抽佣、自动分账或保证金。

详细规则见 `03j-customer-home-feeding-marketplace.md`。

## 9. 预约

预约与正式订单严格分离。

支持洗护、美容、寄养预约。

客户提交后进入待门店确认；门店可确认、提出新时间或拒绝。提出新时间后必须由客户确认，不能静默改约。

线下临时到店允许店员直接快速开单，不强制先预约。

详细规则见 `03a-customer-appointment.md`。

## 10. 洗护 / 美容结果与 AI 报告

服务完成后先形成普通结果，不自动调用 AI。

结果页顺序：

1. 服务状态 / 基本信息
2. N 组前后对比
3. 本次服务摘要 / 服务记录
4. 结算信息
5. AI 洗护分析

N 组由后端数据驱动，不写死固定组数；缺前 / 后素材不得伪造完整对比。

AI 标准流程：

查看普通结果 → 点击 `查看报告` → 完整观看激励广告 / 获得有效资格 → 后端启动 AI → 显示真实处理阶段 → 完成后展示报告。

广告文案与 5 段生成状态按已确认规则执行；约 60 秒仍未完成时提示稍后返回，后台任务继续。

AI 已获资格后失败重试不得重复要求广告。

报告定位为护理 / 外观观察，不作为医疗诊断。

## 11. 我的 / 钱包 / 积分

“我的”页面顺序基线：

1. 头像 / 昵称
2. 脱敏手机号
3. 会员资产摘要卡
4. 积分入口 / 摘要
5. 我的宠物
6. 我的钱包
7. 我的订单
8. 消息
9. 账号与设置

会员资产摘要卡固定展示：

- 当前可用余额
- 当前可使用优惠券数量
- 本金余额
- 赠送余额

整卡进入余额明细；积分不混入资金卡。

“我的钱包”承载余额明细、我的优惠券、邀请码兑换，无充值入口。

### 平台积分

积分属于 Platform User，使用独立积分账本。

每日签到：完整观看有效激励广告后，服务端受约束随机生成 1～10 分；自然周 7 天全签累计必须严格为 50；漏签不补足、不补签。

积分商城由 Platform Super Admin 管理。

实物奖励履约：

选择领取门店 → 扣积分 → 总仓发货 → 门店收货 → 待自提 → 用户到店领取 → 店员核销。

不做积分实物快递到家。

详细规则见 `03c`、`03k`。

## 12. 商品、订单与消息

### 商品

轻商城 / 购买需求，不做完整线上电商。

支持搜索、分类、SKU、详情、购物车、提交购买需求；不支持客户端在线支付、地址、快递、运费、用户物流页。

### 订单

“我的订单”只保留：全部 / 服务 / 商品。

预约不进入普通订单；充值记录归钱包流水。

订单、退款、取消、冲正不得删除或无痕覆盖历史。

### 消息

使用单一时间流，展示当前用户的平台个人消息与当前门店个人消息；其他门店私有消息继续隔离。未读 / 全部已读范围和跨店深链按 03f / 03g 执行。重要业务变化产生站内消息，必要时尝试微信通知；通知失败不得影响正式业务。

V1 不做客户 / 店员私聊、在线客服、客户直接聊天或营销群发。

## 13. 养宠顾问：付费门店权益

养宠顾问不再是全平台默认开放能力。

当前门店显示 / 允许使用至少同时满足：

1. Platform Super Admin 已给当前 Store 授予有效 `pet_advisor` 付费权益；唯一归属字段为 `owner_type=store`、`owner_id=store_id`，Merchant 仅作为购买、管理和审计主体；
2. 权益未过期 / 未停用；
3. 门店已向本店客户开启；
4. 当前 Platform User 已与本店建立有效 Customer 关系；
5. 服务端资格校验通过。

未满足条件时不显示可用养宠顾问悬浮入口。

同一用户切换门店时必须重新校验：A 店付费不代表 B 店可用。

满足条件时使用已确认的圆形悬浮按钮：默认左侧、可拖动、松手吸附最近左右边缘，不遮挡微信系统区、底部导航、首页底部广告和主要按钮。

### 用户额度

本次门店付费变更不修改原有用户额度：

- 同一 Platform User 终身前 3 次有效提问免费；
- 第 4 次前看 `pet_advisor` 激励广告；
- 每次广告解锁 3 次；
- AI 成功回答才消耗 1 次；
- AI 失败不扣；
- 切换到另一家付费门店不重新赠送前三次。

门店资格与用户额度分开判断：有额度不代表可以在未付费门店使用。

门店付费也不代表 Merchant Owner / Staff 自动获得客户聊天正文查看权限。

详细规则见 `03l-customer-pet-advisor.md`。

## 14. 广告体系

V1 当前至少包含三类广告能力：

### 14.1 激励广告

placement：

- `ai_report`
- `daily_checkin`
- `pet_advisor`

完整观看并经可信校验后发放对应权益，要求幂等。

`pet_advisor` 激励广告不能绕过当前门店付费 Feature Entitlement。

### 14.2 首页底部 Banner 广告

placement：`home_bottom_banner`

位置：精选商品后、底部导航前。

用于曝光 / 点击变现，不发 Reward Entitlement；失败 / 无填充 / 关闭时自动收起。

### 14.3 启动封面广告

placement：`launch_cover_ad`

小程序启动 / 符合频控的重新进入时，在恢复本次业务目标前按配置展示；没有明确目标时，目标才是最近有效门店首页。支持平台自定义图片、自定义视频或微信官方广告。

图片 / 视频可单独替换；微信广告单元独立配置；支持时效、频控、跳过和测试 / 正式环境。

失败 / 无填充 / 关闭不得阻塞进入目标页（无目标时进入首页）。

三类广告必须在代码、配置、统计和业务权益上区分，不能因为都叫“广告”就共用错误的状态模型。

详细规则见 `03m`、`03o`、`03p`。

## 15. 故障隔离

任何辅助模块故障不得拖垮核心业务。

特别是：

- AI 失败不影响服务 / 订单；
- 养宠顾问 / 门店权益校验失败只影响顾问；
- 首页 Banner 广告失败只收起广告；
- 启动封面广告失败恢复原入口目标（无明确目标时进入首页）；
- 积分故障不影响钱包 / 收银；
- 上门喂养故障不影响洗护 / 寄养 / 商品。
