# 03 客户端微信小程序

> 状态：已确认
> 版本：V1.0

## 1. 客户端定位

客户端核心定位：

> 服务过程透明 + 客户资料与资产查询 + 门店业务意向提交 + 平台级宠物社区 / 权益 / AI 辅助能力。

V1.0 客户端已确认支持：

- 查看洗护 / 美容 / 寄养服务状态
- 查看洗护 / 美容前后 N 组对比与 AI 洗护报告
- 查看寄养动态时间轴、寄养图片 / 视频，并在寄养中发起“投喂零食 / 寄养加餐”
- 在线预约洗护 / 美容 / 寄养
- 查看和维护宠物档案
- 浏览商品、加入购物车并提交购买需求
- 查看会员资产摘要、钱包、优惠券、订单与消息
- 当前门店宠物交友
- 平台级公开“上门喂养”需求市场
- 平台积分、每日广告签到、积分商城与总仓到店自提
- 全局可拖动的 AI「养宠顾问」

客户端不承担真实线上支付，不提供会员充值入口。平台积分属于 Platform User，与商户钱包、本金、赠送余额和商户优惠券严格分离。

详细规则见 `03a`～`03n`。

---

## 2. 门店进入、多商户与身份

采用“一套平台小程序 + 商户专属二维码”模式。

- 每个商户拥有专属客户二维码。
- 扫码后进入对应 Merchant / Store 上下文。
- 公开首页、推荐商品、上门喂养公开需求等允许按对应规则先浏览。
- 首次使用预约、宠物、钱包、订单、消息、购买需求、宠物交友邀请、上门喂养发布 / 接单、积分签到 / 兑换、养宠顾问等个人能力时，再完成必要的微信身份与手机号验证。
- 平台 User 与商户 Customer 分离。
- 已验证手机号用于当前商户历史 Customer 匹配，不作为平台唯一主身份。
- 同一 User 可成为多个 Merchant 的 Customer，各商户余额、优惠券、订单、服务记录、内部备注等严格隔离。
- 平台积分、养宠顾问等明确的平台级能力归 Platform User，不归某一家 Merchant 所有。
- 直接打开小程序时优先进入最近一次使用的商户。
- 切换商户时门店业务上下文整体切换，禁止跨商户串数据。

完整规则见 `03g-customer-identity-security.md`。

## 4. 首页

### 4.1 首页最终顺序

2026-09-06 当前正式顺序固定为：

1. 当前门店
2. 当前服务
3. 宠物交友
4. 上门喂养
5. 推荐商品

这是当前产品基线。早期“当前服务 → 上门喂养 → 宠物交友”的顺序已被正式调整，不再作为实现依据。

### 4.2 当前门店

首页顶部仅突出：

- 当前商户 / 门店名称
- 必要时的切换门店入口

不额外显示“当前门店”“已绑定客户”等重复辅助说明。

### 4.3 当前服务

当前服务为首页最高业务优先级区域。

- 同一客户最多直接展示 3 条进行中 / 刚完成服务，更多进入完整列表。
- 洗护 / 美容客户侧只显示简化状态：等待中、洗护中 / 美容中、洗护完毕 / 美容完毕。
- 不暴露店员内部细分步骤。
- 无当前服务时使用轻量预约引导。

洗护 / 美容服务首次完成时：

- 客户直接打开仍默认进入首页。
- 首页出现完成提示。
- 提供“查看本次服务结果”和“稍后查看”。
- 选择稍后查看后，完成卡继续保留在当前服务。
- 客户真正进入并查看过本次服务结果后，该完成服务退出首页当前服务区域，历史仍保留在订单 / 宠物服务记录中。

### 4.4 寄养当前服务与动态入口

寄养首页卡至少展示：

- 当前寄养状态
- 日期范围
- 当前第几天
- 今日动态数量
- 最近一条动态
- 新图片 / 视频提示
- “查看寄养动态”入口

点击“查看寄养动态”进入当前宠物的寄养详情 / 动态时间轴。

寄养动态必须按**真实发生时间**记录，客户端以时间轴展示，默认采用：

> 最新动态在上 → 更早动态向下浏览

并按日期分组，例如“今天 / 昨天 / 具体日期”。

每条时间轴事件至少可表达：

- 实际发生时间
- 动态类型
- 文本说明（可选）
- 图片 / 视频（可选）
- 是否最新动态

常见动态包括：

- 喂食 / 早餐 / 午餐 / 晚餐
- 饮水 / 更换饮水
- 遛狗 / 遛宠
- 排便 / 排尿
- 玩耍 / 互动
- 休息
- 环境整理 / 清洁
- 用药 / 特殊照护
- 图片 / 视频更新
- 寄养加餐 / 零食投喂
- 异常情况
- 自定义事件

“实际发生时间”与“系统录入时间”必须分离保存，支持店员补录和审计；客户端时间轴按实际发生时间排序。

### 4.5 宠物交友

首页宠物交友区域：

- 默认自动横向轮播，同时支持手动横向滑动。
- 用户主动滑动时优先响应手势，结束后再恢复自动轮播。
- 每屏 3 只宠物。
- 一轮最多 12 只不同宠物，不重复凑数。
- 当前客户自己的主展示宠物固定第 4 位，即第二屏第 1 位。
- 自己的宠物可以仅对本人展示，不因此自动公开。
- 只有主人主动开启交友后，宠物才进入其他客户可见的公开展示池。
- 对当前客户可正常邀请的其他宠物，能力角标统一为“可发送邀请”。
- 自己的宠物、未开启交友或当前不可邀请的宠物不得错误显示“可发送邀请”。
- 点击卡片进入交友详情，可查看允许公开的社交昵称与服务后照片并发起邀请。
- 不直接公开主人联系方式。
- 同一无序宠物对只允许一条邀请记录；重复 / 反向重复提示已发送过邀请。
- 对方同意后双方看到“已告知店员，请等待店员回复”，同时生成店员端待办。
- 对方拒绝或不回复时，不向邀请方主动发送拒绝 / 未回复结果。

完整规则见 `03h-customer-pet-social.md`。

### 4.6 上门喂养

上门喂养是平台级公开需求市场，首页区域固定放在“宠物交友”之后、“推荐商品”之前。

首页可展示公开需求摘要并提供“查看更多”“发布需求”等入口。

需求至少包含：

- 宠物 / 宠物数量
- 日期范围
- 每日喂养时间 / 次数
- 模糊地点
- 每日预算
- 喂养要求
- 当前状态

公开位置只展示区县 + 小区名称 / 附近区域等模糊位置，不公开精确住宅地址、门牌号、手机号、微信或真实姓名。

发布后支持分享到微信聊天 / 群，分享卡深链到对应需求详情。

第一个成功接单者由服务端原子锁定；其他用户不得继续形成有效接单。接单后只向发布时绑定的门店生成对接待办，由该门店协调双方。

V1.0 不建设平台在线支付、资金托管、抽佣、自动分账或保证金。

完整规则见 `03j-customer-home-feeding-marketplace.md`。

### 4.7 推荐商品

首页展示当前门店 3～6 个推荐商品，并提供“查看更多”。

商品卡至少表达图片、商品名、售价 / 参考售价和客户可见库存状态。

## 5. 预约

预约与正式订单严格分离。

支持：

- 洗护预约
- 美容预约
- 寄养预约

洗护 / 美容正常路径：

选择宠物 → 选择服务 → 选择日期 → 选择开放时段 → 提交预约。

客户提交后状态为“待门店确认”。门店可以确认、提出新时间或拒绝；门店提出新时间时需客户确认，不允许静默修改。

寄养预约包含宠物、入住 / 离店时间、已有寄养资料确认、本次特殊要求等。

线下临时到店允许店员直接快速开单，不强制先预约。

完整规则见 `03a-customer-appointment.md`。

## 6. 洗护 / 美容结果与 AI 报告

服务完成后先形成普通服务结果，**不得因服务完成自动调用 AI 或自动向 AI Provider 提交照片**。

结果页顺序基线：

1. 服务状态 / 基本信息
2. N 组前后拖动对比
3. 本次服务摘要 / 服务记录
4. 结算信息
5. AI 洗护分析
6. 关联订单入口（如需要）

### 6.1 N 组前后对比

- 店员上传 N 组完整“服务前 + 服务后”，客户端动态生成 N 组独立对比。
- 不写死 1 组、4 组或其他固定数量。
- 每组前后图保持同一 comparison group 关系。
- 可有标题 / 角度与排序。
- 缺一侧图片不得伪造完整拖动对比。
- 服务相册保留 `service + comparison group + before/after + sort_order` 关系。

### 6.2 AI 按需生成

标准流程：

查看普通服务结果 → 点击“查看报告” → 展示广告说明 → 完整观看激励广告 / 获得有效资格 → 后端创建 AI 任务 → 提交本次允许分析的照片 → 显示真实进度 → 完成后展示报告。

广告弹窗标题：`查看 AI 洗护报告`

说明文案：

> 本功能采用国际领先AI助手分析，相关费用已由赞助商赞助，观看完整广告后即可免费查看本次 AI 洗护报告。

生成阶段：

1. 宠物影像质量检测中
2. 洗护前后特征比对中
3. 毛发与清洁状态分析中
4. 专业护理知识检索中
5. 结果复核与报告生成中

正常体验目标约 30～60 秒；真实结果提前完成立即展示。约 60 秒仍未完成时提示：

> 报告仍在生成中，分析已提交，可稍后返回本页面查看结果。

客户离开后后台任务继续；再次进入读取真实状态。

广告已完成但 AI 后续失败时，重试同一报告不得再次要求广告。AI 任务需幂等，AI 失败不得影响服务完成、订单和普通结果。

报告定位为护理 / 外观观察，不作为医疗诊断。

## 7. 寄养动态与寄养加餐

### 7.1 寄养动态数据

每条寄养动态至少保存：

- boarding_id
- pet_id
- 实际发生时间
- 动态类型
- 可选文本
- 可选图片 / 视频
- 操作员工
- 系统创建时间

客户端按实际发生时间倒序展示最新动态，并允许向下查看历史。

### 7.2 投喂零食 / 寄养加餐

仅当：

- 宠物处于有效寄养中；
- 主人允许额外零食；
- 门店存在允许寄养投喂且当前可售的商品；

才提供“投喂零食”入口。

客户端选择零食并确认后生成统一商品购买需求，不建立第二套投喂订单：

- `source_channel = mini_program`
- `business_scenario = boarding_feed`
- 关联 `boarding_id / pet_id`

提交后提示“已通知店员”，店员端生成待办，并继续按普通商品确认、库存预占、调价、收银和实际投喂确认处理。

正式成交只计入商品销售一次，不重复计入寄养收入；实际投喂完成后自动写入寄养时间轴。

同一宠物存在未完成投喂请求时，客户端显示“投喂请求处理中”等状态，避免误触连续下单。

完整规则见 `03b-customer-pet-profile.md`。

## 10. 平台积分 / 每日签到 / 积分商城

积分属于 Platform User，使用独立积分账本，与商户资金资产严格分离。

### 10.1 每日签到

点击签到 → 激励广告 → 完整观看并验证成功 → 服务端生成签到奖励。

- 每自然日最多成功签到一次。
- 每日奖励为服务端受约束随机 1～10 分。
- 自然周为周一 00:00 至周日 23:59。
- 若 7 天全部成功签到，7 次奖励累计必须严格为 50 分。
- 漏签只获得实际签到积分，不补足 50。
- V1.0 不提供补签。

### 10.2 积分商城

由 Platform Super Admin 统一管理。

奖励包括：

- 线下消费优惠券 / 虚拟权益
- 狗粮、猫粮、冻干、零食等实物奖励

券类兑换由积分域扣积分，钱包 / 优惠券域向选定门店 Customer 发券，两套账本分离并要求幂等 / 补偿。

实物奖励使用平台总仓独立奖励库存，V1.0 固定履约：

选择奖励 → 选择领取门店 → 扣积分 → 待总仓发货 → 已发往门店 → 门店收货 / 待自提 → 用户到店领取 → 店员核销 → 已领取。

不提供快递到家、用户收货地址、用户运费或用户物流配送页面。

积分明细与积分消费记录只在积分体系中展示，不混入商户钱包流水。

完整规则见 `03k-customer-loyalty-points.md`。

## 11. 我的订单与商品购买需求

“我的订单”顶部只保留：

- 全部
- 服务
- 商品

预约不进入普通订单；充值记录归钱包流水。

商品模块定位为轻商城，支持搜索、分类、商品 / SKU、详情、数量、购物车和提交购买需求，不支持在线支付、地址、快递、运费、物流。

商品购买需求流程：

提交 → 门店确认中 → 店员确认 / 必要时调整数量与金额 → 库存预占 → 优惠券匹配 → 线下付款 → 店员确认收款 → 正式出库并计入营业额。

默认待付款保留 24 小时，可按已确认规则配置。

订单、退款、取消、冲正不得通过删除或无痕覆盖历史实现。

完整规则见 `03d`、`03e`。

## 12. 消息中心

入口：我的 → 消息。

使用单一时间流，不做复杂多 Tab。

重要业务状态自动产生站内消息；必要时尝试微信通知。微信通知失败不得影响正式业务。

V1.0 不做客户 / 店员私聊、在线客服、客户之间直接聊天或营销群发。

普通寄养动态不逐条微信推送；寄养异常按规则提醒。宠物好友邀请、商品状态、积分实物到店自提等可进入消息体系。

完整规则见 `03f-customer-messages.md`。

## 13. 养宠顾问

客户端主要页面提供全局「养宠顾问」悬浮入口：

- 初始位于左侧安全区域。
- 支持拖动。
- 松手后自动吸附距离最近的左侧或右侧。
- 不遮挡微信胶囊、底部导航和固定主要按钮。
- 可记忆用户最近纵向位置。

首次点击先显示“养宠顾问介绍”，关闭 / 开始咨询后进入聊天框；后续默认直接进入聊天，可从“关于养宠顾问”再次查看介绍。

同一 Platform User：

- 前 3 次有效提问终身免费，不按日重置。
- 第 4 次前需要完整观看一次激励广告。
- 每次有效广告解锁 3 次有效提问。
- 3 次用完后再看广告解锁下一组 3 次。
- 只有 AI 成功返回有效回答才消耗一次额度；AI 超时、失败、网络异常或系统错误不得扣次数。

养宠顾问定位为日常养宠知识与护理参考，不作为线上兽医。明显紧急风险应优先显示不依赖广告额度的基础安全提示。

完整规则见 `03l-customer-pet-advisor.md`。

## 14. 统一激励广告权益

AI 洗护报告、每日签到、养宠顾问统一使用公共激励广告权益模块。

当前 placement：

- `ai_report`
- `daily_checkin`
- `pet_advisor`

广告是否完整观看必须由可信 SDK 回调 / 服务端可验证结果判定；权益发放必须幂等，不相信前端自行修改的“已观看”状态。

一个 placement 的广告权益默认不能替代另一个 placement。

广告模块故障只影响对应需要广告解锁的权益，不得导致预约、洗护、寄养、商品、钱包、收银等核心业务整体不可用。

完整规则见 `03m-customer-rewarded-ads.md`。
