# 03 客户端微信小程序

> 状态：讨论中
> 版本：V1.0 Draft

## 1. 客户端定位

客户端用于：

- 查看洗护 / 美容 / 寄养服务状态
- 查看洗护前后对比图
- 查看 AI 洗护分析报告
- 查看宠物档案
- 查看消费记录
- 查看会员余额、积分、优惠券
- 浏览商品并提交购买需求
- 提交会员充值申请
- 提交服务预约
- 接收门店服务通知

客户端不直接承担真实线上支付。

## 2. 门店进入与客户二维码

采用“一套平台小程序 + 商户专属二维码”的模式。

规则：

- 每个商户拥有专属客户二维码。
- 顾客扫描二维码进入小程序时，系统识别对应商户。
- 顾客完成微信登录 / 手机号绑定后，与该商户建立 Customer 关系。
- 顾客后续直接打开小程序时，优先进入最近一次使用的商户上下文。
- 顾客可在自己曾建立关系的商户之间切换。
- 切换商户时，余额、积分、优惠券、订单、服务记录、商品和预约等全部按商户隔离。
- 宠物基础档案可按用户授权机制复用，但商户业务数据不得跨商户暴露。

## 3. 首页核心服务卡片

顾客打开小程序后，若当前有进行中的洗护 / 美容 / 寄养服务，应优先展示当前宠物服务状态。

### 3.1 洗护 / 美容状态

V1.0 客户侧只展示三个简化状态：

1. 等待中
2. 洗护中
3. 洗护完毕

客户端不展示更细的内部员工操作节点。

门店端内部是否保留更细过程记录，在店员端模块中另行设计。

### 3.2 洗护完成弹窗

当一笔洗护 / 美容服务首次进入“洗护完毕”状态，并且顾客打开小程序或回到相关页面时，应明显提示服务已完成。

弹窗核心信息：

- 宠物名称 / 头像
- “本次洗护已完成”提示
- 主按钮：查看本次服务对比图

需避免同一完成记录在每次打开小程序时无限弹窗；系统应记录用户是否已经查看 / 关闭过该完成提示。

## 4. 洗护前后对比页

点击“查看本次服务对比图”进入本次服务结果页面。

页面至少展示：

- 洗护前照片
- 洗护后照片
- 前后对比展示
- 本次服务基本信息
- 完成时间
- 服务员工（是否向客户展示后续确认）

页面第一行 / 首屏醒目区域必须展示：

> 查看本次 AI 分析报告

该入口视觉优先级高于普通服务信息。

## 5. AI 洗护分析报告

### 5.1 报告生成

AI 分析报告由本次洗护前后对比照片作为核心图像输入，由后端调用平台超级管理员选定的 AI 模型生成。

建议输入不局限于一张拼接图；后端应支持把“洗护前图”和“洗护后图”作为独立图像输入提交给支持多图视觉理解的模型，以减少拼图造成的信息损失。

AI 报告至少应具备独立生成状态：

- pending：等待生成
- processing：生成中
- completed：生成成功
- failed：生成失败

AI 生成失败不能影响洗护订单本身完成。

### 5.2 广告解锁

顾客点击“查看本次 AI 分析报告”后，不直接展示报告。

流程：

点击 AI 报告
→ 主动触发激励视频广告
→ 判断广告是否完整观看
→ 完整观看后解锁该次 AI 报告
→ 展示报告

微信小程序支持 RewardedVideoAd 激励视频广告组件，因此实现时应使用官方支持的激励视频广告机制，而不是自制不可关闭的广告弹窗。

建议规则：

- 用户必须主动点击“查看 AI 报告”后才触发广告。
- 只有完整观看广告后才视为成功解锁。
- 中途关闭广告不解锁报告。
- 每份报告成功看完一次广告后建议永久解锁，之后再次查看该份报告无需重复观看广告。
- 需要记录：report_id、user_id、广告解锁状态、解锁时间。
- 广告加载失败、无广告库存等异常场景的降级策略后续单独确认。

## 6. AI Provider 配置

用户提到的“CDkey”在技术实现中统一定义为 AI Provider API Key / Credential。

AI 模型不得写死为某一家供应商。

平台超级管理员应可在 Web 后台配置不同 AI Provider，例如未来可接入：

- OpenAI
- Anthropic（如支持所需视觉能力）
- Google Gemini
- 阿里云 / 通义
- 火山 / 豆包
- 其他兼容视觉模型 API 的供应商

具体支持列表在技术架构阶段确认。

每个 Provider 配置建议包含：

- Provider 名称
- API Base URL（如适用）
- API Key / Credential
- Model ID
- 是否启用
- 是否为当前默认模型
- 超时时间
- 最大重试次数
- 可选请求参数

安全原则：

- AI API Key 只能保存在服务端。
- 小程序和 Web 前端不得获得明文 API Key。
- 数据库存储时应对敏感凭证进行加密或使用独立 Secret 管理机制。
- 日志不得输出完整 API Key。
- AI 请求由统一后端 AI Adapter / Provider 层调用，业务代码不得直接绑定具体厂商 SDK。

## 7. AI 报告内容方向

AI 报告基于洗护前后照片生成，定位为宠物护理 / 外观观察报告，不应伪装为兽医医疗诊断。

建议报告结构后续细化为：

- 本次整体变化概览
- 毛发整洁度 / 蓬松度变化
- 打结 / 毛发状态观察
- 可见皮肤区域观察（仅照片可见范围）
- 外观清洁变化
- 值得主人继续关注的护理事项
- 洗护前后变化总结
- AI 免责声明

任何涉及疾病、诊断、治疗建议的高风险医疗结论应避免或明确限制。

## 8. 寄养状态与时间轴

寄养模块不使用固定时间模板。

店员可以根据实际发生时间自由新增寄养动态。

示例：

- 08:17 早餐
- 09:42 遛狗
- 10:26 排便
- 13:05 喝水
- 15:31 玩耍
- 18:12 晚餐

每条寄养动态至少包含：

- 实际发生时间
- 动态类型
- 文本说明（可选）
- 图片 / 视频（可选，具体限制后续确认）
- 操作员工
- 创建时间

“实际发生时间”和“系统录入时间”必须分开保存，避免员工补录时造成时间失真。

动态类型不能被固定时间绑死，可包含：

- 早餐 / 喂食
- 喝水
- 遛狗
- 排便
- 排尿
- 玩耍
- 休息
- 用药 / 特殊照护
- 洗澡 / 清洁
- 图片 / 视频动态
- 异常情况
- 自定义事件

客户侧按照实际发生时间形成当天时间轴。
