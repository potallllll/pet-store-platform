# 03 客户端微信小程序

> 状态：讨论中
> 版本：V1.0 Draft

## 1. 客户端定位

客户端用于查看洗护 / 美容 / 寄养服务状态，查看洗护前后对比图与 AI 分析报告，查看宠物档案、会员、订单与消费记录，浏览商品并提交购买需求，以及发起服务预约。

客户端不直接承担真实线上支付，也不提供会员充值入口。

## 2. 门店进入与客户二维码

采用“一套平台小程序 + 商户专属二维码”的模式。

规则：

- 每个商户拥有专属客户二维码。
- 顾客扫码后进入该商户上下文。
- 顾客完成微信登录 / 手机号绑定后，与该商户建立 Customer 关系。
- 顾客后续直接打开小程序时，优先进入最近一次使用的商户上下文。
- 顾客可在自己曾建立关系的商户之间切换。
- 切换商户时，余额、积分、优惠券、订单、服务记录、商品和预约全部按商户隔离。
- 宠物基础档案可按用户授权机制复用，但商户业务数据不得跨商户暴露。

## 3. 底部导航结构

V1.0 客户端底部只保留三个一级导航入口，按用户指定顺序排列：

1. 预约
2. 首页
3. 我的

不再单独设置“服务”“商城”“宠物”“门店信息”等底部一级导航。

### 3.1 预约

预约页专门承载未来服务意向，核心用于：

- 预约洗护
- 预约美容
- 预约寄养
- 选择宠物
- 选择日期 / 时间
- 填写备注或特殊需求
- 查看当前预约状态
- 取消 / 修改尚未开始的预约（具体规则后续确认）

V1.0 预约不在线支付。

### 3.2 首页

首页只承载三类核心信息：

- 当前门店
- 当前服务
- 推荐商品

首页不展示门店详细信息、我的宠物、会员资产、订单入口等低频或个人中心类内容。

### 3.3 我的

“我的”作为个人资料与历史资产中心，至少包含：

- 我的宠物
- 我的会员
- 我的订单

后续可在“我的”内部继续承载积分、优惠券、余额明细、消费记录、消息、设置等二级入口，但不新增底部一级导航。

## 4. 首页结构

### 4.1 当前门店

首页顶部显示当前商户 / 门店名称，并提供门店切换入口。

若客户只关联一家商户，仍显示当前门店名称，但不必强调切换能力。

若客户关联多家商户，则可通过顶部入口切换。切换后首页的当前服务、推荐商品，以及“我的”中的会员和订单等业务数据整体切换到目标商户上下文。

### 4.2 当前服务

当前服务为首页最高优先级内容。

若只有一条当前服务，直接展示对应宠物和状态。

若同一客户同时存在多条当前服务，则首页展示服务列表；建议首页直接展示最多 3 条，超过部分通过“查看全部当前服务”进入完整列表。

#### 洗护 / 美容客户侧状态

V1.0 客户侧只展示三个简化状态：

- 等待中
- 洗护中 / 美容中
- 洗护完毕 / 美容完毕

客户端不展示更细的员工内部操作节点。

#### 无当前服务

若没有正在进行的服务，不显示空白卡片。首页当前服务区域改为轻量提示，并引导用户进入底部“预约”页。

#### 洗护 / 美容完成后的展示

当服务首次进入完成状态，顾客打开小程序或回到相关页面时弹出完成提示。

弹窗至少包含：

- 宠物名称 / 头像
- 本次服务已完成提示
- 主按钮：查看本次服务对比图

同一笔完成记录不能无限重复弹窗，需记录用户是否已查看 / 关闭过完成提示。

完成后的服务卡继续在首页保留，直到顾客已经查看本次服务结果，之后退出“当前服务”区域并进入历史订单 / 服务记录。

### 4.3 寄养首页卡片

寄养卡片展示当前寄养状态、寄养日期范围、当前第几天、今日动态数量以及最近若干条动态。

若有新图片 / 视频动态，可在首页显示“有新的寄养动态”提示。

### 4.4 推荐商品

首页仅展示当前门店推荐商品，不承担完整商城导航职责。

建议展示 3～6 个商品卡片，并提供“查看更多”进入商品列表页。

商品点击后可进入详情并提交购买需求；客户仍不能在线完成真实支付。

## 5. 洗护前后对比页

点击“查看本次服务对比图”进入本次服务结果页面。

页面至少展示：

- 洗护前照片
- 洗护后照片
- 前后对比展示
- 本次服务基本信息
- 完成时间

首屏醒目区域必须展示：

> 查看本次 AI 分析报告

该入口视觉优先级高于普通服务信息。

## 6. AI 洗护分析报告

AI 分析报告由本次洗护前图与洗护后图作为独立图像输入，由后端调用平台超级管理员选定的 AI Provider 生成。

建议在店员标记服务完成、且前后照片齐备后自动生成报告，不等待客户点击后才开始生成。

AI 报告至少具备：pending、processing、completed、failed 四个状态。AI 失败不能影响订单本身完成。

### 6.1 广告解锁

顾客点击“查看本次 AI 分析报告”后，主动触发激励视频广告。只有完整观看后才解锁该次报告；中途关闭不解锁。

建议一份报告成功观看一次广告后永久解锁，之后再次查看无需重复观看。

需记录：report_id、user_id、unlocked、unlocked_at。

## 7. AI Provider 配置

AI 模型不得写死为某一家供应商。

平台超级管理员应能在 Web 后台配置不同 AI Provider 的 API Key / Credential、Base URL、Model ID、启用状态、默认模型、超时和重试等参数。

安全原则：AI Key 只允许保存在服务端，前端不得获得明文；日志不得输出完整凭证；敏感凭证需加密保存或进入独立 Secret 管理机制。

系统采用统一 AI Adapter / Provider 层，业务代码不得直接绑定具体厂商。

## 8. AI 报告内容方向

报告定位为宠物护理 / 外观观察，不作为兽医医疗诊断。

建议结构：整体变化概览、毛发整洁度 / 蓬松度变化、打结 / 毛发状态观察、可见皮肤区域观察、外观清洁变化、值得主人继续关注的护理事项、洗护前后总结，以及 AI 免责声明。

缺少洗护前图或洗护后图时，不得强行生成对比报告。

## 9. 寄养状态与时间轴

寄养动态不使用固定时间模板，店员可按真实发生时间自由新增。

例如：08:17 早餐、09:42 遛狗、10:26 排便、13:05 喝水。

每条动态至少包含：实际发生时间、动态类型、可选文本、可选图片 / 视频、操作员工、系统创建时间。

“实际发生时间”和“系统录入时间”必须分开保存，以支持补录审计。

动态类型可包括喂食、喝水、遛狗、排便、排尿、玩耍、休息、用药 / 特殊照护、清洁、图片 / 视频动态、异常情况和自定义事件。

客户侧按实际发生时间形成当天时间轴。

## 10. “我的”页面初步结构

“我的”页首页优先展示三个核心模块：

- 我的宠物：进入宠物列表与宠物档案。
- 我的会员：仅查看当前商户下的可用余额、余额明细、积分、优惠券及后续确认的会员权益；客户端不提供充值入口。
- 我的订单：查看当前门店下的服务订单、商品订单和历史消费。

消息、设置、账号资料等作为二级入口后续继续设计。

## 11. 当前待继续讨论

客户端模块尚未冻结。预约与宠物档案已形成独立已确认子模块，会员余额 / 充值方向已明确为“门店侧发起、老板配置套餐、客户端只查看”。下一步重点继续设计：积分 / 优惠券规则、商品详情与购买需求流程、订单分类与状态、消息中心，以及广告无法加载时的降级策略。
