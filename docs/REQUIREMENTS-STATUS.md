### 当前关键结论

- 底部导航固定：预约 / 首页 / 我的；正常业务首页仍默认进入首页。
- 小程序启动 / 符合频控的重新进入时，在进入正式首页前可展示 `launch_cover_ad`。
- `launch_cover_ad` 由 Platform Super Admin 单独配置，支持 `custom_image`、`custom_video`、`wechat_ad` 三种模式；图片 / 视频可替换，微信广告单元可独立配置。
- 启动封面广告的开关、投放时效、频次、跳过策略、测试 / 正式环境必须配置化，不得散落硬编码。
- 启动封面广告关闭、过期、无填充、素材失败或 SDK 加载失败时必须恢复原入口目标（无明确目标时进入首页），不得阻塞正常业务；预约 / 首页 / 我的等内部页面跳转不重复展示启动广告。
- 首页业务顺序固定：**当前门店 → 当前服务 → 宠物交友 → 上门喂养 → 推荐商品**。
- 首页完整 UI 顺序为：顶部门店栏 → 顶部品牌 / 生活方式 Banner → 当前服务 → 宠物交友 → 上门喂养 → 精选商品 → 微信 Banner 广告横幅 → 底部导航；养宠顾问仅在当前门店具备有效付费权益且已向本店客户开启时作为悬浮入口出现。
- 顶部品牌 / 生活方式 Banner 是产品视觉内容，不等同于微信广告位。
- 首页精选商品之后、底部导航之前正式存在 `home_bottom_banner` 微信 Banner 广告位，用于曝光 / 点击广告变现。
- `home_bottom_banner` 与 `launch_cover_ad` 都不属于激励广告，不发放签到积分、AI 报告资格或养宠顾问次数；失败 / 无填充只降级广告自身。
- 首页顶部右侧只保留消息入口。
- 当前服务最多直接展示 3 条，更多进入完整列表。
- 洗护 / 美容客户状态简化为等待中、洗护中 / 美容中、洗护完毕 / 美容完毕。
- 洗护 / 美容首次完成时首页提示查看结果；真正查看结果后完成卡退出当前服务区域。
- 寄养卡提供“查看寄养动态”；寄养详情按真实发生时间倒序时间轴展示宠物最新动作，按日期分组，媒体与动作绑定；实际发生时间与录入时间分离。
- 寄养中支持“投喂零食 / 寄养加餐”；复用统一商品购买需求，店员实际投喂完成后自动写入寄养时间轴。
- 宠物交友默认自动轮播并支持手动横向滑动；每屏 3 只、一轮最多 12 只；本轮真实宠物至少 4 只且包含本人主宠物时自己的主宠物固定第 4 位；不足 4 只按实际数量展示。
- 宠物交友单卡取消点赞 / 爱心语义，改为基于最近 7 天有效点击和当前门店 7 日排名的“热度”。
- 真正可邀请的其他宠物使用卡片底部浅色 `可发送邀请` 能力标签；自己 / 私有 / 不可邀请状态不得显示。
- 宠物交友公开必须由主人主动授权，不公开主人联系方式，不做客户之间直接聊天。
- 上门喂养是平台级公开需求市场，固定放在宠物交友之后、推荐商品之前。
- 上门喂养公开地址只显示区县 + 小区名称 / 附近区域，不公开精确地址、门牌号、手机号或微信。
- 第一位成功接单者由服务端原子锁定；接单后只向发布时绑定的门店生成对接待办。
- 上门喂养发布后支持分享到微信聊天 / 群，分享卡深链到需求详情。
- 上门喂养客户端主状态简化为：待接单 → 已接单待门店对接 → 进行中 → 已完成；取消作为历史 / 终止状态。
- 当前城市没有可展示上门喂养需求时，随机补充其他城市真实公开需求，必须如实显示异地位置；全平台都无需求时才显示真正 Empty State。
- V1.0 上门喂养不做平台在线支付、托管、抽佣、自动分账或保证金。
- “我的”会员资产摘要卡固定展示：当前可用余额、可用优惠券数量、本金余额、赠送余额；整卡进入余额明细。
- “我的钱包”承载余额明细、优惠券、邀请码兑换；客户端无会员充值入口。
- V1.0 已正式新增 Platform User 级独立积分体系，积分不属于商户钱包。
- 每日签到必须完整观看有效激励广告；每日奖励由服务端受约束随机生成 1～10 分；周一至周日 7 天全签时累计严格为 50 分；漏签不补足，不支持补签。
- 积分商城由 Platform Super Admin 管理；积分消费使用独立积分账本。
- 积分实物奖励使用平台 / 总仓独立库存，履约固定为：用户选择门店 → 总仓发货到门店 → 门店收货 → 用户到店自提 → 店员核销。
- 洗护 / 美容结果支持后端驱动 N 组前后拖动对比，不写死组数。
- AI 洗护报告按需生成：服务完成不自动调用 AI；客户获得有效查看资格后才启动 AI。
- AI 报告 5 段生成状态真实对应后台任务；约 60 秒未完成允许离开并稍后返回。
- **养宠顾问改为门店级付费权益**：Platform Super Admin 必须先给当前 Merchant / Store 授予有效 `pet_advisor` 权益；门店在权益有效时才能向本店客户开启。
- 客户端只有在“当前门店权益有效 + 门店已开启 + 当前 Platform User 已建立本店 Customer 关系”时显示 / 允许使用养宠顾问；切换到未付费、已过期或已关闭门店时入口立即隐藏 / 禁用。
- 门店 A 购买养宠顾问不得让门店 B 自动获得功能，也不得因为同一个 Platform User 在 A 可用就允许其在 B 绕过门店权益。
- 养宠顾问用户额度仍按 Platform User 累计：终身前 3 次有效提问免费；之后每完整观看一次广告解锁 3 次；切换到另一付费门店不重新赠送前三次；只有成功回答才消耗次数，AI 失败不扣。
- 门店购买养宠顾问不意味着 Merchant Owner / Staff 可以查看客户 AI 聊天正文。
- `pet_advisor` 激励广告不能绕过门店付费 Feature Entitlement；用户已有剩余额度可保留，但只有在符合资格的门店上下文才可继续使用。
- AI 洗护报告、每日签到、养宠顾问统一使用激励广告权益模块；广告完成必须可信校验并幂等发放。
- 商品是轻商城 / 购买需求，不支持客户端真实线上支付、普通商品快递、地址、运费或用户物流页面。
- 预约与正式订单分离。
- 财务、余额、积分、库存、退款、冲正、广告配置和付费功能权益等必须留痕并可审计。
- 客户端完整 H5 / 原型必须满足当前业务蓝图和已确认 Design System，不得以少数代表页冒充完整客户端。

后续修改阶段 03 已确认规则，必须按需求变更流程记录，不得无痕覆盖。

## 状态定义

- `讨论中`：允许自由调整，不作为冻结开发依据。
- `待确认`：方案基本形成，仍有关键问题未确认。
- `已确认`：作为正式需求，后续修改必须记录为需求变更。
- `以后版本`：V1.0 不实现，但架构可按需要预留扩展能力。
