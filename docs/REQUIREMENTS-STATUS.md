阶段 03 当前最终确认的重点包括：

- 底部导航固定为：预约 / 首页 / 我的。
- 正常直接打开小程序默认进入首页。
- 2026-09-06 后首页信息顺序更新为：当前门店 → 当前服务 → 上门喂养 → 宠物交友 → 推荐商品。
- 首页顶部仅突出门店名称和必要的切换入口，不展示“当前门店 / 已绑定客户”等辅助文字。
- “我的会员”正式改名为“我的钱包”；钱包承载余额明细、优惠券和邀请码兑换，不重复展示大号资产卡。
- “我的”页面承载客户身份信息、脱敏手机号（存在时）、会员资产摘要卡、独立积分入口、我的宠物、我的钱包、我的订单、消息和账号设置。
- “我的”会员资产摘要卡固定展示：当前可用余额（主金额）+ 当前可使用优惠券数量 + 本金余额 + 赠送余额；整张卡可进入余额明细；平台积分不得混入该资金资产卡。
- 资产摘要卡只冻结信息结构与主次层级，不冻结参考截图中的背景颜色、深浅主题、渐变、高光、字体、圆角、阴影等视觉方案；这些留到阶段 10 UI / Design System 确定。
- 客户端无会员充值入口、无真实线上支付；但 V1.0 已正式新增 Platform User 级独立积分体系。
- 平台积分与商户本金、赠送余额、商户优惠券和钱包流水严格分离，积分消费记录使用独立积分账本。
- 每日签到必须完整观看一次有效激励广告后才成功；每日奖励由服务端受约束随机生成 1～10 分。
- 自然周定义为周一至周日；若 7 天全部成功签到，7 次每日奖励累计必须严格为 50 分；漏签只获得实际签到积分，不自动补足到 50，V1.0 不提供补签。
- 积分商城由 Platform Super Admin 统一管理，可兑换线下消费优惠券和狗粮、猫粮、冻干、零食等实物奖励。
- 积分实物奖励使用平台 / 总仓独立奖励库存，不直接占用门店普通商品销售库存；统一履约为“用户兑换并选择领取门店 → 总仓发货到门店 → 门店确认收货 → 用户到店自提 → 店员核销”。
- 上门喂养是平台级公开需求市场：所有平台用户可浏览，用户可发布时间、地点、每日预算、喂养要求等需求，并支持分享到微信群；公开页只展示模糊地点，不公开精确住宅地址、手机号或微信。
- 上门喂养需求发布时绑定当前门店；第一个有效接单者锁定需求；有人接单后只向绑定门店生成待办，由该门店负责双方对接。
- 上门喂养 V1.0 不建设平台在线支付、资金托管、抽佣、自动分账或保证金体系；底层建议独立为平台级 `home_feeding_job / request`，不直接污染普通商品、洗护或寄养订单营业额。
- 首页加入“宠物交友”：每屏 3 只、一轮最多 12 只；自己的主展示宠物固定第 4 个位置。自己的第 4 位卡片可仅对本人展示，不代表自动向其他客户公开。
- 宠物交友首页默认自动横向轮播，同时支持客户手动横向滑动；客户手动操作时自动轮播让位，交互结束后恢复。
- 对当前客户可正常发起邀请的其他宠物卡片，能力角标统一为“可发送邀请”；该文案表示可进入邀请流程，不改变卡片图片仍可来源于主人授权公开的洗护 / 美容服务后照片。
- 自己的宠物、未开启交友或当前不可邀请的宠物不得错误显示“可发送邀请”。
- 只有主人主动开启交友后，宠物才进入其他客户可见的公开展示池并可作为好友邀请发起方；店员不得代客户默认开启公开展示。
- 宠物交友支持查看社交昵称和允许公开的洗护 / 美容后照片、发送好友邀请、对方同意 / 不同意、重复邀请拦截、同意后通知双方并生成店员待处理事项；不直接公开双方主人联系方式。
- 洗护 / 美容服务首次完成时，客户直接打开仍进入首页并显示完成提示；客户可“查看本次服务结果”或“稍后查看”。查看过本次服务结果后，该完成服务退出首页“当前服务”区域，历史仍保留在订单 / 宠物服务记录。
- 洗护 / 美容结果页支持 N 组前后照片：店员上传 N 组完整对比照片，客户端自动生成 N 组独立拖动对比；服务相册保留对比组、前后类型和排序关系。
- 服务结果页页面顺序由 `03i` 收口为：服务状态 / 基本信息 → N 组前后对比 → 本次服务摘要 → 结算信息 → AI 洗护分析。
- AI 洗护报告改为按需生成：服务完成不提前调用 AI；客户点击“查看报告”并完成有效广告观看 / 获得有效查看资格后，才提交照片并启动 AI 分析。
- AI 报告生成阶段统一为：宠物影像质量检测 → 洗护前后特征比对 → 毛发与清洁状态分析 → 专业护理知识检索 → 结果复核与报告生成；真实结果提前完成立即展示。
- AI 报告正常体验目标约 30～60 秒；约 60 秒仍未完成时提示“报告仍在生成中，分析已提交，可稍后返回本页面查看结果”，后台任务继续执行。
- AI 广告弹窗标题为“查看 AI 洗护报告”，说明文案为“本功能采用国际领先AI助手分析，相关费用已由赞助商赞助，观看完整广告后即可免费查看本次 AI 洗护报告。”
- 寄养中的宠物支持“投喂零食 / 寄养加餐”：仅在当前宠物处于有效寄养中、寄养资料允许额外零食且门店存在可投喂商品时提供入口。
- 宠物寄养资料增加“寄养期间是否允许额外投喂零食”以及禁食 / 忌口信息；过敏、禁食和饮食注意事项必须在客户确认与店员处理时可见，不使用 AI 猜测饮食安全。
- 寄养加餐不建立第二套订单：客户从寄养详情选择门店标记为允许寄养投喂的商品后提交，形成统一商品购买需求，`source_channel = mini_program`，并使用独立业务场景 `business_scenario = boarding_feed` 关联 `boarding_id / pet_id`。
- 客户提交寄养加餐后明确提示“已通知店员”；店员端生成待处理事项，继续按普通商品购买需求规则完成商品确认、数量 / 金额调整、库存预占、收银和实际投喂确认。
- 寄养加餐正式成交只计入商品销售收入，不重复计入寄养收入；实际投喂完成后自动向对应寄养时间轴写入投喂动态。
- 同一宠物存在尚未处理完成的投喂请求时，客户端应显示“投喂请求处理中”等状态，避免连续误触生成重复请求。
- 客户端新增全局「养宠顾问」悬浮入口：默认左侧，可拖动，松手后自动吸附最近左 / 右边缘；不遮挡微信系统区域、底部导航和固定主要按钮。
- 养宠顾问同一 Platform User 前三次有效提问免费；之后每完整观看一次激励广告解锁 3 次有效提问；只有 AI 成功返回有效回答才消耗 1 次额度，AI 超时 / 失败不得扣次数。
- AI 洗护报告、每日签到和养宠顾问统一使用激励广告权益模块；广告完整观看状态必须由可信结果校验并具备幂等能力，不得相信前端自行修改的“已观看”状态。
- 客户端完整 H5 / 原型必须同时按 `03i-customer-screen-blueprint.md` 与 `03n-customer-screen-blueprint-extension.md` 覆盖关键页面和状态，不得只生成少数代表页冒充完整预览。
- 宠物交友、宠物档案、身份体系、消息中心、服务结果、服务相册、AI 报告、钱包资产摘要、寄养加餐、上门喂养、平台积分、养宠顾问、广告权益和页面蓝图已形成当前正式客户端基线。

后续如修改阶段 03 已确认规则，必须按需求变更流程记录原规则、新规则及影响范围，不直接无痕覆盖。

## 状态定义

- `讨论中`：允许自由调整，不作为冻结开发依据。
- `待确认`：方案基本形成，仍有关键问题未确认。
- `已确认`：作为正式需求，后续修改必须记录为需求变更。
- `以后版本`：V1.0 不实现，但架构应在必要时预留扩展能力。
