# 03F 客户端「消息中心 + 微信通知」模块

> 状态：已确认子模块
> 所属阶段：03 客户端微信小程序
> 版本：V1.0

## 1. 设计原则

- 不新增底部一级导航，入口位于“我的 → 消息”。
- 所有重要业务事件优先自动生成站内消息；真正需要客户及时知道的事件再尝试发送微信通知。
- 绝大多数通知由业务状态变化自动触发，不要求店员额外点击“发送通知”。
- 微信通知属于附加通知渠道，发送失败不得影响预约、订单、服务、余额、优惠券等正式业务状态。
- V1.0 不做即时聊天系统，不做在线客服系统，不做营销群发。
- 消息点击后应直接进入对应业务详情页，避免客户再次手工查找。

## 2. 消息中心

入口：我的 → 消息。

消息中心采用单一时间流，不设计复杂多 Tab。消息可标识业务类型，例如：预约、服务、寄养、商品、会员。

每条消息至少保存：

- merchant_id
- customer_id / user_id
- message_type
- title
- summary / content
- related_business_type
- related_business_id
- priority
- read_status
- created_at
- read_at（可选）
- jump_target / 跳转目标

客户端支持未读数量展示及“全部标记已读”。V1.0 不提供客户端删除业务消息能力。

## 3. 预约消息

以下事件自动生成站内消息：

- 预约提交成功
- 门店确认预约
- 门店建议修改时间
- 预约拒绝
- 预约取消
- 客户修改预约后重新进入待确认

微信通知优先用于需要客户及时处理或知晓的预约变化，例如：门店确认、建议新时间、拒绝、取消。

## 4. 洗护 / 美容消息

客户侧不对员工内部每个服务步骤逐条推送。

V1.0 主要消息节点：

- 服务开始
- 服务完成

其中“服务完成”为重要通知，应优先尝试微信通知。

服务完成消息直接跳转本次服务结果页，可继续查看前后对比和 AI 分析报告。

AI 报告生成完成后不再额外重复发送微信通知；若客户进入结果页时报告尚未完成，只显示“AI 报告生成中”。

## 5. 寄养消息

普通寄养动态不逐条发送微信通知。

适合形成站内消息或重要通知的事件包括：

- 办理入住
- 新增图片 / 视频动态
- 异常情况
- 寄养即将结束 / 已结束

多个短时间内连续新增的普通图片、视频或寄养动态由后端尽量合并提示，例如“旺财有 3 条新的寄养动态”，减少消息轰炸。

寄养异常记录默认勾选“通知客户”；店员可在仅作内部记录时主动取消通知。

异常通知直接进入对应寄养详情 / 时间轴。

## 6. 商品消息

商品购买需求可产生以下站内消息：

- 购买需求已提交
- 门店已确认
- 门店已调整商品 / 数量
- 订单即将自动取消
- 订单已取消
- 订单已完成

微信通知优先用于：

- 门店已确认，可到店线下付款
- 门店修改商品 / 数量
- 订单即将超时取消
- 门店取消订单

商品订单按已确认的库存预占规则执行。默认 24 小时未完成付款自动取消前，在临近超时时自动提醒客户；自动取消后释放库存并恢复尚未核销的优惠券。

## 7. 会员消息

V1.0 无积分机制。

会员相关消息包括：

- 充值完成
- 余额人工调整
- 优惠券到账
- 邀请码兑换成功
- 优惠券即将过期（低优先级，可选）

充值完成后系统自动生成站内消息，展示本次到账金额、当前余额以及自动赠送的优惠券。

邀请码兑换在当前页面直接展示结果，同时保留站内消息记录；不再额外发送微信通知。

优惠券即将过期默认仅做站内提醒，不主动发送营销性质微信通知。

## 8. 消息跳转

消息必须尽量直接跳到对应业务页面：

- 预约消息 → 预约详情
- 洗护 / 美容完成 → 服务结果页
- 寄养消息 → 寄养时间轴 / 寄养详情
- 商品消息 → 商品订单详情
- 优惠券到账 → 我的优惠券
- 会员余额变动 → 余额明细

## 9. 主动通知客户

V1.0 为店员保留轻量“通知客户”能力，用于特殊业务情况，不发展为聊天系统。

常用模板至少包括：

- 请联系门店
- 服务预计稍有延迟
- 可以来接宠物了
- 请确认新的预约时间
- 自定义

普通店员只能针对与当前业务相关的单个客户发送通知；群发营销不进入 V1.0。

是否允许普通店员发送自定义通知由权限体系控制。

## 10. 消息优先级

V1.0 按三档处理：

### 重要

例如：预约改时间、服务完成、寄养异常、商品确认 / 取消。

- 生成站内消息
- 尝试微信通知

### 普通

例如：服务开始、商品完成、充值完成、优惠券到账。

- 生成站内消息
- 微信通知按具体事件决定

### 低优先级

例如：普通寄养动态、优惠券即将过期。

- 仅站内消息或业务页面提示
- 默认不主动微信通知

## 11. 微信通知失败处理

微信通知发送与正式业务状态必须解耦。

例如服务完成后：

1. 服务订单正常进入完成状态。
2. 生成站内消息。
3. 尝试发送微信通知。
4. 即使微信通知失败，订单和服务状态也不得回滚。

后台记录发送结果及失败原因，用于审计和问题排查。

客户未授权或无法接收微信通知时，站内消息、订单状态、服务报告等功能仍应正常工作。

## 12. 通知审计

至少保存：

- 消息类型
- 关联业务对象
- 客户
- 创建时间
- 站内消息状态
- 是否尝试微信通知
- 微信发送时间
- 微信发送成功 / 失败
- 失败原因（如有）

店员主动通知时额外记录：

- 操作员工
- 通知内容 / 模板
- 操作时间

## 13. V1.0 不实现

- 即时聊天 / 在线客服
- 客户与店员私聊会话
- 营销群发
- 复杂消息订阅中心
- 因客户未开启通知而阻塞正式业务流程
