# 03B 客户端「我的宠物」模块

> 状态：已确认子模块
> 所属阶段：03 客户端微信小程序
> 版本：V1.0

## 1. 设计原则

- 第一次建档尽量少填，降低客户录入门槛。
- 后续预约、洗护、美容、寄养尽量自动带出宠物资料，减少重复输入。
- 客户和店员均可在权限范围内维护宠物基础资料。
- 客户可见资料与门店内部备注必须分离。
- 历史体重、服务记录、服务照片等数据自动沉淀，不要求额外重复录入。

## 2. 宠物列表

入口：我的 → 我的宠物。

列表展示包含：宠物头像、名称、类型 / 品种、性别、年龄、当前体重，并提供“查看档案”和“添加宠物”。

## 3. 首次添加宠物

首次添加仅要求最少必要信息：

- 宠物名称：必填
- 宠物类型（猫 / 狗 / 其他）：必填
- 宠物头像：选填
- 品种：选填
- 性别：选填
- 出生日期：选填
- 当前体重：选填

其他信息进入“完善宠物档案”，不得强迫客户一次填写大量资料。

## 4. 宠物档案结构

宠物档案分为：

1. 基本资料
2. 护理档案
3. 寄养资料
4. 服务记录
5. 服务相册
6. 宠物交友设置

### 4.1 基本资料

包含：头像、名称、类型、品种、性别、出生日期、系统自动计算年龄、当前体重、是否绝育等。

年龄应根据出生日期自动计算，不要求用户每年更新。

### 4.2 护理档案

用于洗护 / 美容过程中自动提示，包含可选标签和备注，例如：

- 性格：温顺、胆小、活泼、敏感、其他
- 怕水
- 怕吹风
- 怕剪指甲
- 容易应激
- 不喜欢陌生人
- 其他护理注意事项

店员创建或开始洗护 / 美容服务时，应自动展示相关注意事项，避免重复询问或录入。

### 4.3 寄养资料

用于寄养预约和入住时自动带出，包括：

- 喂食习惯
- 每日餐数
- 自带粮 / 门店粮
- 遛狗习惯
- 性格
- 过敏情况
- 长期用药
- 特殊照护
- 其他寄养备注

后续寄养预约时默认展示已有资料，让客户选择“信息无误”或“本次修改”，不要求每次重新填写。

### 4.4 宠物交友设置

每只宠物独立维护交友展示设置，至少包括：

- 是否参与宠物交友 / 允许在当前门店交友区公开展示
- 宠物社交昵称；默认可沿用宠物名称
- 允许用于交友展示的服务后照片

未明确开启交友展示的宠物不得出现在其他客户的宠物交友轮播或完整列表中。

交友公开展示属于客户隐私授权，必须由宠物主人在客户端主动开启或关闭；店员不得默认替客户开启公开展示。

自己的主宠物可以在本人首页第 4 位以“仅本人可见”形式出现，即使尚未开启交友；这不代表对其他客户公开。未开启交友时不能作为好友邀请发起方。

公开资料必须遵循最小化原则，仅展示交友需要的信息，不公开主人姓名、手机号、微信信息、会员资产、消费记录、门店内部备注、用药 / 过敏等非必要资料。

完整交友规则见 `03h-customer-pet-social.md`。

## 5. 客户与店员共同维护

已确认：客户和店员都可以维护宠物基础资料。

但系统必须区分：

### 客户可见 / 可维护资料

如名称、出生日期、性别、是否绝育、喂食习惯、客户填写的护理注意事项等。

### 门店内部备注

必须支持门店内部备注，默认客户不可见，例如：

- 洗澡时挣扎明显
- 剪指甲需两人配合
- 有咬人历史
- 某类操作需特别注意

门店内部备注必须归属于当前商户，不得跨商户共享。

### 交友公开授权例外

“客户和店员共同维护基础资料”不等于店员可以代表客户授权公开宠物。宠物交友开关、社交公开昵称和公开照片范围属于客户侧隐私授权能力，具体规则以 `03h-customer-pet-social.md` 为准。

## 6. 体重历史

已确认保存体重历史，而不是只覆盖一个当前体重值。

每次新增体重记录至少保存：

- 宠物 ID
- 体重
- 测量 / 记录时间
- 数据来源（客户、店员、服务记录等）
- 记录人（如适用）

客户端宠物主页只展示当前最新体重；历史体重可在二级页面查看，并为未来体重趋势分析预留能力。

## 7. 服务记录

宠物档案下应按宠物维度展示历史洗护、美容、寄养等服务记录。

“我的订单”和“宠物服务记录”属于同一底层业务数据的不同查询入口：

- 我的订单：按订单维度查看
- 宠物档案：按宠物维度查看

不得复制生成两套互相独立的数据。

## 8. 服务相册

已确认自动生成宠物服务相册。

店员在洗护 / 美容服务报告中上传的前后照片，应自动归档到对应宠物服务相册，不增加店员额外上传步骤。

相册可按日期 / 服务记录展示洗护前、洗护后或美容前后照片。

宠物交友优先复用服务相册中的洗护 / 美容服务后照片。主人可选择哪些服务后照片允许作为交友公开图；不要求店员为了交友功能再次上传。

## 9. 宠物移除与历史数据

已有订单、报告、寄养记录、照片等历史数据的宠物不得通过普通用户操作进行物理删除。

客户端使用“移除宠物 / 归档宠物”语义；历史业务数据继续保留，并支持在合理权限下恢复。

宠物被移除 / 归档后不得继续出现在宠物交友公开展示池中。

真正的数据删除应由后续账号注销、隐私与数据保留规则统一处理。

## 10. 店员搜索

店员端客户 / 宠物搜索必须支持至少：

- 客户姓名 / 昵称
- 手机号
- 宠物名称

社区门店员工常以宠物名称识别客户，因此宠物名称必须作为核心搜索字段。

## 11. 跨商户宠物档案

宠物基础档案属于平台用户 / 客户可授权复用的基础资料。

客户进入其他商户时，可主动选择复用已有宠物基础档案，减少重复建档。

新商户只能访问客户明确授权的基础资料，不得看到其他商户的：

- 历史订单
- 消费记录
- 会员资产
- 服务报告
- 商户内部备注
- 员工评价
- 其他经营数据

宠物交友展示授权同样按商户隔离。客户在 A 商户开启交友展示，不代表该宠物在 B 商户自动公开展示。

## 12. 需求变更记录

### 2026-08-31：新增宠物交友设置

【需求变更】

- 原规则：宠物档案用于基础资料、护理、寄养、服务记录与服务相册，不包含宠物交友公开展示控制。
- 新规则：新增每只宠物独立的交友展示开关、社交昵称和公开服务后照片设置；只有主人明确授权的宠物才进入当前门店宠物交友公开展示池。
- 影响范围：客户端宠物档案、首页宠物交友、服务相册、隐私、数据库、API。

### 2026-08-31：明确交友授权主体

【需求变更】

- 原规则：客户和店员均可维护宠物基础资料，可能被误读为店员也可开启宠物公开交友。
- 新规则：交友公开开关和公开照片范围必须由宠物主人客户端主动授权；店员不能默认代开。自己的主宠物可仅对本人显示在首页第 4 位，不等于公开授权。
- 影响范围：宠物档案、宠物交友、隐私、店员端权限边界。
