# 03P 客户端「启动封面广告」模块

> 状态：已确认子模块
> 所属阶段：03 客户端微信小程序
> 版本：V1.0

## 1. 产品定位

V1.0 客户端新增「启动封面广告」能力，用于用户打开 / 重新进入小程序时，在进入本次目标业务前展示可配置的封面广告；没有明确目标时才进入首页。

该能力与以下广告 / Banner 严格区分：

- 顶部品牌 / 生活方式 Banner：产品视觉内容，不是启动广告。
- 首页底部 `home_bottom_banner`：首页内容流中的微信 Banner 曝光广告。
- 激励广告：用户完整观看后获得 AI 报告、签到、养宠顾问次数等权益。

启动封面广告是独立 placement，建议：

`launch_cover_ad`

其目标是品牌曝光 / 广告变现 / 平台运营，不自动发放积分、AI 次数、优惠券、余额等权益。

---

## 2. 触发时机

启动封面广告用于“小程序启动 / 重新进入”场景，不用于每次页面内部跳转。

原则：

- 用户从外部打开小程序时，可按当前配置展示一次。
- 小程序从后台重新进入前台时，是否再次展示由频控配置决定。
- 首页 → 预约 → 我的等内部页面切换不得重复弹封面广告。
- 广告未加载成功不得阻止用户恢复本次目标，目标与门店上下文按第 2.1 节处理。

具体频次必须配置化，不在前端组件内写死。

建议配置至少支持：

- `every_launch`：每次符合条件的启动 / 重新进入尝试展示；
- `once_per_day`：同一用户自然日最多一次；
- `interval`：按配置间隔控制；
- `disabled`：关闭。

默认频次由 Platform Super Admin 在正式运营前配置。

### 2.1 目标恢复与门店优先级

- 广告只是启动过程中的临时层，不把分享、微信通知、扫码或后台恢复目标改写成首页。
- 展示广告前保存本次有效外部目标、业务标识、所需门店上下文，以及同一账号后台恢复所需的原页面 / 未提交内容；参数必须经服务端与允许的路由规则校验。
- 本次有效扫码 / 门店业务深链优先于历史门店；无新外部目标的后台回前台恢复原页面；普通冷启动且无目标时进入最近有效门店首页。
- 没有有效当前门店且目标需要门店时，按 `03g` 展示扫码 / 选择有效门店，并保留原目标。平台公开上门喂养详情不强制先选发布门店，也不因查看平台详情自动切店。
- 目标需要登录、手机号验证或 Customer 关系时，广告结束后按需完成身份流程，成功后重新鉴权并恢复同一目标；不能登录成功却进入无关首页。
- 目标已取消 / 结束但仍有读取权限时展示真实历史状态；目标失效、所属门店不可用或无权限时显示原因与返回 / 选择有效门店入口，不泄露私有数据或静默改投另一家门店。
- 广告关闭、跳过、展示结束、关闭配置、无填充、失败、过期或等待超时后，均执行上述目标恢复；只有没有目标且门店有效时才进入首页。
- 用户主动点击广告配置目标时按允许的点击目标跳转，保留原业务的返回路径；广告点击不代表原预约、接单或其他业务已完成。返回原业务时不因页面内部导航重复弹出广告。

## 3. 广告来源模式

启动封面广告支持三种正式来源模式，并允许平台单独配置 / 切换：

### 3.1 自定义图片

`mode = custom_image`

Platform Super Admin 可配置：

- 封面图片
- 展示起止时间
- 可选点击目标
- 是否显示跳过 / 关闭
- 展示时长 / 倒计时（配置化）
- 适用环境 / 发布版本

图片应适配常见手机比例与安全区，重要文案不得贴近系统状态栏或底部安全区。

### 3.2 自定义视频

`mode = custom_video`

Platform Super Admin 可配置：

- 视频素材
- 封面 / 首帧
- 自动播放策略
- 是否静音（按微信能力与最终 UI 规则适配）
- 展示起止时间
- 可选点击目标
- 是否允许跳过 / 跳过时机
- 最大展示时长

视频加载失败必须快速降级，不允许用户长时间卡在空白启动页。

### 3.3 微信官方广告

`mode = wechat_ad`

- 使用微信小程序官方支持的广告能力 / 广告组件接入。
- 广告单元、展示、点击、关闭、曝光与收益统计按微信正式平台能力执行。
- 前端不得用自定义素材伪装成微信官方广告。
- 微信广告无填充 / 加载失败时按第 6 节一次兜底与统一等待上限处理，之后恢复原目标，不显示虚假广告。

---

## 4. 配置化要求

为了方便后续替换素材、调试和商业运营，启动封面广告不得硬编码。

至少需要配置：

- `placement = launch_cover_ad`
- `enabled`
- `mode = custom_image | custom_video | wechat_ad`
- `image_asset / video_asset`
- `wechat_ad_unit_id`（微信广告模式）
- `click_target`（自定义素材可选）
- `starts_at / ends_at`
- `frequency_mode`
- `frequency_interval`（如使用间隔模式）
- `skip_enabled`
- `skip_after_seconds`（如适用）
- `max_display_seconds`
- `max_load_wait_seconds`：从启动前已知有效配置取得、供本次配置读取 / 主素材 / 一次兜底共用的总等待上限，不能在 fallback 时重新计时
- `environment = development | test | production`
- `fallback_behavior`

敏感配置 / Credential 仅后端或安全配置层可见，前端不得包含明文敏感凭证。

启动前只能使用已随版本提供且经确认的预算，或本地已验证配置中的有限加载等待预算。没有任何已知有效预算时立即恢复业务；远端配置可在后台读取，不阻塞本次启动。远端返回的新配置不能延长本次已经启动的截止，只能收紧或用于下次流程，避免为读取等待上限本身无限等待。

配置中的等待上限、展示时长、频控和跳过策略必须校验为有效且有限的值。运营默认值与允许范围见 `DEC-LAUNCH-01`，未确认前不得擅自写成正式秒数；配置缺失或无效时不启动广告等待，直接执行目标恢复。

---

## 5. 展示与跳过

### 自定义图片 / 视频

- 可根据平台配置显示“跳过 / 关闭”。
- 是否立即可跳过、几秒后可跳过、最大展示时长均由后台配置，不在 UI 写死。
- 到达最大展示时长后应自动恢复本次目标，不得无限阻塞。
- 用户点击广告素材时只执行已配置且被微信小程序允许的跳转目标。

### 微信官方广告

- 关闭 / 跳过行为以微信官方广告组件能力为准。
- 不在其上叠加会影响官方广告点击 / 关闭行为的自定义遮挡层。

---

## 6. 加载状态与降级

至少支持：

- `disabled`
- `loading`
- `loaded`
- `no_fill`
- `failed`
- `expired`

规则：

- `loaded`：展示当前有效广告。
- `disabled / expired`：不尝试兜底，直接恢复本次目标。
- `no_fill / failed`：只有已配置有效 fallback 且总等待预算尚有剩余时，可尝试一次兜底；否则立即恢复本次目标。
- 自定义素材下载 / 解码失败：不得卡住启动流程。
- 微信广告 SDK 异常：不得导致小程序无法打开。
- 广告服务故障只影响广告自身，不影响登录、首页、预约、服务、订单、钱包等业务。

平台可配置一次兜底，例如微信官方广告无填充后退回自定义图片；未配置则不兜底。配置读取、主素材加载和兜底加载共用 `max_load_wait_seconds`，从本次流程开始计时，不能因切换素材重置。

- 兜底失败、过期、无填充或总等待超时后立即恢复目标，不循环切换或重试第二个兜底。
- 用户跳过 / 关闭后直接恢复目标，不再展示 fallback。
- 已恢复业务页面后，迟到的配置、加载成功、错误或关闭回调均不得再次覆盖业务页面、重置目标或重复跳转。
- 自定义素材加载完成后的展示受 `max_display_seconds` 控制；微信官方广告展示 / 关闭仍遵守其正式组件能力，不叠加遮挡或伪造关闭控件。加载等待与实际展示阶段须分别记录，不能用展示配置延长空白等待。

### 6.1 待决配置项

| 决策 ID | 待确认内容 | 收口阶段 / 生效前要求 |
|---|---|---|
| DEC-LAUNCH-01 | 总加载等待上限、最大展示时长、频控与跳过的运营默认值和可配置范围 | 阶段 05 / 正式运营配置；正式启用前确认并验证，未确认或无有效配置时跳过广告，不写入未经确认的秒数 |

## 7. 平台后台管理

启动封面广告由 Platform Super Admin 单独设置。

阶段 05 Web 后台至少需要预留：

- 启用 / 停用
- 广告来源模式
- 图片素材替换
- 视频素材替换
- 微信官方广告单元配置
- 投放开始 / 结束时间
- 频控
- 跳过策略
- 点击目标
- 开发 / 测试 / 正式环境配置
- 当前素材预览
- 发布 / 生效状态

普通 Merchant Owner / Staff 不直接修改平台启动广告配置。

未来若支持“不同门店展示不同启动广告”，必须作为单独的定向投放规则确认；V1.0 默认按平台级配置执行。

## 8. 调试要求

开发 / H5 / 测试环境必须能独立模拟：

- 自定义图片广告
- 自定义视频广告
- 微信官方广告占位 / SDK 模拟状态
- 加载成功
- 无填充
- 加载失败
- 素材过期
- 广告关闭
- 跳过
- 自动恢复深链 / 后台原页面，以及无明确目标时进入首页
- 登录后恢复目标、无有效门店时扫码 / 选店
- 一次 fallback 成功 / 失败、总等待超时、迟到回调不再次覆盖业务

调试模式必须有明确标识，不得把 Mock 曝光 / 点击数据计入真实广告收益。

广告配置应支持在测试环境单独替换，不影响生产广告单元。

## 9. 数据与统计

平台可记录技术侧运行指标：

- 请求次数
- 加载成功 / 失败
- 无填充
- 展示完成
- 用户跳过 / 关闭
- 自定义素材点击

微信官方广告的正式曝光 / 点击 / 收益以微信广告平台可信数据为准。

自定义素材的本地统计不得冒充微信官方广告收益数据。

## 10. 与其他广告模块关系

### 与 `home_bottom_banner`

两者互相独立：

- 启动封面广告：进入本次目标业务前展示，无明确目标时恢复至首页；
- 首页底部 Banner：进入首页后，在精选商品下方的内容流中展示。

可分别启用、关闭、调试和配置。

### 与激励广告

启动封面广告不授予任何 Reward Entitlement，也不消耗用户养宠顾问额度。

用户看过启动封面广告后：

- 每日签到仍需按签到规则观看激励广告；
- AI 洗护报告仍需按规则获取报告权益；
- 养宠顾问无剩余额度时仍需按规则观看 `pet_advisor` 激励广告。

## 11. V1.0 验收场景

### C-LAUNCH-AD-01：自定义图片

后台选择自定义图片并发布后，小程序符合触发条件时展示该图片；替换素材后无需修改客户端页面代码。

### C-LAUNCH-AD-02：自定义视频

后台切换为视频模式后正常播放；加载失败按一次兜底规则处理并恢复目标。

### C-LAUNCH-AD-03：微信官方广告

切换为微信广告模式后使用正式广告组件；无填充 / 失败时按配置最多尝试一次兜底，受统一加载等待上限约束，最终恢复目标。

### C-LAUNCH-AD-04：独立开关

关闭启动封面广告后直接恢复目标，无目标且门店有效时进入首页，不影响首页底部 Banner 广告。

### C-LAUNCH-AD-05：不重复污染页面导航

一次启动后在预约 / 首页 / 我的内部切换，不重复弹封面广告。

### C-LAUNCH-AD-06：调试隔离

测试环境可替换测试素材 / 广告单元，不影响生产配置或真实收益统计。

### 目标与等待边界验收补充

- 从上门喂养分享、服务完成消息、B 店二维码进入，在广告关闭 / 失败 / 自动结束后仍到对应目标；历史 A 店不能覆盖 B 店目标。
- 需登录 / 绑定时完成后继续原目标；首次无有效门店时进入扫码 / 选店，不构造默认店。
- 后台恢复保持原页面和同一会话未提交内容，不在内部返回时重复展示广告。
- 无填充有有效兜底时最多尝试一次；总等待超时、兜底失败或用户关闭后不再次尝试；迟到成功回调不重新覆盖业务页。

## 12. 需求变更记录

### 2026-09-08：目标恢复与有限兜底

【需求变更】

- 原规则：广告结束 / 失败等场景统一进入首页，与消息和分享详情深链冲突；无填充直接首页与可配置 fallback 并列，缺少执行优先级。
- 新规则：广告结束恢复本次业务 / 后台页面，登录后继续目标，明确门店目标优先与无有效门店选店；fallback 最多一次且共用总加载等待上限，用户关闭和迟到回调不得重开广告。运营数值由 `DEC-LAUNCH-01` 待决项确认。
- 影响范围：启动 / 回前台流程、分享和微信通知、身份与门店选择、广告配置、`10c` UI 流程与验收。下方 2026-09-06 记录保留当时历史口径，现行执行以本次变更为准。

### 2026-09-06：新增启动封面广告

【需求变更】

- 原规则：客户端进入小程序后直接进入业务首页，只存在首页顶部品牌 Banner、首页底部微信 Banner 和若干激励广告。
- 新规则：新增独立 `launch_cover_ad`，在小程序启动 / 重新进入时按配置展示；平台超级管理员可独立选择自定义图片、自定义视频或微信官方广告，并可替换素材、控制频次、时效、跳过与测试 / 正式环境。
- 降级规则：广告关闭、无填充、过期或加载失败均不得阻塞进入首页。
- 影响范围：小程序启动流程、广告配置、Web 平台后台、媒体素材、微信广告 SDK、H5 / 测试调试、监控和收益统计。
