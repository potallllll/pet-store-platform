# 03D 客户端「我的订单」模块

> 状态：已确认子模块
> 所属阶段：03 客户端微信小程序
> 版本：V1.0

## 1. 设计原则

- 预约与正式订单分离：预约管理未来服务意向，正式订单记录已经发生或正在发生的消费。
- 客户端订单分类必须简单，不暴露大量内部技术状态。
- 客户端订单页直接复用正式业务订单数据，不额外维护一套“客户展示订单”。
- 店员端线下快速开单后，若客户已绑定小程序，订单与服务状态自动同步到客户端。
- 已完成、取消、退款、冲正等历史记录不得被客户端真正删除。

## 2. 订单入口与分类

入口：我的 → 我的订单。

V1.0 只保留三个分类：

- 全部
- 服务
- 商品

其中“服务”统一包含洗护、美容、寄养。

预约记录继续放在预约模块的“我的预约”中，不进入“我的订单”。

充值记录继续放在“我的会员 / 余额明细”中，不作为普通消费订单分类。

## 3. 订单列表

订单列表默认按最新业务时间倒序展示；正在进行中的服务可置顶。

服务订单卡片建议展示：

- 日期 / 时间
- 宠物名称
- 服务类型 / 服务项目
- 客户可见状态
- 已结算时显示实付金额
- 查看详情 / 查看服务结果入口

商品订单卡片建议展示：

- 日期 / 时间
- 主要商品摘要
- 商品件数
- 客户可见状态
- 已结算时显示实付金额
- 查看详情入口

## 4. 客户可见状态

### 4.1 洗护 / 美容

客户端继续使用简化状态：

- 等待中
- 洗护中 / 美容中
- 洗护完毕 / 美容完毕
- 已取消

后台可保留更细内部状态，但不直接暴露给客户。

### 4.2 寄养

客户端建议显示：

- 寄养中
- 已完成
- 已取消

未入住的寄养仍属于预约，不提前作为正式消费订单展示。

### 4.3 商品订单

客户端显示：

- 门店确认中
- 待线下付款
- 已完成
- 已取消

客户提交商品购买需求后进入“门店确认中”；门店确认商品、数量和当前应收金额后进入“待线下付款”；有权限店员确认已收款后进入“已完成”。

## 5. 洗护 / 美容订单详情

订单详情至少展示：

- 宠物
- 服务状态
- 服务时间
- 服务项目明细
- 原始应收金额
- 优惠券优惠金额（如有）
- 人工调价金额（如有）
- 最终应收 / 实付金额
- 支付方式（结算后）
- 查看本次服务结果入口

“查看本次服务结果”直接进入同一笔服务的洗护 / 美容前后对比与 AI 报告页面，不额外建立独立报告列表。

首页“当前服务”和“我的订单”中的进行中服务，应打开同一个服务详情数据源和页面能力。

## 6. 寄养订单详情

寄养订单详情至少展示：

- 宠物
- 入住 / 离店日期时间
- 当前寄养状态
- 当前第几天
- 当日动态摘要
- 查看全部寄养动态入口
- 当前费用 / 预计费用或最终实付金额

寄养过程中可能发生延住、提前离店、加项或费用调整，因此正式结算前显示“当前金额 / 预计金额”，完成结算后显示最终实付金额。

## 7. 服务加项与改单

同一只宠物同一次服务过程中增加项目，不应生成多个独立小订单。

例如基础洗护 + 打结处理 + 剪指甲，应作为同一服务订单下的多个服务项。

系统必须保留原始项目、加项、价格变化、人工调价及操作记录。

## 8. 商品购买需求

客户端商品流程：

首页推荐商品 / 商品列表
→ 商品详情
→ 选择数量
→ 提交购买需求
→ 我的订单显示“门店确认中”
→ 店员确认商品、数量和当前应收金额
→ 客户端显示“待线下付款”
→ 客户线下付款
→ 有权限店员确认已收款
→ 订单“已完成”
→ 扣减库存并计入营业额

客户不能在客户端自行确认付款或把订单标记为已完成。

## 9. 店员修改商品需求

结算前店员可以根据库存或实际情况修改商品、数量和金额。

修改后客户端自动显示当前门店确认结果与最新金额，不要求客户额外点击“同意”；客户最终线下付款作为成交确认。

系统必须保留原始购买需求与门店修改后的正式明细，禁止无痕覆盖。

## 10. 金额展示与财务留痕

订单至少保留并可按权限展示 / 审计：

- 商品 / 服务明细原价
- 系统原始应收金额
- 自动优惠金额
- 优惠券优惠金额
- 人工调价金额
- 最终应收金额
- 实付金额
- 支付方式及组合支付明细

不得只保存最终成交金额。

## 11. 支付方式展示

客户订单详情可以查看实际支付方式，例如：

- 会员余额
- 微信
- 支付宝
- 现金
- 其他允许的支付方式

组合支付应按实际金额拆分展示。

客户端不展示内部操作员工、内部收银备注、本金 / 赠送余额扣减细节或完整审计日志。

## 12. 退款 / 取消展示

订单模型预留客户可见状态：

- 已取消
- 已退款
- 部分退款

退款不能通过直接修改原实付金额来实现；客户端应保留原订单金额、退款金额和退款后实际消费结果。

具体退款、优惠券恢复、余额返还和冲正规则在核心业务规则阶段统一确认。

## 13. 与宠物档案的数据复用

“我的订单”与“我的宠物 → 服务记录”展示同一笔订单数据，只是查询入口不同。

禁止为了两个页面重复保存两份订单 / 服务数据。

## 14. 订单来源

后台应记录订单来源，例如：

- 小程序
- 微信
- 电话
- 美团
- 抖音
- 线下到店
- 其他

该字段用于渠道分析，客户端默认不展示。

## 15. V1.0 暂不实现

- 客户删除订单
- 复杂订单搜索
- 多商户订单混合列表
- 客户在线再次付款
- 物流 / 快递状态
- 电子发票
- 一键再次购买整单
- 完整售后工单体系
