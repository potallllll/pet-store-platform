## 1. 文档职责

本文件是 `03i-customer-screen-blueprint.md` 的详细扩展，用于承接 2026-09-06 后确认的：

- 上门喂养需求市场

## 2. 首页最终顺序

首页核心信息顺序固定为：

1. 当前门店
2. 当前服务
3. 宠物交友
4. 上门喂养
5. 推荐商品

上门喂养属于平台级公开需求市场，但发布时绑定当前门店；不新增底部一级导航。

旧的“当前服务 → 上门喂养 → 宠物交友”顺序已被正式调整，不再作为实现依据。

## 4. 寄养详情 / 动态时间轴

### 4.1 入口

首页当前寄养服务卡必须提供“查看寄养动态”。

点击后进入当前宠物的寄养详情，不另建与寄养记录无关的第二套动态数据。

### 4.2 页面顶部

至少展示：

- 宠物名称 / 头像
- 寄养日期范围
- 当前第几天
- 当前寄养状态
- 今日动态数量
- 新图片 / 视频数量（如有）

### 4.3 时间轴顺序

客户端按**实际发生时间倒序**展示：

> 最新动作在最上方，更早动作向下浏览。

并按日期分组：

- 今天
- 昨天
- 具体日期

最新一条可使用“最新”轻量状态标签。

### 4.4 时间轴事件

至少支持：

- 喂食 / 早餐 / 午餐 / 晚餐
- 饮水 / 更换饮水
- 遛狗 / 遛宠
- 排便
- 排尿
- 玩耍 / 互动
- 休息
- 环境整理 / 清洁
- 用药 / 特殊照护
- 图片 / 视频更新
- 寄养加餐 / 零食投喂
- 异常情况
- 自定义事件

每条至少展示：发生时间、动作 / 标题、说明；有图片 / 视频时媒体与该时间点绑定展示。

店员补录时，客户端排序仍以真实发生时间为准，不能因为晚录入就错误显示为最新动作。

### 4.5 投喂零食

符合既有条件时，寄养详情提供“投喂零食”。

路径：

投喂零食 → 可投喂商品 → 选择 → 确认 → 已通知店员 → 请求处理中 → 店员处理 / 收银 / 实际投喂 → 寄养时间轴新增投喂动态。

## 5. 首页「上门喂养」区域

首页上门喂养区域至少提供：

- 当前公开需求摘要
- 时间
- 模糊地点
- 每日预算
- 当前状态
- “查看更多”
- “发布需求”

公开区域不得显示精确住宅地址、门牌号、手机号、微信、真实姓名等敏感信息。

---

## 6. 上门喂养发布页

正常发布路径：

选择宠物 → 日期范围 → 每日时间 / 次数 → 地点 → 每日预算 → 喂养要求 → 发布。

发布成功至少提供：

- 查看需求
- 分享到微信 / 群

分享卡点击后深链进入对应需求详情。

---

## 7. 上门喂养接单详情

详情至少展示：

- 宠物摘要
- 日期范围
- 每日时间
- 模糊地点
- 每日预算
- 喂养要求
- 当前状态
- 我要接单（符合条件时）

第一个成功接单者原子锁定需求。之后其他用户看到：

> 已有人接单，等待门店对接

接单前不得公开精确联系方式；接单后只向发布时绑定门店生成待办。

## 8. “我的”积分入口

会员资产摘要卡继续只展示：

- 当前可用余额
- 优惠券数量
- 本金余额
- 赠送余额

积分作为独立平台权益入口，至少展示：

- 当前积分
- 今日是否已签到
- 积分商城入口

积分不得混入“我的钱包”资金资产卡。

---

## 9. 每日签到交互

正常路径：

点击「签到」 → 激励广告 → 完整观看并验证成功 → 签到成功 → 今日获得 N 积分（1～10） → 更新本周累计。

规则：

- 每个自然日最多成功一次。
- 每日积分由服务端受约束随机生成。
- 周一至周日 7 天全部签到时，本周 7 次累计严格为 50 分。
- 漏签只获得实际签到积分，不补足 50。
- V1.0 不补签。
- 广告中途退出 / 加载失败 / 验证失败，不签到、不增加积分。

---

## 10. 积分商城

商城至少区分：

- 优惠券 / 虚拟权益
- 实物奖励

### 10.1 优惠券

积分扣减与商户优惠券发放分属不同业务账本；跨模块必须支持幂等与补偿。

### 10.2 实物奖励

V1.0 固定履约：

选择奖励 → 选择领取门店 → 确认消耗积分 → 待总仓发货 → 已发往门店 → 门店已收货 / 待自提 → 已领取。

实物库存来自平台 / 总仓独立奖励库存，不直接占用门店正常销售库存。

客户端不建设用户收货地址、快递到家、用户运费或用户物流配送页。

## 11. 养宠顾问悬浮入口

- 默认位于左侧安全区域。
- 支持拖动。
- 拖动过程中可在安全区域移动。
- 松手后吸附距离最近的左侧或右侧边缘。
- 不遮挡微信系统胶囊、底部导航和固定主要按钮。
- 可记录用户上次纵向位置。
- 全屏广告 / 沉浸式媒体等特殊场景可按 UI 安全需要临时隐藏。

---

## 12. 养宠顾问首次进入与聊天

首次点击：

养宠顾问悬浮按钮 → 养宠顾问介绍 → 关闭 / 开始咨询 → AI 聊天页。

后续默认直接进入聊天，可通过“关于养宠顾问”再次查看介绍。

同一 Platform User：

- 前 3 次有效提问终身免费。
- 第 4 次前观看一次有效激励广告。
- 每次有效广告解锁 3 次有效提问。
- AI 成功返回有效回答才消费一次。
- AI 超时 / 失败 / 网络异常不得扣次数。

客户端剩余次数最终以服务端为准，不得只靠本地计算。

## 13. 激励广告权益

当前统一 placement：

- `ai_report`
- `daily_checkin`
- `pet_advisor`

广告权益必须由可信结果校验、服务端幂等发放；前端自行修改“已观看”状态不得获得权益。

不同 placement 默认不可互相替代。

## 14. 新增关键验收场景

### C-BOARDING-01：寄养动态时间轴

- 从当前服务点击“查看寄养动态”。
- 默认最新动作在上。
- 按日期分组。
- 至少包含多种真实动作。
- 图片 / 视频与对应时间点绑定。

### C-BOARDING-02：寄养加餐回写

- 发起投喂零食。
- 提交后显示已通知店员 / 请求处理中。
- 店员完成实际投喂后，时间轴出现对应投喂动态。

### C-FEED-01：发布并分享

- 完成上门喂养发布。
- 发布成功后可分享到微信群。
- 分享深链进入当前需求。

### C-FEED-02：公开隐私

- 所有用户可浏览。
- 只显示模糊地点。
- 不显示门牌号、手机号、微信。

### C-FEED-03：接单与门店对接

- 第一位接单者成功锁定。
- 需求显示等待门店对接。
- 只通知发布时绑定门店。

### C-POINTS-01：签到

- 完整广告后随机获得 1～10 分。
- 同日不可重复签到。

### C-POINTS-02：完整周 50 分

- 模拟周一至周日连续签到。
- 单日奖励均为 1～10。
- 7 天总计严格 50。

### C-POINTS-03：实物自提

- 兑换实物并选择门店。
- 展示待总仓发货、已发往门店、待自提、已领取。

### C-ADVISOR-01：悬浮吸附

- 拖动悬浮入口。
- 松手后吸附最近左 / 右边缘。

### C-ADVISOR-02：前三次免费 + 广告解锁

- 前 3 次有效回答免费。
- 第 4 次前触发广告。
- 广告成功后获得 3 次有效提问。

### C-ADVISOR-03：AI 失败不扣额度

- 模拟 AI 错误。
- 剩余额度不减少。

## 16. 需求变更记录

### 2026-09-06：扩展客户端页面蓝图

【需求变更】

- 新增平台上门喂养、独立积分中心、积分商城、全局养宠顾问和统一激励广告权益页面 / 场景。
- 影响范围：首页、我的、页面地图、H5 / UI 原型、Codex 客户端开发输入。

### 2026-09-06：五项新增功能方案正式确认

【需求确认】

1. 上门喂养固定放在首页“宠物交友”之后、“推荐商品”之前。
2. 上门喂养公开位置仅展示区县 + 小区名称 / 附近区域，不公开门牌号、精确住宅地址、手机号或微信。
3. 同一需求由第一位成功接单者原子锁定。
4. 积分实物奖励统一总仓发货到用户选择门店，再由用户到店自提并由店员核销。
5. 养宠顾问同一账号终身前 3 次有效提问免费，之后每完整观看一次广告解锁 3 次有效提问。

### 2026-09-06：首页顺序再次收口

【需求变更】

- 原规则：当前服务 → 上门喂养 → 宠物交友 → 推荐商品。
- 新规则：当前服务 → 宠物交友 → 上门喂养 → 推荐商品。
- 影响范围：首页、上门喂养、客户端总纲、主产品蓝图和 H5 / UI。

### 2026-09-06：寄养动态时间轴

【需求变更】

- 原规则：寄养详情支持查看动态，但页面排序与视觉时间轴未完整冻结。
- 新规则：点击“查看寄养动态”后，以真实发生时间倒序展示宠物最新动作，按日期分组，并将图片 / 视频与对应动态绑定；店员实际完成的寄养加餐自动写入该时间轴。
- 影响范围：寄养详情、店员动态录入、API、数据库、H5 / UI 和验收。
