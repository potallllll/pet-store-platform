## 1. 文档职责

本文件是 `03i-customer-screen-blueprint.md` 的详细扩展，用于补充：

- 上门喂养需求市场；
- 平台积分 / 每日签到 / 积分商城；
- 条件式养宠顾问；
- 统一激励广告权益；
- 寄养详情时间轴与寄养加餐联动。

启动封面广告见 `03p-customer-launch-cover-ad.md`；首页底部 Banner 广告见 `03o-customer-home-banner-ad.md`。

`03i` 是当前统一主产品蓝图，本文件不得与 `03i` 冲突。

## 2. 首页最终顺序

首页业务顺序固定：

1. 当前门店
2. 当前服务
3. 宠物交友
4. 上门喂养

## 4. 寄养详情 / 动态时间轴

### 4.1 入口

首页当前寄养服务卡必须提供 `查看寄养动态`。

点击后进入当前宠物的寄养详情，不另建第二套动态数据。

### 4.2 页面顶部

至少展示：

- 宠物名称 / 头像
- 寄养日期范围
- 当前第几天
- 当前寄养状态
- 今日动态数量
- 新图片 / 视频数量（如有）

### 4.3 时间轴顺序

客户端按**实际发生时间倒序**展示：

> 最新动作在最上方，更早动作向下浏览。

按日期分组：今天 / 昨天 / 具体日期。

最新一条可使用 `最新` 轻量状态标签。

### 4.4 时间轴事件

至少支持：

- 喂食 / 早餐 / 午餐 / 晚餐
- 饮水 / 更换饮水
- 遛狗 / 遛宠
- 排便 / 排尿
- 玩耍 / 互动
- 休息
- 环境整理 / 清洁
- 用药 / 特殊照护
- 图片 / 视频更新
- 寄养加餐 / 零食投喂
- 异常情况
- 自定义事件

每条至少展示发生时间、动作 / 标题、说明；媒体与对应时间点绑定。

店员补录时仍按真实发生时间排序，不能因为晚录入就错误显示成最新动作。

### 4.5 投喂零食

符合条件时：

投喂零食 → 可投喂商品 → 选择 → 确认 → 已通知店员 → 请求处理中 → 店员处理 / 收银 → 待投喂 → 实际投喂确认 → 时间轴新增一次投喂动态。

付款与投喂状态分开；已收款未执行仍属于请求处理中。执行、取消、寄养提前结束时的按钮和收口按 03e 执行。

## 5. 首页上门喂养

至少展示：

- 公开需求摘要
- 时间
- 模糊地点
- 每日预算
- 当前状态
- 更多需求
- 发布需求

公开区域不得显示精确住宅地址、门牌号、手机号、微信、真实姓名。

客户端正常主状态：

1. 待接单
2. 已接单待门店对接
3. 进行中
4. 已完成

取消属于历史 / 终止状态。

当前城市无公开需求时，随机补充其他城市**真实**公开需求，并如实展示真实城市 / 区县；全平台都没有时才显示 Empty State。

## 6. 上门喂养发布 / 接单

发布路径：

选择宠物 → 日期范围 → 每日时间 / 次数 → 地点 → 每日预算 → 喂养要求 → 发布。

发布成功至少提供：

- 查看需求
- 分享到微信 / 群

详情至少展示宠物摘要、日期范围、每日时间、模糊地点、每日预算、喂养要求、当前状态和 `我要接单`（符合条件时）。

第一位成功接单者由服务端原子锁定。之后其他用户看到 `已接单待门店对接`。

接单前不得公开精确联系方式；接单后只向发布时绑定门店生成待办。取消、重新开放、过期与门店异常状态按 03j 的操作矩阵和待决项执行；未确定的截止时间不得由页面自行补默认值。分享启动后按 03p 恢复本需求详情。

## 7. “我的”积分入口

会员资产摘要卡继续只展示：

- 当前可用余额
- 优惠券数量
- 本金余额
- 赠送余额

积分作为独立平台权益入口，至少展示：

- 当前积分
- 今日是否已签到
- 积分商城入口

积分不得混入“我的钱包”资金资产卡。

## 8. 每日签到

点击 `签到` → 激励广告 → 完整观看并验证成功 → 签到成功 → 今日获得 N 积分（1～10） → 更新本周累计。

- 每自然日最多一次。
- 每日积分由服务端受约束随机生成。
- 周一至周日 7 天全部签到时累计严格为 50。
- 漏签不补足 50，不补签。
- 广告退出 / 加载失败 / 验证失败不签到、不增加积分。

---

## 9. 积分商城

商城至少区分：

- 优惠券 / 虚拟权益
- 实物奖励

实物奖励固定履约：

选择奖励 → 选择领取门店 → 扣积分 → 待总仓发货 → 已发往门店 → 门店已收货 / 待自提 → 已领取。

实物库存来自平台 / 总仓独立奖励库存，不直接占用门店正常销售库存。兑换处理中、取消 / 返还处理中、领取凭证和异常门店提示按 03k 展示；已领取与取消互斥，客户端不自行判定补偿完成。

客户端不建设快递到家、用户收货地址、运费或用户物流配送页。

## 10. 养宠顾问：付费门店条件式入口

养宠顾问已改为门店级付费权益。

客户端显示 / 允许使用至少满足：

1. 当前 Merchant / Store 有有效 `pet_advisor` Feature Entitlement；
2. 门店已向本店客户开启；
3. 当前 Platform User 与当前门店存在有效 Customer 关系；
4. 服务端资格校验通过。

不满足时不展示可用悬浮入口。

同一用户跨店切换必须重新校验；A 店付费不代表 B 店可用。

满足条件时悬浮入口：

- 默认左侧安全区域；
- 圆形按钮；
- 支持拖动；
- 松手后吸附最近左 / 右边缘；
- 不遮挡微信系统胶囊、底部导航、首页底部 Banner 广告和固定主要按钮；
- 可记录上次纵向位置；提供可见的“调整位置 → 左侧 / 右侧 / 重置”操作，位置重新限制在安全区内；
- 启动封面广告 / 全屏广告 / 沉浸媒体期间隐藏。

## 11. 养宠顾问首次进入与聊天

首次点击：

养宠顾问悬浮按钮 → 养宠顾问介绍 → 关闭 / 开始咨询 → AI 聊天页。

后续默认直接进入聊天，可通过“关于养宠顾问”再次查看介绍。

用户额度规则仍保持：

- 同一 Platform User 前 3 次有效提问终身免费；
- 第 4 次前观看 `pet_advisor` 激励广告；
- 每次有效广告解锁 3 次；
- AI 成功返回有效回答才消耗一次；
- AI 超时 / 失败 / 网络异常不得扣次数；
- 切换到另一家付费门店不重新赠送前三次。

客户端剩余次数最终以服务端为准。

门店付费资格与用户额度分开判断；有额度不代表可在未付费门店使用。

## 12. 激励广告权益

当前统一 placement：

- `ai_report`
- `daily_checkin`
- `pet_advisor`

广告权益必须由可信结果校验、服务端幂等发放；前端自行修改“已观看”状态不得获得权益。

`pet_advisor` placement 不能绕过当前门店付费权益。

`home_bottom_banner` 与 `launch_cover_ad` 属于曝光 / 运营广告，不发激励权益。

## 13. 关键验收场景

### C-BOARDING-01：寄养动态时间轴

- 从当前服务点击查看寄养动态。
- 最新动作在上，按日期分组。
- 图片 / 视频与对应时间点绑定。

### C-BOARDING-02：寄养加餐回写

- 发起投喂零食。
- 提交后显示已通知店员 / 请求处理中。
- 实际投喂后时间轴出现对应动态。

### C-FEED-01：发布并分享

- 完成上门喂养发布并分享深链。

### C-FEED-02：公开隐私

- 只显示模糊地点，不显示精确地址和联系方式。

### C-FEED-03：接单与门店对接

- 第一位接单者锁定，只通知发布时绑定门店。

### C-FEED-06：异地推荐

- 本地无需求时展示其他城市真实公开需求并如实标注城市。

### C-POINTS-01：签到

- 完整广告后随机 1～10 分；同日不可重复。

### C-POINTS-02：完整周 50 分

- 7 天全签总计严格 50。

### C-POINTS-05：实物自提

- 展示总仓发货 → 门店收货 → 待自提 → 已领取。

### C-ADVISOR-01：付费门店入口

- 有有效权益 + 已开启 + 本店 Customer → 显示；否则隐藏。

### C-ADVISOR-02：跨店切换

- 付费门店切到未付费门店后入口消失，切回恢复。

### C-ADVISOR-08：前三次免费 + 广告解锁

- 前 3 次有效回答免费；广告后增加 3 次；换另一家付费门店不重新送 3 次免费。

### C-ADVISOR-06：AI 失败不扣额度

- 模拟 AI 错误后剩余额度不减少。
