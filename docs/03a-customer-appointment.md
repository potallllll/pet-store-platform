# 03A 客户端预约模块

> 状态：已确认子模块
> 所属阶段：03 客户端微信小程序
> 版本：V1.0

## 1. 设计原则

- 客户端尽量少步骤。
- 店员确认预约尽量一屏完成。
- 预约不在线支付，显示价格仅为参考价。
- 预约与正式服务订单分离。
- 不要求商户维护复杂员工个人排班。
- 能自动带出的客户、宠物、寄养资料不重复填写。
- 线下临时到店客户可由店员直接快速开单，不强制先建预约。

## 2. 预约类型

V1.0 支持：

- 洗护
- 美容
- 寄养

## 3. 洗护 / 美容预约

客户流程：选择宠物 → 选择服务 → 选择日期和时间 → 确认预约。

规则：

- 只有一只宠物时自动预选。
- 无宠物档案时可在当前流程添加，保存后自动返回预约流程。
- 支持一次预约多只宠物，系统内部为每只宠物建立独立服务项。
- 服务项目由商户配置，可只配置洗护 / 美容大类，也可配置细分项目。
- 所有预约价格均为参考价，最终金额以实际结算为准。
- 客户不能自由输入预约时间，只能选择门店开放的预约时段。
- 商户设置营业时间、预约间隔、每时段最大预约量。
- 商户可关闭单个时间段、半天或全天。

## 4. 预约确认

客户提交后状态为“待门店确认”，不直接视为预约成功。

店员预约卡片直接提供：

- 确认
- 调整时间
- 拒绝

正常预约一键确认。

调整时间时系统优先推荐附近可用时间，门店发送建议后由客户接受或重新选择；门店不得无提示直接修改客户时间。

拒绝预约优先使用快捷原因，选择“其他”时才要求输入文字。

## 5. 客户侧预约状态

- 待确认
- 待确认新时间
- 已确认
- 已取消
- 已完成

预约状态与服务状态分开。客户到店并由店员开始服务后，才进入等待中 / 洗护中 / 洗护完毕等正式服务状态。

## 6. 修改与取消

- 服务尚未开始时客户可取消预约。
- 修改已确认预约后需重新由门店确认。
- 商户可设置距预约开始前 X 小时后禁止客户自行修改 / 取消。
- 平台 V1.0 不设置预约订金、违约金。

## 7. 寄养预约

流程：选择宠物 → 入住日期时间 → 离店日期时间 → 确认寄养资料 → 填写本次特殊要求 → 提交 → 门店确认。

宠物档案中的长期寄养资料自动带出，客户只需确认或做本次临时修改。

商户可设置建议最大寄养容量；预计超量时系统提示客户和门店，但 V1.0 不强制禁止提交，由门店人工确认。

## 8. 防重复与并发

- 提交按钮需防重复点击。
- 同一宠物存在高度重叠预约时提醒客户，但不绝对禁止。
- 时段名额以后端提交时实时校验为准。
- 时段刚被占满时直接提示并推荐附近可用时间。

## 9. 线下快速开单

店员端必须支持：选择客户 / 宠物 → 选择服务 → 立即开始。

系统后台自动创建正式订单和服务记录，避免线下临时客户被迫经过预约流程。

## 10. V1.0 暂不实现

- 员工个人预约日历
- 客户指定美容师
- 复杂员工排班匹配
- 预约订金 / 违约金
- 自动候补
- AI 自动排班
- 复杂寄养房型预订
